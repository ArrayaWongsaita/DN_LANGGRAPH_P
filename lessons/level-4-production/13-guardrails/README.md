# บทที่ 4-13 guardrails ที่เขียนเอง

## แนวคิด

นอกจาก middleware สำเร็จรูป คุณเขียน **guardrail** (รั้วกั้น) เองได้ด้วย `createMiddleware` จุดแทรกที่ใช้บ่อย:

- `beforeModel`: ดักก่อนเรียกโมเดล (ตัวอย่างในบทนี้ตรวจทุกข้อความที่ผู้ใช้ส่งมาและโมเดลยังไม่ได้ตอบ และตัดอักขระความกว้างศูนย์ที่ใช้พรางคำ) เช่นปฏิเสธคำขอต้องห้ามโดย **ไม่เสียค่าโมเดลเลย**
- `afterModel`: ดักหลังโมเดลตอบ เช่นตรวจว่าคำตอบเผยความลับหรือไม่ แล้วแทนที่ (ข้อความใหม่ต้องใช้ `id` เดียวกับข้อความที่รั่ว เพื่อเขียนทับในประวัติ ไม่ใช่แค่ต่อท้าย ไม่งั้นความลับยังอยู่ในประวัติและถูกส่งให้โมเดลอีกในรอบถัดไป)

เมื่ออยากหยุดทั้งการรันและตอบเองทันที ให้ hook คืน `jumpTo: "end"` พร้อมข้อความ และต้องบอก middleware ว่ากระโดดไปได้ด้วย `canJumpTo`:

```ts
createMiddleware({
  name: "guard",
  beforeModel: {
    canJumpTo: ["end"],
    hook: async (state) => {
      if (ข้อความผู้ใช้ล่าสุดมีคำต้องห้าม) return { messages: [new AIMessage("ขออภัย")], jumpTo: "end" };
      return undefined;   // ผ่าน
    },
  },
})
```
guardrail แบบกฎ (คำต้องห้าม, regex) เร็วและแน่นอน ส่วน guardrail ที่ใช้โมเดลช่วยตัดสิน (classifier) ยืดหยุ่นกว่าแต่ช้ากว่าและพลาดได้

## 1. ลองเติมช่องเดียว

เปิด [`guard.ts`](./guard.ts) แล้วเติมข้อ 1: ดักข้อความที่มีคำต้องห้ามใน `beforeModel` แล้วจบทันที รันจากโฟลเดอร์หลักของโปรเจกต์ บทนี้เรียกโมเดลจริง ตั้ง provider และ API key ใน `.env` ตาม [บท 1-02](../../level-1-basics/02-llm-config/README.md) ก่อนรัน

```sh
pnpm lesson 4-13
```

ในไฟล์ข้อ 1 มี **แนวทาง** เป็นโค้ดที่คอมเมนต์ไว้ เอา `//` ออกแล้วแทนที่ `todo(1)` ได้เลย แต่ลองอ่านก่อนว่าแต่ละบรรทัดทำอะไร

ในไฟล์มีรายการคำต้องห้าม (`BANNED`) และ hook ตรวจคำลับในคำตอบ (`afterModel`) ให้แล้ว ขาดแค่ hook ที่ดักก่อนเรียกโมเดล

โค้ดตามแนวทาง:

```ts
if (BANNED.some((word) => last.includes(word))) {
  return { messages: [new AIMessage("ขออภัย ช่วยเรื่องนี้ไม่ได้")], jumpTo: "end" };
}
return undefined;
```

## 2. ผลที่ได้

ตัวอย่างผลที่รันจากเฉลย ข้อความจากโมเดลเปลี่ยนได้ทุกรอบ

```text
  realBanned: 'ขออภัย ช่วยเรื่องนี้ไม่ได้',
  realOk: 'สวัสดี ขอให้คุณมีวันที่ดีนะ'
✅ คำขอต้องห้าม: ปฏิเสธทันที และไม่เสียค่าโมเดล
✅ แทรกอักขระความกว้างศูนย์ในคำต้องห้าม ก็ยังถูกจับ
✅ คำขอปกติ: ผ่านและได้คำตอบของโมเดล
✅ โมเดลเผยความลับ: ถูกแทนที่ก่อนถึงผู้ใช้ และไม่เหลือในประวัติ
✅ หลังถูกปฏิเสธไปรอบหนึ่ง รอบถัดไปที่ปกติต้องผ่านตามเดิม
✅ โมเดลจริง: ปฏิเสธคำขอต้องห้าม และตอบคำขอปกติได้
```

สิ่งที่ได้: สร้างรั้วกั้นทั้งขาเข้าและขาออกของโมเดล

## 3. ส่วนประกอบที่ใช้ในบทนี้

| hook | เวลาที่ทำงาน | ในบทนี้ |
|---|---|---|
| `beforeModel` | ก่อนเรียกโมเดล | ตรวจข้อความผู้ใช้ ถ้ามีคำต้องห้ามคืน `jumpTo: "end"` พร้อมข้อความปฏิเสธ |
| `afterModel` | หลังโมเดลตอบ | ตัดคำที่เป็นความลับออกจากคำตอบ |

## ข้อควรจำ

- guardrail แบบนี้คุมสิ่งที่ `invoke()` คืนและสถานะปัจจุบัน แต่ข้อความที่โมเดลเพิ่งสร้างยังอาจอยู่ใน checkpoint ก่อนหน้าและในสตรีม (`stream`) ที่ส่งไปถึงผู้ใช้ก่อนถูกแทนที่ ถ้าความลับห้ามหลุดเด็ดขาด ให้ปกปิดก่อนเข้าโมเดล (บท 4-12) ไม่ใช่พึ่งการแก้ภายหลัง
- guardrail ขาเข้าประหยัดค่าโมเดล guardrail ขาออกกันความลับหลุด ใช้คู่กัน
- ข้อความที่ปฏิเสธควรบอกผู้ใช้ชัดเจนแต่ไม่เปิดเผยกติกาภายใน
