# บทที่ 4-01: node timeout (กัน node ที่ค้าง)

## แนวคิด
node ที่เรียกโมเดลหรือเครือข่ายอาจ **ค้างนานเกินไป** โดยไม่ล้มเหลวเสียที LangGraph (ตั้งแต่ 1.4) ให้ตั้งเวลาสูงสุดต่อ node ได้ตอน `addNode`:

```ts
.addNode("callModel", fn, { timeout: 60_000 })             // มิลลิวินาที
.addNode("callModel", fn, { timeout: { runTimeout: 120_000, idleTimeout: 30_000 } })
```
- `runTimeout`: เพดานเวลารวมต่อหนึ่งความพยายาม (ไม่ถูกต่อเวลา)
- `idleTimeout`: เวลาที่ยอมให้เงียบ (ไม่มีความคืบหน้า) ถูกรีเซ็ตเมื่อมีความคืบหน้า
- เมื่อหมดเวลา LangGraph โยน `NodeTimeoutError` (ตรวจด้วย `isNodeTimeoutError(e)`) ซึ่งมีชื่อ node และชนิด (`"run"` หรือ `"idle"`)
- ถ้า node มี `retryPolicy` (บท 3-06) การหมดเวลาจะถูกลองใหม่ได้ด้วย

## ดูตัวอย่าง
`timeout.ts` มี node `slow` ที่หน่วงตามเวลาที่กำหนด ขาดการตั้ง timeout และการจับ error เมื่อหมดเวลา

## คุณทำได้แล้ว
- ตัด node ที่ช้าเกินกำหนด และแยก "หมดเวลา" ออกจาก error อื่น

## ข้อควรจำ
- timeout ยกเลิกความพยายามนั้น (ค่าที่ node เขียนไว้ระหว่างนั้นถูกทิ้ง) แต่โค้ดใน node ที่ไม่สนใจ `config.signal` ยังรันต่อเบื้องหลังได้ (ผลข้างเคียงเช่นการเขียนฐานข้อมูลยังเกิดขึ้น) ถ้างานยกเลิกได้ ให้ส่ง `signal` ต่อไปให้ `fetch` หรือไลบรารีที่รับมัน
- จับเฉพาะ `NodeTimeoutError` อย่าปิดบัง error ชนิดอื่น
