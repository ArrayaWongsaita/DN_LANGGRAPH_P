# บทที่ 4-01 node timeout (กัน node ที่ค้าง)

## แนวคิด

node ที่เรียกโมเดลหรือเครือข่ายอาจ **ค้างนานเกินไป** โดยไม่ล้มเหลวเสียที LangGraph (ตั้งแต่ 1.4) ให้ตั้งเวลาสูงสุดต่อ node ได้ตอน `addNode`:

```ts
.addNode("callModel", fn, { timeout: 60_000 })             // มิลลิวินาที
.addNode("callModel", fn, { timeout: { runTimeout: 120_000, idleTimeout: 30_000 } })
```
- `runTimeout`: เพดานเวลารวมต่อหนึ่งความพยายาม (ไม่ถูกต่อเวลา)
- `idleTimeout`: เวลาที่ยอมให้เงียบ (ไม่มีความคืบหน้า) ถูกรีเซ็ตเมื่อมีความคืบหน้า
- เมื่อหมดเวลา LangGraph โยน `NodeTimeoutError` (ตรวจด้วย `isNodeTimeoutError(e)`) ซึ่งมีชื่อ node และชนิด (`"run"` หรือ `"idle"`)
- ถ้า node มี `retryPolicy` (บท 3-06) การหมดเวลาจะถูกลองใหม่ได้ด้วย

## 1. ลองเติมช่องเดียว

เปิด [`timeout.ts`](./timeout.ts) แล้วเติมข้อ 1: ตั้ง `{ timeout: timeoutMs }` เป็น options ของ node รันจากโฟลเดอร์หลักของโปรเจกต์ บทนี้ไม่เรียกโมเดลจริง รันได้โดยไม่ต้องมี API key

```sh
pnpm lesson 4-01
```

ในไฟล์ข้อ 1 มี **แนวทาง** เป็นโค้ดที่คอมเมนต์ไว้ เอา `//` ออกแล้วแทนที่ `todo(1)` ได้เลย แต่ลองอ่านก่อนว่าแต่ละบรรทัดทำอะไร

ในไฟล์มี node `slow` ที่หน่วงตามเวลาที่กำหนด และการจับ `NodeTimeoutError` ให้แล้ว ขาดแค่ options ของ node

โค้ดตามแนวทาง:

```ts
const options = { timeout: timeoutMs };
```

## 2. ผลที่ได้

ผลที่รันจากเฉลย

```text
  fast: { ok: true, log: 'เสร็จ' },
  timedOut: { ok: false, node: 'slow' },
  elapsedMs: 53
✅ ทำงานเร็วกว่าเพดาน: สำเร็จ
✅ ช้ากว่าเพดาน: ได้ผลหมดเวลาพร้อมชื่อ node (ไม่ใช่ exception)
✅ หมดเวลาแล้วกลับมาเร็ว ไม่รอจนงาน 2 วินาทีเสร็จ
✅ error ชนิดอื่นถูกโยนต่อ ไม่ถูกแปลงเป็น "หมดเวลา"
```

สิ่งที่ได้: ตัด node ที่ช้าเกินกำหนด และแยก "หมดเวลา" ออกจาก error อื่น

## 3. ส่วนประกอบที่ใช้ในบทนี้

| รูปแบบ `timeout` | ตัวอย่าง | ความหมาย |
|---|---|---|
| ตัวเลข | `{ timeout: 60_000 }` | เวลาสูงสุดต่อ node เป็นมิลลิวินาที |
| ออบเจ็กต์ | `{ timeout: { runTimeout: ... } }` | ตั้งเพดานเวลาแยกเป็นรายละเอียดมากขึ้น |
| error เมื่อหมดเวลา | `NodeTimeoutError` | จับเฉพาะ error นี้ อย่าซ่อน error อื่น |

## ข้อควรจำ

- timeout ยกเลิกความพยายามนั้น (ค่าที่ node เขียนไว้ระหว่างนั้นถูกทิ้ง) แต่โค้ดใน node ที่ไม่สนใจ `config.signal` ยังรันต่อเบื้องหลังได้ (ผลข้างเคียงเช่นการเขียนฐานข้อมูลยังเกิดขึ้น) ถ้างานยกเลิกได้ ให้ส่ง `signal` ต่อไปให้ `fetch` หรือไลบรารีที่รับมัน
- จับเฉพาะ `NodeTimeoutError` อย่าปิดบัง error ชนิดอื่น
