# บทที่ 4-06: ออกแบบ node ให้ทดสอบง่าย

## แนวคิด
ส่วนที่เป็นของปลอมในบทเรียน (เช่นบทนี้) **ไม่ใช้ key และไม่เรียกเครือข่าย** เพราะโค้ดถูกเขียนให้ทดสอบได้ หลักการมีสามข้อ:

1. **ส่งโมเดลเข้ามา (dependency injection)** อย่า `import` โมเดลตายตัวใน node ทำเป็น factory: `makeSummarizeNode(llm)` ตอนทดสอบส่งโมเดลปลอม ตอนใช้จริงส่งตัวจริง
2. **แยกตรรกะล้วน ๆ ออกจาก node** ฟังก์ชันที่ไม่เรียกโมเดล (เช่นทำความสะอาดข้อความ) ทดสอบตรง ๆ ได้ ไม่ต้องรัน graph
3. **ทดสอบสองชั้น** ชั้น node เดี่ยว (เรียกฟังก์ชัน node ด้วย State ที่เตรียมไว้) และชั้น graph ทั้งเส้น (เช็กการต่อสาย)

```ts
const node = makeSummarizeNode(fakeLLM);      // ชั้น node
await node({ text: "..." });                   // ได้ { summary }
await buildGraph(fakeLLM).invoke({ text });    // ชั้น graph
```
เมื่อมีหลายขั้นที่ล้มได้ ทดสอบทีละชั้นจะรู้ทันทีว่าพังตรงไหน

## ดูตัวอย่าง
`testable.ts` มีโครงของ pipeline "ทำความสะอาด → สรุป" ขาดสามจุด: ตัว node สรุป, ฟังก์ชันทำความสะอาด, และการต่อสาย

## คุณทำได้แล้ว
- เขียนโค้ดที่ทดสอบได้โดยไม่ต้องมีโมเดลจริง

## ข้อควรจำ
- ถ้าต้องมีของจริงถึงจะทดสอบได้ แปลว่าส่งของเข้ามาไม่ได้ ให้ออกแบบใหม่
- ตรวจ **สิ่งที่โมเดลได้รับ** (`calls`) ไม่ใช่แค่ผลลัพธ์
