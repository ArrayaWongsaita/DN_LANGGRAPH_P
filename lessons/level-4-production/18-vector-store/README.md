# บทที่ 4-18 vector store ในหน่วยความจำ

## แนวคิด

**vector store** คือที่เก็บชิ้นเอกสารพร้อมเวกเตอร์ และตอบโจทย์เดียว: "ให้ k ชิ้นที่ใกล้คำถามที่สุด" ของจริง (pgvector, Chroma, Pinecone ฯลฯ) ทำให้เร็วด้วยดัชนีพิเศษ แต่หลักการเหมือนที่คุณทำในบท 4-16:

1. **add:** แปลงข้อความของแต่ละชิ้นเป็นเวกเตอร์ (`embedDocuments`) แล้วเก็บคู่ (ชิ้น, เวกเตอร์)
2. **search:** แปลงคำถามเป็นเวกเตอร์ (`embedQuery`) หาคะแนน cosine กับทุกชิ้น เรียงมากไปน้อย แล้วคืน k อันดับแรกพร้อมคะแนน

LangChain มีอินเทอร์เฟซ `VectorStore` มาตรฐาน (`addDocuments`, `similaritySearch`) ให้สลับ store ได้โดยไม่แก้โค้ดส่วนอื่น ในบทนี้คุณเขียน store แบบง่ายเองเพื่อเห็นข้างใน (`cosine` ใช้จาก `@src/rag` ที่ตรงกับบท 4-16)

## 1. ลองเติมช่องเดียว

เปิด [`store.ts`](./store.ts) แล้วเติมข้อ 1: ค้น k ชิ้นที่ใกล้คำถามที่สุดใน `SimpleIndex.search` รันจากโฟลเดอร์หลักของโปรเจกต์ บทนี้เรียกโมเดลจริง ตั้ง provider และ API key ใน `.env` ตาม [บท 1-02](../../level-1-basics/02-llm-config/README.md) ก่อนรัน

```sh
pnpm lesson 4-18
```

ในไฟล์ข้อ 1 มี **แนวทาง** เป็นโค้ดที่คอมเมนต์ไว้ เอา `//` ออกแล้วแทนที่ `todo(1)` ได้เลย แต่ลองอ่านก่อนว่าแต่ละบรรทัดทำอะไร

ในไฟล์มีคลาส `SimpleIndex` พร้อมเมธอด `add` ที่แปลงชิ้นเป็นเวกเตอร์ให้แล้ว ขาดแค่ `search`

โค้ดตามแนวทาง:

```ts
const q = await this.embeddings.embedQuery(query);
const scored = this.items.map(({ chunk, vector }) => ({ ...chunk, score: cosine(q, vector) }));
return scored.sort((a, b) => b.score - a.score).slice(0, k);
```

## 2. ผลที่ได้

ตัวอย่างผลที่รันจากเฉลย ข้อความจากโมเดลเปลี่ยนได้ทุกรอบ

```text
embedding จริง: {
  source: 'shop.md',
  text: 'สินค้าคืนเงินได้ภายใน 7 วัน การจัดส่งภายใน 3 วัน',
  score: 0.7370839157145201
✅ ค้นหา: ชิ้นที่ตรงที่สุดมาก่อน พร้อมที่มาและคะแนน
✅ store ว่างคืนอาร์เรย์ว่าง และจำกัดจำนวนด้วย k
✅ add หลายครั้งสะสมต่อกัน ไม่ทับของเดิม
✅ embed เอกสารตอน add ครั้งเดียว ไม่ embed ซ้ำตอนค้นหา
✅ embedding จริง: ถามว่า 'ขอเงินคืน' เจอเอกสารเรื่องคืนเงิน
```

สิ่งที่ได้: สร้างที่เก็บเอกสารที่ค้นหาตามความคล้ายได้

## 3. ส่วนประกอบที่ใช้ในบทนี้

| เมธอด | ทำอะไร |
|---|---|
| `add` | แปลงแต่ละชิ้นเป็นเวกเตอร์แล้วเก็บคู่กับชิ้น |
| `search(query, k)` | แปลงคำถามเป็นเวกเตอร์ คำนวณ cosine กับทุกชิ้น เรียงจากมากไปน้อย แล้วเอา k ชิ้นแรก |

## ข้อควรจำ

- เก็บ embedding ไว้ ไม่ต้องคำนวณใหม่ทุกครั้งที่ค้นหา (คิดเงินตามจำนวนครั้งที่ embed)
- store ในหน่วยความจำหายเมื่อรีสตาร์ต ของจริงใช้ฐานข้อมูล (เช่น Postgres + pgvector)
