# บทที่ 4-12: ปกปิดข้อมูลส่วนตัว (PII) ด้วย middleware

## แนวคิด
ข้อความของผู้ใช้อาจมีอีเมล เลขบัตร หรือเลขบัตรประชาชนที่ **ไม่ควรส่งไปให้โมเดลของบริษัทอื่น** หรือบันทึกลง log `piiMiddleware` ของ `langchain` ตรวจและจัดการข้อมูลเหล่านี้ก่อนถึงโมเดล:

```ts
piiMiddleware("email", { strategy: "redact" })        // → [REDACTED_EMAIL]
piiMiddleware("credit_card", { strategy: "mask" })     // → ****-****-****-1111
piiMiddleware("email", { strategy: "block" })          // พบแล้วโยน PIIDetectionError
piiMiddleware("thai_id", { detector: /\d{13}/g, strategy: "redact" })   // ชนิดที่นิยามเอง
```
- ชนิดในตัว: `email`, `credit_card`, `ip`, `mac_address`, `url` กลยุทธ์: `redact` (ค่าเริ่มต้น), `mask`, `hash`, `block`
- ชนิดที่นิยามเองให้ `detector` เป็น regex **ต้องมีแฟล็ก `g`** (ไม่มี `g` โปรแกรมวนไม่จบจน memory เต็ม เราลองแล้ว)
- ค่าเริ่มต้นตรวจ **ข้อความขาเข้า** (`applyToInput`) ส่วนผลลัพธ์ของโมเดลและ tool ตั้งเพิ่มได้ (`applyToOutput`, `applyToToolResults`)
- เลือกกลยุทธ์ตามความเสี่ยง: ข้อมูลที่ห้ามหลุดเด็ดขาดใช้ `block` หรือ `redact`

## ดูตัวอย่าง
`pii.ts` สร้าง agent ที่ต้องมี middleware สามตัว ขาดการตั้งค่าแต่ละตัว

## คุณทำได้แล้ว
- กันข้อมูลส่วนตัวไม่ให้ไปถึงโมเดลโดยไม่ต้องแก้ตัว agent

## ข้อควรจำ
- การปกปิดช่วยลดความเสี่ยงแต่ไม่รับประกันว่าจับได้ทุกรูปแบบ ทดสอบกับข้อมูลจริงของคุณ
- ข้อมูลต้นฉบับยังอยู่ใน checkpoint ของคุณเอง ถ้าต้องไม่เก็บเลยให้ปกปิดก่อนเข้า graph
