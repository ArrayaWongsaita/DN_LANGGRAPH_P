# บทที่ 4-12 ปกปิดข้อมูลส่วนตัว (PII) ด้วย middleware

## แนวคิด

ข้อความของผู้ใช้อาจมีอีเมล เลขบัตร หรือเลขบัตรประชาชนที่ **ไม่ควรส่งไปให้โมเดลของบริษัทอื่น** หรือบันทึกลง log `piiMiddleware` ของ `langchain` ตรวจและจัดการข้อมูลเหล่านี้ก่อนถึงโมเดล:

```ts
piiMiddleware("email", { strategy: "redact" })        // → [REDACTED_EMAIL]
piiMiddleware("credit_card", { strategy: "mask" })     // → ****-****-****-1111
piiMiddleware("email", { strategy: "block" })          // พบแล้วโยน PIIDetectionError
piiMiddleware("thai_id", { detector: /\d{13}/g, strategy: "redact" })   // ชนิดที่นิยามเอง
```
- ชนิดในตัว: `email`, `credit_card`, `ip`, `mac_address`, `url` กลยุทธ์: `redact` (ค่าเริ่มต้น), `mask`, `hash`, `block`
- ชนิดที่นิยามเองให้ `detector` เป็น regex **ต้องมีแฟล็ก `g`** (ไม่มี `g` โปรแกรมวนไม่จบจน memory เต็ม เราลองแล้ว)
- ค่าเริ่มต้นตรวจ **ข้อความขาเข้า** (`applyToInput`) ส่วนผลลัพธ์ของโมเดลและ tool ตั้งเพิ่มได้ (`applyToOutput`, `applyToToolResults`)
- เลือกกลยุทธ์ตามความเสี่ยง: ข้อมูลที่ห้ามหลุดเด็ดขาดใช้ `block` หรือ `redact`

## 1. ลองเติมช่องเดียว

เปิด [`pii.ts`](./pii.ts) แล้วเติมข้อ 1: ตั้ง middleware ปกปิดเลขบัตรประชาชน 13 หลัก รันจากโฟลเดอร์หลักของโปรเจกต์ บทนี้เรียกโมเดลจริง ตั้ง provider และ API key ใน `.env` ตาม [บท 1-02](../../level-1-basics/02-llm-config/README.md) ก่อนรัน

```sh
pnpm lesson 4-12
```

ในไฟล์ข้อ 1 มี **แนวทาง** เป็นโค้ดที่คอมเมนต์ไว้ เอา `//` ออกแล้วแทนที่ `todo(1)` ได้เลย แต่ลองอ่านก่อนว่าแต่ละบรรทัดทำอะไร

ในไฟล์มี middleware ปกปิดอีเมลและเลขบัตรเครดิตที่ตั้งไว้แล้ว และ agent ที่ใช้ทั้งสามตัว ขาดแค่ตัวสำหรับเลขบัตรประชาชน

โค้ดตามแนวทาง:

```ts
const thaiId = piiMiddleware("thai_id", { detector: /\d{13}/g, strategy: "redact" });
```

## 2. ผลที่ได้

ตัวอย่างผลที่รันจากเฉลย ข้อความจากโมเดลเปลี่ยนได้ทุกรอบ

```text
โมเดลจริงตอบ: สวัสดี! ยินดีที่ได้รู้จักและได้ทักทายกันนะ ขอให้เป็นวันที่ดีมาก ๆ เลย 😊
✅ อีเมลถูกแทนที่ก่อนถึงโมเดล
✅ บัตรเครดิตถูก mask เหลือสี่ตัวท้าย
✅ เลขบัตรประชาชน 13 หลัก (ชนิดที่นิยามเอง) ถูกปิดบัง
✅ ข้อความที่ไม่มีข้อมูลส่วนตัวผ่านไปเหมือนเดิม
✅ กลยุทธ์ block: เจอแล้วโยน error และโมเดลไม่ถูกเรียก
✅ โมเดลจริงยังตอบได้หลังผ่าน middleware
```

สิ่งที่ได้: กันข้อมูลส่วนตัวไม่ให้ไปถึงโมเดลโดยไม่ต้องแก้ตัว agent

## 3. ส่วนประกอบที่ใช้ในบทนี้

| ชนิด | ตัวอย่างการตั้ง | กลยุทธ์ |
|---|---|---|
| `email` | `piiMiddleware("email", { strategy: "redact" })` | ปกปิดทั้งก้อน |
| `credit_card` | `piiMiddleware("credit_card", { strategy: "mask" })` | แสดงเพียงบางส่วน |
| `thai_id` | `piiMiddleware("thai_id", { detector: /\d{13}/g, strategy: "redact" })` | ตัวตรวจที่เขียนเองต้องมีแฟล็ก `g` |

## ข้อควรจำ

- การปกปิดช่วยลดความเสี่ยงแต่ไม่รับประกันว่าจับได้ทุกรูปแบบ ทดสอบกับข้อมูลจริงของคุณ
- ข้อมูลต้นฉบับยังอยู่ใน checkpoint ของคุณเอง ถ้าต้องไม่เก็บเลยให้ปกปิดก่อนเข้า graph
