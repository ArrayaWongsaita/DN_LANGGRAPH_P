# บทที่ 4-21 ตอบพร้อมอ้างอิงแหล่งที่มา

## แนวคิด

ระบบ RAG ที่เชื่อถือได้ต้องให้ผู้ใช้ **ตรวจสอบคำตอบได้**: ตอบพร้อมบอกว่ามาจากเอกสารไหน ทำสามขั้น:

1. **บังคับรูปแบบคำตอบ** ด้วย structured output (บท 2-14): `{ answer: string, sources: string[] }`
2. **ใส่ที่มาในบริบท** ให้โมเดลเห็นว่าชิ้นไหนมาจากไฟล์ใด
3. **ตรวจที่ฝั่งโค้ด ไม่เชื่อโมเดล** โมเดลอาจอ้างไฟล์ที่ไม่เคยได้รับ (มั่วการอ้างอิง) จึงกรองเหลือเฉพาะแหล่งที่อยู่ในชิ้นที่ค้นมาจริง ถ้าไม่เหลือแหล่งที่ถูกต้องเลย ให้ถือว่าคำตอบ **ไม่มีหลักฐานรองรับ** (`grounded: false`) เพื่อให้ระบบเตือนหรือปฏิเสธ

## 1. ลองเติมช่องเดียว

เปิด [`cite.ts`](./cite.ts) แล้วเติมข้อ 1: กรองแหล่งอ้างอิงที่โมเดลคืนให้เหลือเฉพาะแหล่งที่ได้รับจริง รันจากโฟลเดอร์หลักของโปรเจกต์ บทนี้เรียกโมเดลจริง ตั้ง provider และ API key ใน `.env` ตาม [บท 1-02](../../level-1-basics/02-llm-config/README.md) ก่อนรัน

```sh
pnpm lesson 4-21
```

ในไฟล์ข้อ 1 มี **แนวทาง** เป็นโค้ดที่คอมเมนต์ไว้ เอา `//` ออกแล้วแทนที่ `todo(1)` ได้เลย แต่ลองอ่านก่อนว่าแต่ละบรรทัดทำอะไร

ในไฟล์มี schema ของคำตอบ, prompt ที่ใส่ที่มาในบริบทและการเรียกโมเดลให้แล้ว ขาดแค่การกรอง `sources`

โค้ดตามแนวทาง:

```ts
const real = new Set(hits.map((h) => h.source));
const sources: string[] = result.sources.filter((s) => real.has(s));
```

## 2. ผลที่ได้

ตัวอย่างผลที่รันจากเฉลย ข้อความจากโมเดลเปลี่ยนได้ทุกรอบ

```text
  answer: 'ตามเอกสารที่ให้มา คำตอบอยู่ใน it.md ซึ่งระบุเรื่องการรีเซ็ตรหัสผ่านที่พอร์ทัล: หากลืมรหัสผ่าน ให้ดำเนินการรีเซ็ตรหัสผ่านผ่านพอร์ทัล (ทำตามขั้นตอนการรีเซ็ตรหัสผ่านที่พอร์ทัล)
' +
    '
' +
    'หมายเหตุ: เอกสารที่ให้มามีเพียงหัวข้อสรุปของ it.md (รีเซ็ตรหัสผ่านที่พอร์ทัล) จึงไม่มีรายละเอียดขั้นตอนเพิ่มเติม ส่วน hr.md เป็นเรื่องการลาป่วย 30 วัน ไม่เกี่ยวข้องกับคำถามนี้',
  sources: [ 'it.md' ],
  grounded: true
✅ อ้างแหล่งที่มีจริง: ผ่าน และ grounded
✅ โมเดลเห็นที่มาของทุกชิ้นใน prompt
✅ โมเดลมั่วอ้างไฟล์ที่ไม่เคยได้รับ: ถูกกรองออก เหลือของจริง
✅ อ้างแต่ไฟล์ที่ไม่มีจริง หรือไม่อ้างเลย: ไม่มีหลักฐาน (grounded false)
✅ ชื่อไฟล์ที่ลงท้ายคล้ายกันไม่นับ (edit.md ไม่ใช่ it.md)
✅ ชื่อที่เป็นแค่ส่วนหนึ่งของชื่อไฟล์หรือว่างเปล่าไม่นับ
✅ โมเดลจริง: ได้คำตอบ และแหล่งที่อ้างอยู่ในชุดที่ส่งให้เท่านั้น
```

สิ่งที่ได้: ทำให้คำตอบของ RAG ตรวจสอบย้อนกลับได้และจับการอ้างอิงที่มั่ว

## 3. ส่วนประกอบที่ใช้ในบทนี้

| ขั้น | ทำอะไร |
|---|---|
| บังคับรูปแบบ | `{ answer, sources }` ด้วย structured output |
| ใส่ที่มาในบริบท | แต่ละชิ้นมีชื่อไฟล์กำกับ |
| กรองผล | ทิ้ง `sources` ที่ไม่มีใน `hits` จริง กันการอ้างไฟล์ที่ไม่เคยได้รับ |

## ข้อควรจำ

- การมีแหล่งอ้างอิงไม่ได้แปลว่าคำตอบถูก แต่ช่วยให้คนตรวจได้เร็ว
- แสดงที่มาให้ผู้ใช้เห็นเสมอ
