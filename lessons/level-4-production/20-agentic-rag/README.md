# บทที่ 4-20 agentic RAG (ให้คะแนนผลค้นและเขียนคำถามใหม่)

## แนวคิด

ผลค้นหาไม่ได้ดีเสมอไป: คำถามอาจกำกวม ("ทำไงดี") หรือใช้คำคนละชุดกับเอกสาร RAG แบบ **agentic** เพิ่มการตัดสินใจเข้าไปใน graph:

```
retrieve → grade (ผลที่ได้เกี่ยวข้องไหม?)
              ├ เกี่ยวข้อง → generate (ตอบ) → END
              ├ ไม่เกี่ยว (ยังไม่เคยเขียนใหม่) → rewrite (เขียนคำค้นใหม่) → retrieve
              └ ไม่เกี่ยว (เขียนใหม่ครบ 1 ครั้งแล้ว) → giveUp ("ไม่พบในเอกสาร") → END
```
- **grade:** ใช้โมเดลตอบแบบมีโครงสร้าง `{ relevant: boolean }` (บท 2-14)
- **rewrite:** ให้โมเดลปรับคำค้นให้ตรงกับศัพท์ในเอกสารมากขึ้น
- **giveUp:** ถ้าลองแล้วยังไม่เจอ **ตอบตรง ๆ ว่าไม่พบ** ดีกว่าให้โมเดลแต่งคำตอบเอง ข้อนี้สำคัญที่สุดของระบบที่เชื่อถือได้
- ต้องมีเพดานจำนวนรอบเสมอ (บท 3-09) เพื่อกันวน

ที่นี่ retrieve ใช้ index จริงในหน่วยความจำ (embedding ปลอมแบบนับคำ) ส่วนโมเดลคือตัวที่ส่งเข้ามา (ในบทนี้เป็นโมเดลปลอม)

## 1. ลองเติมช่องเดียว

เปิด [`agentic.ts`](./agentic.ts) แล้วเติมข้อ 1: เขียนตัวเลือกทางหลังให้คะแนนผลค้น: ตอบ เขียนคำถามใหม่ หรือยอมแพ้ รันจากโฟลเดอร์หลักของโปรเจกต์ บทนี้เรียกโมเดลจริง ตั้ง provider และ API key ใน `.env` ตาม [บท 1-02](../../level-1-basics/02-llm-config/README.md) ก่อนรัน

```sh
pnpm lesson 4-20
```

ในไฟล์ข้อ 1 มี **แนวทาง** เป็นโค้ดที่คอมเมนต์ไว้ เอา `//` ออกแล้วแทนที่ `todo(1)` ได้เลย แต่ลองอ่านก่อนว่าแต่ละบรรทัดทำอะไร

ในไฟล์ต่อ node `retrieve`, `grade`, `rewrite`, `generate`, `giveUp` และ prompt ให้แล้ว ขาดแค่ฟังก์ชันเลือกทาง

โค้ดตามแนวทาง:

```ts
if (state.relevant) return "generate";
return state.rewrites < MAX_REWRITES ? "rewrite" : "giveUp";
```

## 2. ผลที่ได้

ตัวอย่างผลที่รันจากเฉลย ข้อความจากโมเดลเปลี่ยนได้ทุกรอบ

```text
{ answer: 'ให้รีเซ็ตรหัสผ่านที่พอร์ทัล IT', rewrites: 0 }
✅ ผลค้นเกี่ยวข้องตั้งแต่ครั้งแรก: ให้คะแนน แล้วตอบ (ไม่เขียนคำค้นใหม่)
✅ ขั้นตอบเห็นเอกสาร (พร้อมที่มา) และคำถาม
✅ ผู้ให้คะแนนเห็นทั้งคำถามและเอกสาร
✅ ไม่เกี่ยวครั้งแรก: เขียนคำค้นใหม่ ค้นอีกรอบ แล้วตอบ
✅ หลังเขียนใหม่ ขั้นให้คะแนนและขั้นตอบยังเห็นคำถามเดิม
✅ ลองใหม่แล้วยังไม่เกี่ยว: ยอมรับว่าไม่พบ และไม่เรียกโมเดลตอบ
✅ โมเดลจริง: ได้คำตอบ และเขียนคำค้นใหม่ไม่เกินเพดาน
```

สิ่งที่ได้: สร้าง RAG ที่ตรวจตัวเองและยอมรับว่าไม่รู้ได้

## 3. ส่วนประกอบที่ใช้ในบทนี้

| เงื่อนไข | ทางที่เลือก |
|---|---|
| `state.relevant` เป็นจริง | `"generate"` |
| ไม่เกี่ยวและ `rewrites < MAX_REWRITES` | `"rewrite"` แล้วค้นใหม่ |
| ไม่เกี่ยวและเขียนใหม่ครบแล้ว | `"giveUp"` |

## ข้อควรจำ

- การให้คะแนนด้วยโมเดลเพิ่มค่าใช้จ่ายและอาจพลาด วัดผลด้วย eval (บท 4-08) ว่าคุ้มหรือไม่
- เขียนเกณฑ์ให้ grade เคร่งพอ (ไม่ใช่ "เกี่ยวข้องทุกอย่าง")
