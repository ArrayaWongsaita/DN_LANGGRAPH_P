# บทที่ 4-20: agentic RAG (ให้คะแนนผลค้นและเขียนคำถามใหม่)

## แนวคิด
ผลค้นหาไม่ได้ดีเสมอไป: คำถามอาจกำกวม ("ทำไงดี") หรือใช้คำคนละชุดกับเอกสาร RAG แบบ **agentic** เพิ่มการตัดสินใจเข้าไปใน graph:

```
retrieve → grade (ผลที่ได้เกี่ยวข้องไหม?)
              ├ เกี่ยวข้อง → generate (ตอบ) → END
              └ ไม่เกี่ยว → rewrite (เขียนคำค้นใหม่) → retrieve   (ทำได้ 1 ครั้ง)
                            ไม่ไหวแล้ว → giveUp ("ไม่พบในเอกสาร") → END
```
- **grade:** ใช้โมเดลตอบแบบมีโครงสร้าง `{ relevant: boolean }` (บท 2-14)
- **rewrite:** ให้โมเดลปรับคำค้นให้ตรงกับศัพท์ในเอกสารมากขึ้น
- **giveUp:** ถ้าลองแล้วยังไม่เจอ **ตอบตรง ๆ ว่าไม่พบ** ดีกว่าให้โมเดลแต่งคำตอบเอง ข้อนี้สำคัญที่สุดของระบบที่เชื่อถือได้
- ต้องมีเพดานจำนวนรอบเสมอ (บท 3-09) เพื่อกันวน

ที่นี่ retrieve ใช้ index จริงในหน่วยความจำ (embedding ปลอมแบบนับคำ) ส่วนโมเดลคือตัวที่ส่งเข้ามา (ปลอมในตัวตรวจ)

## ดูตัวอย่าง
`agentic.ts` ต่อ node retrieve/rewrite/generate/giveUp ไว้ให้แล้ว ขาด node ให้คะแนน การเลือกเส้นทางหลังให้คะแนน และ prompt ขั้นตอบ

## คุณทำได้แล้ว
- สร้าง RAG ที่ตรวจตัวเองและยอมรับว่าไม่รู้ได้

## ข้อควรจำ
- การให้คะแนนด้วยโมเดลเพิ่มค่าใช้จ่ายและอาจพลาด วัดผลด้วย eval (บท 4-08) ว่าคุ้มหรือไม่
- เขียนเกณฑ์ให้ grade เคร่งพอ (ไม่ใช่ "เกี่ยวข้องทุกอย่าง")
