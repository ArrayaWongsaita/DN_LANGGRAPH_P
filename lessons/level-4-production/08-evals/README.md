# บทที่ 4-08 ประเมินคุณภาพด้วยชุดทดสอบ (eval)

## แนวคิด

การทดสอบด้วยโมเดลปลอมบอกว่า **โค้ดถูก** แต่ไม่บอกว่า **โมเดลตอบดีไหม** นั่นคืองานของ **eval**: เตรียมชุดคำถามพร้อมคำตอบที่คาดหวัง รันกับโมเดลจริง แล้วให้คะแนน

```ts
type Case = { input: string; expected: string };
const result = await runEval(askMyAgent, cases, containsScorer);  // { passed, total, rate, failures }
```
ตัวให้คะแนน (scorer) มีสองแบบหลัก:
- **กฎ (rule):** เช็กตรง ๆ เช่นคำตอบ "มีคำว่า" ที่คาดหวัง ถูก เร็ว แต่แข็ง
- **โมเดลเป็นกรรมการ (LLM-as-judge):** ให้โมเดลอีกตัวอ่านคำตอบแล้วตอบ `PASS` หรือ `FAIL` ยืดหยุ่น แต่ต้องตรวจสอบความน่าเชื่อถือของกรรมการเอง

ตอน CI ใช้กรรมการปลอมได้ (เหมือนบทที่แล้ว) และรัน eval กับโมเดลจริงเป็นระยะ เช่นก่อนปล่อยเวอร์ชัน

## 1. ลองเติมช่องเดียว

เปิด [`evals.ts`](./evals.ts) แล้วเติมข้อ 1: รันกรณีทดสอบทีละข้อและเก็บข้อที่ไม่ผ่านใน `failures` รันจากโฟลเดอร์หลักของโปรเจกต์ บทนี้เรียกโมเดลจริง ตั้ง provider และ API key ใน `.env` ตาม [บท 1-02](../../level-1-basics/02-llm-config/README.md) ก่อนรัน

```sh
pnpm lesson 4-08
```

ในไฟล์ข้อ 1 มี **แนวทาง** เป็นโค้ดที่คอมเมนต์ไว้ เอา `//` ออกแล้วแทนที่ `todo(1)` ได้เลย แต่ลองอ่านก่อนว่าแต่ละบรรทัดทำอะไร

ในไฟล์มี scorer แบบกฎ, scorer แบบกรรมการและชุดทดสอบให้แล้ว ขาดแค่ตัวรันที่วนเรียก `run` แล้วให้ scorer ตัดสิน

โค้ดตามแนวทาง:

```ts
const output = await run(testCase.input);
if (!(await scorer(output, testCase))) failures.push(testCase.input);
```

## 2. ผลที่ได้

ตัวอย่างผลที่รันจากเฉลย ข้อความจากโมเดลเปลี่ยนได้ทุกรอบ

```text
  ruled: {
    passed: 2,
    total: 3,
    rate: 0.6666666666666666,
    failures: [ '2+2' ]
  realRuled: { passed: 3, total: 3, rate: 1, failures: [] },
  realJudged: { passed: 3, total: 3, rate: 1, failures: [] }
✅ scorer แบบกฎ: มีคำที่คาดหวัง = ผ่าน ไม่สนตัวพิมพ์
✅ runEval: นับผ่าน/ไม่ผ่าน คิดอัตรา และบอกข้อที่ตก
✅ ชุดทดสอบว่าง: rate เป็น 0 ไม่ใช่ NaN
✅ กรรมการ: PASS ผ่าน FAIL ตก
✅ กรรมการ: คำตัดสินว่างตก ส่วน "PASS." ผ่าน
✅ พรอมต์ของกรรมการมีทั้งคำถาม คำตอบที่คาดหวัง และคำตอบจริง
✅ eval กับโมเดลจริงทำงานครบ 3 ข้อทั้งสองแบบ
```

สิ่งที่ได้: วัดคุณภาพของระบบเป็นตัวเลขที่เทียบกันข้ามเวอร์ชันได้

## 3. ส่วนประกอบที่ใช้ในบทนี้

| ชนิด scorer | ตัดสินด้วย | เหมาะกับ |
|---|---|---|
| แบบกฎ | โค้ดเทียบผลกับคำตอบที่คาด | คำตอบที่เช็กได้ตรง ๆ |
| แบบกรรมการ | โมเดลให้คะแนน | คำตอบที่ต้องใช้วิจารณญาณ ควรใช้โมเดลคนละตัวกับผู้ตอบ |

## ข้อควรจำ

- ชุดทดสอบต้องมีทั้งกรณีง่ายและกรณีที่เคยพลาด เพิ่มกรณีใหม่ทุกครั้งที่เจอบั๊ก
- อย่าใช้โมเดลตัวเดียวกันเป็นทั้งผู้ตอบและกรรมการถ้าเลี่ยงได้
