# บทที่ 4-15 context engineering (ล้างผลลัพธ์ tool เก่า)

## แนวคิด

agent ที่ใช้ tool หลายรอบจะสะสมผลลัพธ์ของ tool ในประวัติ (เช่นข้อความยาวจากการค้นหา) ซึ่งกิน token และอาจทำให้โมเดลสับสน ผลลัพธ์เก่ามักหมดประโยชน์แล้ว **context engineering** คือการเลือกว่าโมเดลควรเห็นอะไรในแต่ละรอบ `contextEditingMiddleware` ทำให้ง่ายที่สุดด้วยการ **แทนที่ผลลัพธ์ tool เก่าด้วยข้อความสั้น**:

```ts
contextEditingMiddleware({
  edits: [new ClearToolUsesEdit({
    trigger: { tokens: 100_000 },   // เริ่มล้างเมื่อ context ใหญ่ถึงเกณฑ์
    keep: { messages: 3 },          // เก็บผลลัพธ์ล่าสุด 3 อัน
    placeholder: "[ล้างแล้ว]",      // ข้อความที่ใส่แทน
    excludeTools: ["important"],    // tool ที่ห้ามล้าง
  })],
})
```
ต่างจาก summarization (บท 3-28) ที่สรุปทั้งบทสนทนา: อันนี้ล้างเฉพาะ **ผลลัพธ์ของ tool** โดยไม่แตะข้อความของผู้ใช้และโมเดล และไม่ต้องเรียกโมเดลเพิ่ม (ใช้ในบทนี้ตั้ง `trigger` ต่ำมากเพื่อให้เห็นผลในการทดสอบ)

## 1. ลองเติมช่องเดียว

เปิด [`editing.ts`](./editing.ts) แล้วเติมข้อ 1: สร้าง `ClearToolUsesEdit` ที่ล้างผลลัพธ์ tool เก่าเหลือล่าสุด 1 ข้อความ รันจากโฟลเดอร์หลักของโปรเจกต์ บทนี้เรียกโมเดลจริง ตั้ง provider และ API key ใน `.env` ตาม [บท 1-02](../../level-1-basics/02-llm-config/README.md) ก่อนรัน

```sh
pnpm lesson 4-15
```

ในไฟล์ข้อ 1 มี **แนวทาง** เป็นโค้ดที่คอมเมนต์ไว้ เอา `//` ออกแล้วแทนที่ `todo(1)` ได้เลย แต่ลองอ่านก่อนว่าแต่ละบรรทัดทำอะไร

ในไฟล์มี agent ที่เรียก tool บวกหลายรอบ และการนำ edit ไปใส่ใน `contextEditingMiddleware` ให้แล้ว ขาดแค่ตัว edit

โค้ดตามแนวทาง:

```ts
const edit = new ClearToolUsesEdit({ trigger: { tokens: 1 }, keep: { messages: 1 }, placeholder: "[ล้างแล้ว]" });
```

## 2. ผลที่ได้

ตัวอย่างผลที่รันจากเฉลย ข้อความจากโมเดลเปลี่ยนได้ทุกรอบ

```text
โมเดลจริงตอบ: ทำตามลำดับให้แล้วครับ (เรียก tool ทีละครั้ง):

1. `add(1, 1)` → **2**
2. `add(2, 2)` → **4**
3. `add(4, 3)` → **7**

**ผลสุดท้าย = 7**

หมายเหตุ: ผลลัพธ์ของสองครั้งแรกถูกล้างออกจากหน้าจอ (แสดงเป็น "[ล้างแล้ว]") แต่ค่าที่ใช้บวกในขั้นถัดไปคือ 2 และ 4 ตามลำดับ และผลจาก tool ครั้งสุดท้ายยืนยันว่าได้ 7 ครับ
✅ ผลลัพธ์ tool เก่าถูกแทนด้วย placeholder เหลือเฉพาะอันล่าสุด
✅ รอบแรกยังไม่มีอะไรให้ล้าง และรอบที่สองเห็นผลลัพธ์อันแรกครบ
✅ ข้อความของผู้ใช้ไม่ถูกแตะ
✅ โมเดลจริงทำงานผ่าน middleware ได้และตอบผลสุดท้าย
```

สิ่งที่ได้: คุม context ของ agent ที่ใช้ tool หนัก ๆ ไม่ให้บวมโดยไม่เสียค่าสรุป

## 3. ส่วนประกอบที่ใช้ในบทนี้

| ตัวเลือก | ค่าในบทนี้ | ความหมาย |
|---|---|---|
| `trigger` | `{ tokens: 1 }` | เริ่มล้างเมื่อ context ถึงเกณฑ์ (ตั้งต่ำเพื่อให้เห็นผลในบทนี้) |
| `keep` | `{ messages: 1 }` | เก็บผลล่าสุดไว้กี่ข้อความ |
| `placeholder` | `"[ล้างแล้ว]"` | ข้อความที่แทนผลที่ถูกล้าง |

## ข้อควรจำ

- ล้างแล้วโมเดลเห็นแค่ placeholder ถ้าผลลัพธ์เก่ายังจำเป็นต้องใช้ ให้เพิ่ม `keep` หรือใส่ tool นั้นใน `excludeTools`
- ใช้ `trigger` ที่ตรงกับ context window ของโมเดลที่ใช้จริง
