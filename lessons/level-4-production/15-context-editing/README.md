# บทที่ 4-15: context engineering (ล้างผลลัพธ์ tool เก่า)

## แนวคิด
agent ที่ใช้ tool หลายรอบจะสะสมผลลัพธ์ของ tool ในประวัติ (เช่นข้อความยาวจากการค้นหา) ซึ่งกิน token และอาจทำให้โมเดลสับสน ผลลัพธ์เก่ามักหมดประโยชน์แล้ว **context engineering** คือการเลือกว่าโมเดลควรเห็นอะไรในแต่ละรอบ `contextEditingMiddleware` ทำให้ง่ายที่สุดด้วยการ **แทนที่ผลลัพธ์ tool เก่าด้วยข้อความสั้น**:

```ts
contextEditingMiddleware({
  edits: [new ClearToolUsesEdit({
    trigger: { tokens: 100_000 },   // เริ่มล้างเมื่อ context ใหญ่ถึงเกณฑ์
    keep: { messages: 3 },          // เก็บผลลัพธ์ล่าสุด 3 อัน
    placeholder: "[ล้างแล้ว]",      // ข้อความที่ใส่แทน
    excludeTools: ["important"],    // tool ที่ห้ามล้าง
  })],
})
```
ต่างจาก summarization (บท 3-28) ที่สรุปทั้งบทสนทนา: อันนี้ล้างเฉพาะ **ผลลัพธ์ของ tool** โดยไม่แตะข้อความของผู้ใช้และโมเดล และไม่ต้องเรียกโมเดลเพิ่ม (ใช้ในบทนี้ตั้ง `trigger` ต่ำมากเพื่อให้เห็นผลในการทดสอบ)

## ดูตัวอย่าง
`editing.ts` สร้าง agent ที่เรียก tool บวกหลายรอบ ขาดการตั้ง middleware

## โจทย์
เติม 2 ข้อ แล้วรัน:

    pnpm lesson 4-15

สคริปต์จะพิมพ์ผล แล้วท้ายไฟล์มีส่วนตรวจที่แสดง ✅/❌ (ไม่ต้องแก้และไม่ต้องอ่านก็ได้)

## คุณทำได้แล้ว
- คุม context ของ agent ที่ใช้ tool หนัก ๆ ไม่ให้บวมโดยไม่เสียค่าสรุป

## ข้อควรจำ
- ล้างแล้วโมเดลเห็นแค่ placeholder ถ้าผลลัพธ์เก่ายังจำเป็นต้องใช้ ให้เพิ่ม `keep` หรือใส่ tool นั้นใน `excludeTools`
- ใช้ `trigger` ที่ตรงกับ context window ของโมเดลที่ใช้จริง

## ลองเล่นต่อ
อยากทดลองเองโดยไม่มีส่วนตรวจคำตอบ: `pnpm play 4-15` จะรันไฟล์ `playground.ts` ในโฟลเดอร์บทนี้ (สร้างให้แล้ว มีแต่ import ที่ใช้ เขียนโค้ดต่อเองได้เลย) ในหัวไฟล์มีไอเดียให้ลองทำ ใช้ `--watch` ให้รันซ้ำทุกครั้งที่บันทึก และ `--reset` เพื่อเริ่มใหม่
