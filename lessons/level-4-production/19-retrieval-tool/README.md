# บทที่ 4-19 ให้ agent ค้นเอกสารเป็น tool

## แนวคิด

วิธี RAG ที่ง่ายและยืดหยุ่นที่สุดในยุค agent: ทำการค้นหาเป็น **tool** แล้วให้ agent ตัดสินใจเองว่าจะค้นเมื่อไรและค้นด้วยคำอะไร (บท 2-08, 2-16):

```
ผู้ใช้ถาม → agent เรียก search_docs("รีเซ็ตรหัสผ่าน") → ได้ชิ้นเอกสาร + ที่มา → ตอบโดยอ้างจากนั้น
```
สิ่งที่ต้องออกแบบดี ๆ มีสามอย่าง:
1. **รูปแบบผลลัพธ์ของ tool:** ใส่ที่มาทุกชิ้น (`[it.md] ...`) เพื่อให้โมเดลอ้างอิงได้ และกรองชิ้นที่คะแนนเป็น 0 (ไม่เกี่ยวเลย) ทิ้ง ถ้าไม่เหลือสักชิ้นให้บอกชัดว่าไม่พบ ไม่ใช่ส่งข้อความว่าง
2. **คำอธิบาย tool** ที่บอกว่าใช้เมื่อไร
3. **system prompt** ให้ตอบจากผลที่ค้นได้เท่านั้น และบอกตรง ๆ ถ้าไม่พบ (ลดการมั่ว)

เทียบกับ "ค้นก่อนเสมอแล้วยัดทุกครั้ง" (2-step RAG): แบบ tool ประหยัดเมื่อคำถามไม่ต้องใช้เอกสาร (เช่นทักทาย) และ agent ค้นซ้ำด้วยคำใหม่ได้ ราคาคือเรียกโมเดลหลายรอบ

## 1. ลองเติมช่องเดียว

เปิด [`rag.ts`](./rag.ts) แล้วเติมข้อ 1: ให้ tool ค้นเอกสารคืนผลที่จัดรูปแล้วของ 2 ชิ้นที่ใกล้ที่สุด รันจากโฟลเดอร์หลักของโปรเจกต์ บทนี้เรียกโมเดลจริง ตั้ง provider และ API key ใน `.env` ตาม [บท 1-02](../../level-1-basics/02-llm-config/README.md) ก่อนรัน

```sh
pnpm lesson 4-19
```

ในไฟล์ข้อ 1 มี **แนวทาง** เป็นโค้ดที่คอมเมนต์ไว้ เอา `//` ออกแล้วแทนที่ `todo(1)` ได้เลย แต่ลองอ่านก่อนว่าแต่ละบรรทัดทำอะไร

ในไฟล์มี index ที่พร้อมใช้, `formatHits` และการประกอบ agent ให้แล้ว ขาดแค่การเรียกค้นภายใน tool

โค้ดตามแนวทาง:

```ts
return formatHits(await index.search(query, 2));
```

## 2. ผลที่ได้

ตัวอย่างผลที่รันจากเฉลย ข้อความจากโมเดลเปลี่ยนได้ทุกรอบ

```text
โมเดลจริงตอบ: จากเอกสาร IT พบวิธีดำเนินการดังนี้ครับ

- **ลืมรหัสผ่าน** → ให้ทำการรีเซ็ตรหัสผ่านที่ **พอร์ทัล IT**
- **หากทำงานอยู่นอกออฟฟิศ** → ต้อง **เปิด VPN** ก่อนด้วยครับ

เอกสารระบุไว้เพียงเท่านี้ ไม่ได้ให้รายละเอียดเพิ่มเติมเกี่ยวกับขั้นตอนในพอร์ทัลครับ
✅ formatHits: บรรทัดละชิ้นพร้อมที่มา และตัดชิ้นที่คะแนน 0 ทิ้ง
✅ formatHits: ไม่มีชิ้นที่เกี่ยวข้องเลย ต้องบอกชัดเจน ไม่ใช่ข้อความว่าง
✅ tool ค้นหาคืนข้อความที่ถูกจัดรูปแล้ว
✅ agent: ค้นด้วย tool แล้วตอบ และโมเดลเห็นผลค้นหาพร้อมที่มา
✅ system prompt สั่งให้ตอบจากเอกสาร ไม่ต้องเดา
✅ โมเดลจริงค้นเอกสารแล้วตอบ (มีคำว่า รีเซ็ต หรือ พอร์ทัล)
```

สิ่งที่ได้: สร้าง agent ที่ตอบจากเอกสารของคุณพร้อมที่มา

## 3. ส่วนประกอบที่ใช้ในบทนี้

| ส่วน | หน้าที่ |
|---|---|
| tool `search_docs` | agent ตัดสินใจเองว่าจะค้นเมื่อไรและด้วยคำอะไร |
| `index.search(query, 2)` | ดึง 2 ชิ้นที่ใกล้ที่สุด |
| `formatHits` | แปลงผลเป็นข้อความพร้อมที่มา |

## ข้อควรจำ

- ผลค้นหาคือ "ข้อมูลภายนอก" ที่อาจมีคำสั่งแอบแฝง ดูบท 4-14
- ตั้ง k ให้พอดี ชิ้นมากเกินไปทำให้ prompt บวมและโมเดลสับสน
