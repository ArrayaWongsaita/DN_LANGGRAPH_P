# บทที่ 4-19: ให้ agent ค้นเอกสารเป็น tool

## แนวคิด
วิธี RAG ที่ง่ายและยืดหยุ่นที่สุดในยุค agent: ทำการค้นหาเป็น **tool** แล้วให้ agent ตัดสินใจเองว่าจะค้นเมื่อไรและค้นด้วยคำอะไร (บท 2-08, 2-16):

```
ผู้ใช้ถาม → agent เรียก search_docs("รีเซ็ตรหัสผ่าน") → ได้ชิ้นเอกสาร + ที่มา → ตอบโดยอ้างจากนั้น
```
สิ่งที่ต้องออกแบบดี ๆ มีสามอย่าง:
1. **รูปแบบผลลัพธ์ของ tool:** ใส่ที่มาทุกชิ้น (`[it.md] ...`) เพื่อให้โมเดลอ้างอิงได้ และกรองชิ้นที่คะแนนเป็น 0 (ไม่เกี่ยวเลย) ทิ้ง ถ้าไม่เหลือสักชิ้นให้บอกชัดว่าไม่พบ ไม่ใช่ส่งข้อความว่าง
2. **คำอธิบาย tool** ที่บอกว่าใช้เมื่อไร
3. **system prompt** ให้ตอบจากผลที่ค้นได้เท่านั้น และบอกตรง ๆ ถ้าไม่พบ (ลดการมั่ว)

เทียบกับ "ค้นก่อนเสมอแล้วยัดทุกครั้ง" (2-step RAG): แบบ tool ประหยัดเมื่อคำถามไม่ต้องใช้เอกสาร (เช่นทักทาย) และ agent ค้นซ้ำด้วยคำใหม่ได้ ราคาคือเรียกโมเดลหลายรอบ

## ดูตัวอย่าง
`rag.ts` มี index พร้อมใช้ ขาดตัวจัดรูปผลลัพธ์ tool ค้นหา และการประกอบ agent
