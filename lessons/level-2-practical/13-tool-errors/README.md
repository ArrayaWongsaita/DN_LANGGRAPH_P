# บทที่ 2-13: เมื่อ tool พัง

## แนวคิด
tool คือโค้ดที่คุยกับโลกภายนอก มันพังได้ (หารด้วยศูนย์, เครือข่ายล่ม, ไม่มีข้อมูล) ถ้าปล่อยให้ exception หลุดออกไป agent ทั้งตัวจะล่ม แต่ `ToolNode` จับ error ให้เราแล้ว: ถ้า tool throw มันจะ **แปลงเป็น `ToolMessage` ที่มี `status: "error"`** และข้อความ error ส่งกลับให้ LLM เห็น LLM จึงมีโอกาส "แก้ตัว" เช่นเปลี่ยน argument หรืออธิบายผู้ใช้

```ts
// ผลเมื่อ tool throw
ToolMessage { content: "Error: หารด้วยศูนย์ไม่ได้\n Please fix your mistakes.", status: "error" }
```
หลักการเขียน tool ที่ดี:
- **ข้อความ error ต้องบอกว่าผิดอะไร** เพราะ LLM เป็นคนอ่าน
- สิ่งที่เป็น "ผลปกติ" (เช่นไม่พบเมืองนี้) คืนเป็นข้อความธรรมดาได้ ไม่ต้อง throw
- นับ/ตรวจ error จาก `status === "error"` ได้เมื่อต้องการ log

## ดูตัวอย่าง
`errors.ts` มี tool `divide` ที่ต้อง throw เมื่อหารศูนย์ และสคริปต์ที่ส่งคำขอหารสองครั้งเข้า `ToolNode` ขาดตัวฟังก์ชันของ tool และการนับ tool error ในผลลัพธ์ บทนี้ไม่ใช้ LLM

## คุณทำได้แล้ว
- เขียน tool ที่รายงาน error ได้ชัดเจนและให้ agent ฟื้นตัวเองได้

## ข้อควรจำ
- ข้อความ error คือ "คำสั่งสอน" ที่ LLM อ่าน เขียนให้ชัด
- agent ไม่ล่มเพราะ tool พัง แต่ยังต้องมี recursion limit กัน LLM ลองซ้ำไม่จบ
