# บทที่ 2-20: ให้มนุษย์ตรวจและแก้ไขร่าง

## แนวคิด
การอนุมัติไม่ได้มีแค่ใช่/ไม่ มนุษย์ยัง **แก้ไขสิ่งที่ AI ร่างไว้** แล้วค่อยไปต่อได้ เช่น AI ร่างอีเมล คนอ่านแล้วแก้ถ้อยคำ แล้วระบบส่งฉบับที่แก้แล้ว:

```
write (LLM ร่าง) → review (interrupt แสดงร่าง รอฉบับแก้) → send (ใช้ฉบับสุดท้าย)
```
รูปแบบ: ส่งร่างออกไปกับ `interrupt({ draft })` และให้คน resume ด้วย **ข้อความที่แก้แล้ว** (ถ้าโอเคตามร่าง ให้ส่งร่างเดิมกลับไปทั้งดุ้น เพราะ `resume` เป็น `null` ไม่ได้)

## ดูตัวอย่าง
`review.ts` มี node `write` (LLM ร่างข้อความ) ขาดโหนด `review` ที่หยุดรอ และการ resume ทั้งแบบส่งฉบับแก้และแบบ "ใช้ตามร่าง"

## โจทย์
เติม 3 ข้อ (ค้นหา `// 👉 ข้อ N` ในไฟล์) แล้วรัน:

    pnpm lesson 2-20

สคริปต์จะพิมพ์ผล แล้วท้ายไฟล์มีส่วนตรวจที่แสดง ✅/❌ (ไม่ต้องแก้และไม่ต้องอ่านก็ได้)

## คุณทำได้แล้ว
- ให้มนุษย์แก้ผลงานของ AI ก่อนระบบทำต่อ

## ข้อควรจำ
- ชื่อ node ห้ามซ้ำกับชื่อ field ใน State (ที่นี่ field ชื่อ `draft` เลยตั้งชื่อ node ว่า `write`)
- กำหนดให้ชัดว่า resume ว่างหมายถึง "ใช้ตามร่าง"
- ฉบับที่แก้ ใช้แทนร่างเดิมใน State จริง ๆ ไม่ใช่แค่แสดงผล

## ลองเล่นต่อ
อยากทดลองเองโดยไม่มีส่วนตรวจคำตอบ: `pnpm play 2-20` จะรันไฟล์ `playground.ts` ในโฟลเดอร์บทนี้ (สร้างให้แล้ว มีแต่ import ที่ใช้ เขียนโค้ดต่อเองได้เลย) ในหัวไฟล์มีไอเดียให้ลองทำ ใช้ `--watch` ให้รันซ้ำทุกครั้งที่บันทึก และ `--reset` เพื่อเริ่มใหม่
