# บทที่ 2-01: เก็บข้อความแชตไว้ใน State

## แนวคิด
แชตบอตต้องจำว่า "คุยอะไรกันไปแล้ว" ใน LangGraph ที่ที่จำคือ **State** เราเก็บรายการข้อความไว้ใน field ชื่อ `messages` และใช้ `MessagesValue` ที่เป็น reducer สำเร็จรูปสำหรับแชต (บท 16 สอนว่า reducer คืออะไร):

- node คืน `{ messages: [ข้อความใหม่] }` แล้วข้อความจะถูก **ต่อท้าย** รายการเดิม (ไม่ทับ)
- รับทั้ง object ข้อความ (`HumanMessage`, `AIMessage`) ได้ตรง ๆ

```ts
const State = new StateSchema({ messages: MessagesValue });

// node: ส่งประวัติทั้งหมดให้ LLM แล้วต่อคำตอบท้ายประวัติ
async (state) => ({ messages: [await llm.invoke(state.messages)] })
```

> **กล่องข้อสังเกต: ตัวตรวจในคอร์สนี้ทำงานอย่างไร** ไฟล์ `chat.test.ts` ไม่เรียก LLM จริง แต่ส่ง "LLM ปลอม" (`fakeToolLLM`) ที่ตอบตามสคริปต์เข้าไปในฟังก์ชันของคุณ จึงตรวจผลได้แน่นอนและไม่ต้องมี key ฟังก์ชันของคุณรับ `llm` เป็นพารามิเตอร์ ตัวจริงหรือตัวปลอมก็ใช้ได้เหมือนกัน

## ดูตัวอย่าง
`chat.ts` มี graph แชตโหนดเดียว: ส่ง `state.messages` ให้ LLM แล้วต้องคืนคำตอบกลับเข้า State ยังไม่มีความจำข้ามรอบ (เรียก `invoke` ใหม่ = เริ่มใหม่) ซึ่งเราจะแก้ในบทถัดไป

## คุณทำได้แล้ว
- เก็บประวัติแชตใน State ด้วย `MessagesValue`
- เห็นว่าไม่มี checkpointer = ไม่มีความจำข้ามการเรียก

## ข้อควรจำ
- `messages` เป็นรายการข้อความ ไม่ใช่สตริง
- node คืนเฉพาะ "ข้อความใหม่" reducer ต่อท้ายให้เอง
- ข้อความตอบกลับของ LLM เป็น `AIMessage` ใช้ `.text` อ่านเป็นสตริง

## บทถัดไป
บท 2-02 เพิ่ม checkpointer เพื่อให้ graph จำข้ามการเรียก
