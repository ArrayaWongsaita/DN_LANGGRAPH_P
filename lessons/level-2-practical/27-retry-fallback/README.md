# บทที่ 2-27: ลองใหม่ (retry) และตัวสำรอง (fallback)

## แนวคิด
เรียก LLM ผ่านเครือข่ายย่อมพลาดได้: ถูกจำกัดอัตรา (429), เซิร์ฟเวอร์ล่มชั่วคราว, โมเดลไม่ว่าง งานจริงต้องรับมือ LangChain ให้เครื่องมือสองตัวที่ใช้กับ LLM (หรือ Runnable ใด ๆ) ได้ตรง ๆ:

```ts
const sturdy = llm
  .withRetry({ stopAfterAttempt: 3 })              // ล้มเหลว ลองใหม่ได้สูงสุด 3 ครั้ง
  .withFallbacks({ fallbacks: [backupLlm] });       // ยังล้มอีก ให้ตัวสำรองตอบแทน
```
ใช้แทน LLM เดิมได้เลย (`await sturdy.invoke(...)`) ส่วนนี้ยังสอนเรื่อง **การสลับโมเดล** ด้วย: ตัวสำรองมักเป็นโมเดลอื่นหรือ provider อื่นที่เราตั้งไว้ใน `src/llm.ts` ทำให้แอปไม่ผูกกับเจ้าเดียว

## คุณทำได้แล้ว
- ทำให้การเรียก LLM ทนต่อความล้มเหลวด้วย retry และ fallback

## ข้อควรจำ
- retry เหมาะกับความผิดพลาดชั่วคราว (ลองใหม่แล้วอาจผ่าน) แต่ error ถาวร (key ผิด 401) ลองกี่ครั้งก็ไม่หาย
- `withRetry` รอเว้นช่วงก่อนลองใหม่ (เพิ่มเป็นสองเท่าทุกครั้ง) ตัวตรวจของบทนี้จึงช้ากว่าบทอื่นสองสามวินาที
- retry ทำให้ใช้เวลาและเงินเพิ่ม จำกัดจำนวนครั้งเสมอ
- ลำดับสำคัญ: retry ตัวหลักก่อน แล้วค่อยสลับไปตัวสำรอง
