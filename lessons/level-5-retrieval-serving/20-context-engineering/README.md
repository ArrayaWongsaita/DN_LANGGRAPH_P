# บทที่ 5-20 Context engineering ด้วยพรอมต์และโมเดลแบบไดนามิก

## แนวคิด

Context engineering คือการ **จัดสิ่งที่โมเดลเห็นในแต่ละครั้งที่เรียก** ให้ถูกต้องพอดี บท 4-15 ทำเรื่อง "ล้างผลลัพธ์ tool เก่า" บทนี้ทำอีกสองมือของงานเดียวกัน: **พรอมต์ระบบ** และ **เลือกโมเดล** ที่เปลี่ยนตามผู้เรียกและสถานการณ์ โดยไม่ต้องสร้าง agent ใหม่ทุกครั้ง

ข้อมูลต่อผู้เรียก (ชื่อ แพ็กเกจ ภาษา) ส่งผ่าน **runtime context** (บท 3-05) ไม่ใช่ใน state:

```ts
const contextSchema = z.object({ tier: z.enum(["free", "pro"]).default("free"), name: z.string().default("ผู้ใช้") });
const agent = createAgent({ model, contextSchema, middleware: [promptMw, routerMw] });
await agent.invoke({ messages }, { context: { tier: "pro", name: "สมชาย" } });
```
- `dynamicSystemPromptMiddleware((state, runtime) => string)` สร้างพรอมต์ระบบ **ก่อนทุกการเรียกโมเดล** จาก `runtime.context` และ state
- `createMiddleware({ wrapModelCall })` ครอบการเรียกโมเดล: แก้คำขอ (`request`) ก่อนส่งต่อ `handler({ ...request, model })` สลับโมเดลได้ที่นี่

สิ่งที่ควรทำเป็นฟังก์ชันล้วน ๆ (ทดสอบง่าย): **กติกาการเลือก** ว่าใครได้โมเดลไหน และ **การประกอบพรอมต์** จากข้อมูลผู้ใช้ จุดที่ต้องระวัง:
- ข้อมูลผู้ใช้ที่เอาไปใส่พรอมต์คือ **ข้อความที่ผู้ใช้ควบคุมได้** (เช่นชื่อที่ตั้งเอง) ทำให้เกิด prompt injection ได้ ต้องทำความสะอาดและจำกัดความยาว
- พรอมต์ที่เปลี่ยนทุกครั้งทำให้ prompt cache ของผู้ให้บริการใช้ไม่ได้ผล ถ้าส่วนใหญ่คงที่ให้เรียงส่วนคงที่ไว้ก่อน

## 1. ลองเติมช่องเดียว

เปิด [`context.ts`](./context.ts) แล้วเติมข้อ 1: เติมส่วนหลักของบท (Context engineering ด้วยพรอมต์และโมเดลแบบไดนามิก) รันจากโฟลเดอร์หลักของโปรเจกต์ บทนี้เรียกโมเดลจริง ตั้ง provider และ API key ใน `.env` ตาม [บท 1-02](../../level-1-basics/02-llm-config/README.md) ก่อนรัน

```sh
pnpm lesson 5-20
```

ในไฟล์ข้อ 1 มี **แนวทาง** เป็นโค้ดที่คอมเมนต์ไว้ เอา `//` ออกแล้วแทนที่ `todo(1)` ได้เลย แต่ลองอ่านก่อนว่าแต่ละบรรทัดทำอะไร

`context.ts` มี `contextSchema` และการประกอบ agent ให้แล้ว ส่วนอื่นของบทนี้เขียนไว้ให้แล้ว ขาดแค่ข้อ 1

โค้ดตามแนวทาง:

```ts
return handler({ ...request, model: pickModel(request.runtime.context, models) });
```

## 2. ผลที่ได้

ตัวอย่างผลที่รันจากเฉลย ข้อความจากโมเดลเปลี่ยนได้ทุกรอบ

```text
สวัสดีค่ะคุณมานี ฉันเป็นผู้ช่วยของบริษัท พร้อมให้ข้อมูลและช่วยตอบคำถามค่ะ
✅ sanitizeName: ชื่อปกติผ่าน ภาษาไทยไม่เพี้ยน
✅ sanitizeName: ตัดอักขระควบคุม/ขึ้นบรรทัดใหม่/สัญลักษณ์แท็ก และยุบช่องว่าง
✅ sanitizeName: จำกัดความยาวและ trim หลังตัด
✅ sanitizeName: ค่าว่าง/ผิดชนิด/เหลือแต่สัญลักษณ์ → ค่าเริ่มต้น
✅ sanitizeName: ทำความสะอาดก่อนแล้วค่อยตัดความยาว และแทนอักขระควบคุมทุกตัวรวม DEL
✅ buildSystemPrompt: ส่วนคงที่ก่อน ส่วนที่เปลี่ยนตามผู้ใช้ต่อท้าย
✅ buildSystemPrompt: pro ภาษาอื่น และไม่ใส่ชื่อที่เป็นอันตรายดิบ ๆ
✅ buildSystemPrompt: ไม่มีข้อมูลเลยใช้ค่าเริ่มต้น และชื่อยาวถูกตัดที่ 30 ตัว
✅ pickModel: pro ได้โมเดลใหญ่ นอกนั้นทุกกรณีได้โมเดลเล็ก
✅ agent: ผู้ใช้ pro ใช้โมเดลใหญ่ + พรอมต์ที่ตรงกับ context
✅ agent: ผู้ใช้ free ใช้โมเดลเล็ก และ context ต่างกันได้พรอมต์ต่างกัน (agent ตัวเดียว)
✅ agent: ชื่อที่เป็น prompt injection ถูกทำความสะอาดก่อนถึงโมเดล
✅ โมเดลจริง: ตอบได้ผ่าน agent เดียวกัน
```

สิ่งที่ได้: ปรับพรอมต์และโมเดลตามผู้เรียกใน agent ตัวเดียว อย่างปลอดภัยต่อข้อมูลที่ผู้ใช้ตั้งเอง

## ข้อควรจำ

- กติกาเลือกโมเดลต้องมีค่าเริ่มต้นที่ปลอดภัย (ค่าใน context ผิดรูปต้องไม่ทำให้ได้โมเดลแพงโดยไม่ตั้งใจ)
- โมเดลทุกตัวที่สลับกันต้องรองรับ tool ชุดเดียวกัน (บท 2-15)
