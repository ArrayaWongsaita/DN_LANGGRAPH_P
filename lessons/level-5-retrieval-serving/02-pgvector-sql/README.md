# บทที่ 5-02: เก็บและค้นเวกเตอร์ด้วย pgvector (SQL ตรง ๆ)

## แนวคิด
**pgvector** เป็นส่วนเสริมของ Postgres ที่เพิ่มชนิดข้อมูล `vector(N)` และตัวดำเนินการวัดระยะ ฐานข้อมูลในโปรเจกต์นี้ (`docker compose up -d --wait`) เปิดใช้ไว้ให้แล้ว หลักการ:

```sql
CREATE TABLE course_chunks (id text PRIMARY KEY, source text, text text, embedding vector(768));
-- ค้นหาใกล้ที่สุด: <=> คือระยะ cosine (ยิ่งน้อยยิ่งใกล้)
SELECT source, text, 1 - (embedding <=> $1::vector) AS score
FROM course_chunks ORDER BY embedding <=> $1::vector LIMIT $2;
```
- เวกเตอร์ส่งเป็นสตริงรูป `[0.1,0.2,...]` แล้วแปลงด้วย `::vector`
- **ใส่ค่าด้วยพารามิเตอร์ (`$1`, `$2`) เสมอ ห้ามต่อสตริงเข้า SQL** เพื่อกัน SQL injection และให้ฐานข้อมูลเก็บแผนคำสั่งไว้ใช้ซ้ำ
- ต้อง `ORDER BY` ด้วยระยะ (ไม่ใช่ด้วยคะแนนที่ตั้งชื่อใหม่) เพื่อให้ดัชนี (`hnsw`) ช่วยให้เร็ว
- `score = 1 - ระยะ` ทำให้ยิ่งมากยิ่งคล้าย ตรงกับที่คุณคุ้นจากบท 4-18

ตัวตรวจใช้ฐานข้อมูลปลอมที่จดว่าได้รับ SQL และพารามิเตอร์อะไร ไม่ต้องเปิด Docker

## ดูตัวอย่าง
`pgvector.ts` มีคำสั่งสร้างตารางและ insert ให้แล้ว ขาด 3 ส่วน: แปลงเวกเตอร์เป็นสตริงสำหรับ SQL, ข้อความ SQL ค้นหา และฟังก์ชันค้นหาที่แปลงแถวผลลัพธ์
