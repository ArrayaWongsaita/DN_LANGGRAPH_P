# บทที่ 5-01: embedding จริงและข้อตกลงที่ต้องรักษา

## แนวคิด
ใน Level 4 คุณใช้ embedding ปลอมที่นับคำ ในระดับนี้เราใช้ embedding **จริง** ซึ่งจับ "ความหมาย" ได้ เช่น "ลืมพาสเวิร์ด" ใกล้ "ลืมรหัสผ่าน" ทั้งที่ไม่มีคำซ้ำกันเลย ตัวทำ embedding มาจาก `getEmbeddings()` ใน `src/embeddings.ts` ตั้งค่าที่ `.env` (ดู `.env.example`: `GOOGLE_API_KEY` ที่ขอฟรีได้ และ `EMBEDDING_DIMENSIONS`) ส่วนตัวตรวจของแต่ละบทยังใช้ embedding ปลอม จึงไม่ต้องมี key

ข้อตกลงที่ต้องรักษาเสมอ ไม่งั้นการค้นหาพังแบบเงียบ ๆ:
1. **โมเดลเดียวกันทั้งตอนเก็บและตอนค้นหา** เวกเตอร์จากคนละโมเดลเทียบกันไม่ได้
2. **จำนวนมิติ (dimension) ต้องตรงกับตารางฐานข้อมูล** (`vector(768)` รับได้เฉพาะ 768 ช่อง) ถ้าไม่ตรงจะได้ error ตอน insert หรือแย่กว่านั้นคือผลที่ผิดโดยไม่รู้ตัว
3. **ส่งทีละกลุ่ม (batch)** ผู้ให้บริการจำกัดจำนวนข้อความต่อคำขอ และโควตาฟรีมีเพดาน การส่งข้อความหมื่นอันในคำขอเดียวจะล้มเหลว ส่งทีละกลุ่มตามลำดับ ลำดับของเวกเตอร์ต้องตรงกับลำดับของข้อความ

## ดูตัวอย่าง
`batch.ts` ขาด 3 ส่วน: แบ่งรายการเป็นกลุ่ม ๆ, ฟังก์ชันที่ embed ทีละกลุ่มแล้วรวมผลตามลำดับ และตัวตรวจจำนวนมิติ

## โจทย์
เติม 3 ข้อ แล้วรัน:

    pnpm test:lesson 5-01

ลองกับ embedding จริง (ตั้ง `GOOGLE_API_KEY` ใน `.env` ก่อน):

    pnpm lesson 5-01

## คุณทำได้แล้ว
- ใช้ embedding จริงอย่างปลอดภัย: ส่งเป็นกลุ่ม ตรวจมิติ และรักษาลำดับ

## ข้อควรจำ
- ถ้าเปลี่ยนโมเดลหรือจำนวนมิติ ต้อง embed เอกสารทั้งหมดใหม่
- embedding ที่ตอบเร็วและฟรีมีโควตา เก็บผลไว้ใช้ซ้ำแทนการเรียกซ้ำ (บท 5-06)
