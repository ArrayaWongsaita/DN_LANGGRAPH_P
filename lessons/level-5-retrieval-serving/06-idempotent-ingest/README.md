# บทที่ 5-06 นำเข้าเอกสารโดยไม่ซ้ำ (idempotent ingestion)

## แนวคิด

ระบบ RAG จริงต้องนำเข้าเอกสารซ้ำ ๆ: เอกสารถูกแก้ ลบบางส่วน หรือรันสคริปต์นำเข้าซ้ำ ถ้าแต่ละครั้ง "ลบทั้งหมดแล้ว embed ใหม่" จะเปลืองโควตา embedding และช้า ถ้า "เพิ่มอย่างเดียว" ข้อมูลจะซ้ำและเก่าค้าง

หลักคือ **idempotent** (รันกี่ครั้งผลเหมือนรันครั้งเดียว):
1. **ตั้ง id ของ chunk จากเนื้อหา** (`docId` + hash ของข้อความ) ข้อความเดิมได้ id เดิมเสมอ
2. **เทียบกับของที่มีอยู่:** id ที่ยังมีอยู่ = ไม่ต้องทำอะไร, id ใหม่ = ต้อง embed และเพิ่ม, id ที่เคยมีแต่ตอนนี้ไม่อยู่ในเอกสาร = ลบ
3. **embed เฉพาะที่เพิ่ม** (ประหยัดโควตา) แล้ว upsert

ผลที่ได้: รันซ้ำโดยไม่แก้เอกสาร = ไม่เรียก embedding เลย, แก้หนึ่งย่อหน้า = embed แค่ย่อหน้านั้นและลบอันเก่า

## 1. ลองเติมช่องเดียว

เปิด [`ingest.ts`](./ingest.ts) แล้วเติมข้อ 1: เติมส่วนหลักของบท (นำเข้าเอกสารโดยไม่ซ้ำ (idempotent ingestion)) รันจากโฟลเดอร์หลักของโปรเจกต์ บทนี้เรียกโมเดลจริง ตั้ง provider และ API key ใน `.env` ตาม [บท 1-02](../../level-1-basics/02-llm-config/README.md) ก่อนรัน

```sh
pnpm lesson 5-06
```

ในไฟล์ข้อ 1 มี **แนวทาง** เป็นโค้ดที่คอมเมนต์ไว้ เอา `//` ออกแล้วแทนที่ `todo(1)` ได้เลย แต่ลองอ่านก่อนว่าแต่ละบรรทัดทำอะไร

`ingest.ts` มี interface ของตาราง (`Table`) ให้แล้ว (ของจริงคือตาราง pgvector จากบท 5-02) ส่วนอื่นของบทนี้เขียนไว้ให้แล้ว ขาดแค่ข้อ 1

โค้ดตามแนวทาง:

```ts
const existing = new Set(existingIds);
const wantedIds = new Set(wanted.map((r) => r.id));
return {
  toAdd: wanted.filter((r) => !existing.has(r.id)),
  toRemove: existingIds.filter((id) => !wantedIds.has(id)),
  unchanged: wanted.filter((r) => existing.has(r.id)).length,
};
```

## 2. ผลที่ได้

ตัวอย่างผลที่รันจากเฉลย ข้อความจากโมเดลเปลี่ยนได้ทุกรอบ

```text
  first: { added: 3, removed: 0, unchanged: 0 },
  again: { added: 0, removed: 0, unchanged: 3 },
  edited: { added: 1, removed: 1, unchanged: 2 },
  shrunk: { added: 0, removed: 1, unchanged: 2 }
✅ chunkId: คงที่สำหรับข้อความเดิม ต่างกันเมื่อข้อความหรือเอกสารต่าง
✅ planSync: แยกเพิ่ม/ลบ/คงเดิมถูกต้อง
✅ นำเข้าครั้งแรก: embed และเพิ่มทุกชิ้น
✅ นำเข้าซ้ำโดยไม่แก้อะไร: ไม่เรียก embedding และไม่ซ้ำ
✅ แก้หนึ่งชิ้น: embed เฉพาะชิ้นใหม่ และลบชิ้นเก่าของมัน
✅ ลบบางส่วนออกจากเอกสาร: ชิ้นที่หายถูกลบ และไม่ต้อง embed อะไร
✅ ข้อความซ้ำในเอกสารเดียวกันเก็บแถวเดียว (และ embed ครั้งเดียว)
✅ หลายเอกสารไม่ปนกัน: การนำเข้าเอกสารหนึ่งไม่ลบของอีกเอกสาร
```

สิ่งที่ได้: นำเข้าเอกสารซ้ำได้อย่างถูกต้องและประหยัด

## ข้อควรจำ

- ถ้าเปลี่ยนโมเดลหรือจำนวนมิติของ embedding ต้องล้างและนำเข้าใหม่ทั้งหมด (id จากเนื้อหาไม่รู้ว่าโมเดลเปลี่ยน) จึงควรเก็บชื่อโมเดลไว้กับข้อมูล
- ทำเป็นธุรกรรมเมื่อใช้ฐานข้อมูลจริง เพื่อไม่ให้ค้างครึ่งทางเมื่อล้ม
