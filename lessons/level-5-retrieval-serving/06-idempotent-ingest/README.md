# บทที่ 5-06: นำเข้าเอกสารโดยไม่ซ้ำ (idempotent ingestion)

## แนวคิด
ระบบ RAG จริงต้องนำเข้าเอกสารซ้ำ ๆ: เอกสารถูกแก้ ลบบางส่วน หรือรันสคริปต์นำเข้าซ้ำ ถ้าแต่ละครั้ง "ลบทั้งหมดแล้ว embed ใหม่" จะเปลืองโควตา embedding และช้า ถ้า "เพิ่มอย่างเดียว" ข้อมูลจะซ้ำและเก่าค้าง

หลักคือ **idempotent** (รันกี่ครั้งผลเหมือนรันครั้งเดียว):
1. **ตั้ง id ของ chunk จากเนื้อหา** (`docId` + hash ของข้อความ) ข้อความเดิมได้ id เดิมเสมอ
2. **เทียบกับของที่มีอยู่:** id ที่ยังมีอยู่ = ไม่ต้องทำอะไร, id ใหม่ = ต้อง embed และเพิ่ม, id ที่เคยมีแต่ตอนนี้ไม่อยู่ในเอกสาร = ลบ
3. **embed เฉพาะที่เพิ่ม** (ประหยัดโควตา) แล้ว upsert

ผลที่ได้: รันซ้ำโดยไม่แก้เอกสาร = ไม่เรียก embedding เลย, แก้หนึ่งย่อหน้า = embed แค่ย่อหน้านั้นและลบอันเก่า

## ดูตัวอย่าง
`ingest.ts` มี interface ของตาราง (`Table`) ให้แล้ว (ของจริงคือตาราง pgvector จากบท 5-02) ขาด 3 ส่วน: การตั้ง id, การวางแผนเทียบ และฟังก์ชันนำเข้า

## คุณทำได้แล้ว
- นำเข้าเอกสารซ้ำได้อย่างถูกต้องและประหยัด

## ข้อควรจำ
- ถ้าเปลี่ยนโมเดลหรือจำนวนมิติของ embedding ต้องล้างและนำเข้าใหม่ทั้งหมด (id จากเนื้อหาไม่รู้ว่าโมเดลเปลี่ยน) จึงควรเก็บชื่อโมเดลไว้กับข้อมูล
- ทำเป็นธุรกรรมเมื่อใช้ฐานข้อมูลจริง เพื่อไม่ให้ค้างครึ่งทางเมื่อล้ม
