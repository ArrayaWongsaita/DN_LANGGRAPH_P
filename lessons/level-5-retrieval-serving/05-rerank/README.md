# บทที่ 5-05 จัดอันดับใหม่ด้วยโมเดล (rerank)

## แนวคิด

การค้นหาด้วยเวกเตอร์เร็วและกว้างแต่ไม่แม่นพอ: มันเทียบ "ภาพรวม" ของคำถามกับเอกสารที่ถูกแปลงเป็นเวกเตอร์ไปแล้วโดยไม่เห็นคำถาม แนวปฏิบัติที่นิยมคือ **สองขั้น**:

1. ดึงผู้สมัครมาเยอะ ๆ (เช่น 20 อัน) ด้วยการค้นหาที่เร็ว
2. ให้โมเดลที่ **อ่านคำถามคู่กับแต่ละเอกสาร** ให้คะแนนความเกี่ยวข้อง (0-10) แล้วเรียงใหม่ เก็บเฉพาะอันที่ผ่านเกณฑ์ และเอา `topN` อันดับแรกไปให้ขั้นตอบ

ขั้นที่ 2 แพงกว่า (เรียกโมเดล) จึงทำกับผู้สมัครกลุ่มเล็กเท่านั้น

สิ่งที่ต้องระวัง: **อย่าเชื่อเอาต์พุตของโมเดลโดยไม่ตรวจ** โมเดลอาจคืนคะแนนจำนวนไม่ตรงกับจำนวนเอกสาร ถ้าเป็นแบบนั้นให้ถอยกลับไปใช้ลำดับเดิมของการค้นหา (ดีกว่าจับคู่คะแนนผิดตัวแล้วเรียงมั่ว)

ส่วนตรวจใช้โมเดลปลอมที่ตอบ JSON `{ "scores": [...] }` ตามลำดับเอกสารที่ส่งไป

## 1. ลองเติมช่องเดียว

เปิด [`rerank.ts`](./rerank.ts) แล้วเติมข้อ 1: เติมส่วนหลักของบท (จัดอันดับใหม่ด้วยโมเดล (rerank)) รันจากโฟลเดอร์หลักของโปรเจกต์ บทนี้เรียกโมเดลจริง ตั้ง provider และ API key ใน `.env` ตาม [บท 1-02](../../level-1-basics/02-llm-config/README.md) ก่อนรัน

```sh
pnpm lesson 5-05
```

ในไฟล์ข้อ 1 มี **แนวทาง** เป็นโค้ดที่คอมเมนต์ไว้ เอา `//` ออกแล้วแทนที่ `todo(1)` ได้เลย แต่ลองอ่านก่อนว่าแต่ละบรรทัดทำอะไร

ในไฟล์มีส่วนอื่นของบทนี้เขียนไว้ให้แล้ว ขาดแค่ข้อ 1

โค้ดตามแนวทาง:

```ts
return candidates
  .map((candidate, index) => ({ candidate, index, score: result.scores[index] }))
  .filter((s) => s.score >= options.minScore)
  .sort((a, b) => b.score - a.score || a.index - b.index)
  .slice(0, options.topN)
  .map((s) => s.candidate);
```

## 2. ผลที่ได้

ตัวอย่างผลที่รันจากเฉลย ข้อความจากโมเดลเปลี่ยนได้ทุกรอบ

```text
โมเดลจริงเลือก: [ 'เรื่องรีเซ็ตรหัสผ่าน', 'เรื่องรหัสผ่านและ VPN' ]
✅ พรอมต์: มีคำถาม เอกสารเรียงหมายเลขตั้งแต่ 1 และบอกช่วงคะแนน
✅ เรียงใหม่ตามคะแนนมากไปน้อย และตัดตาม topN
✅ ตัดอันที่คะแนนต่ำกว่าเกณฑ์ (เท่ากับเกณฑ์ผ่าน)
✅ คะแนนเท่ากันคงลำดับเดิมของผู้สมัคร
✅ คะแนนจำนวนไม่ตรง: ถอยกลับไปลำดับเดิม ไม่กรอง ไม่เรียงใหม่ (ยังตัดตาม topN)
✅ ไม่มีผู้สมัคร: ไม่เรียกโมเดล
✅ โมเดลได้รับพรอมต์ที่สร้างจากฟังก์ชันของคุณ
✅ โมเดลจริง: เลือกเอกสารเรื่องรหัสผ่านและตัดเรื่องคืนเงิน/ลาป่วยออก
```

สิ่งที่ได้: ทำการค้นสองขั้นที่แม่นขึ้นและไม่พังเมื่อโมเดลตอบผิดรูป

## ข้อควรจำ

- ใช้ผู้สมัครไม่มากเกินไป (ค่าใช้จ่ายและความหน่วงเพิ่มตามจำนวน)
- วัดด้วย eval (บท 4-08) ว่า rerank ช่วยจริงกับข้อมูลของคุณก่อนเปิดใช้
