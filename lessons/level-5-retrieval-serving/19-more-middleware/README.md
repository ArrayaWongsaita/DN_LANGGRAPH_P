# บทที่ 5-19 middleware สำเร็จรูปเพิ่มเติม (tool selector, to-do list, tool emulator)

## แนวคิด

บท 3-28..3-30 และ 4-12..4-15 ใช้ middleware สำเร็จรูปไปหลายตัวแล้ว (summarization, HITL, retry/fallback, limits, PII, context editing) บทนี้เติม 3 ตัวที่ยังไม่เคยใช้ ซึ่งแก้ปัญหาต่างกัน:

**1. `llmToolSelectorMiddleware` — เมื่อมี tool เยอะ**
tool 30 ตัวแปลว่าพรอมต์ยาวและโมเดลสับสน middleware นี้เรียก "โมเดลคัดเลือก" ก่อน เพื่อเลือก tool ที่เกี่ยวกับคำถาม แล้วส่งให้โมเดลหลักแค่ชุดนั้น

```ts
llmToolSelectorMiddleware({ model: selectorLlm, maxTools: 2, alwaysInclude: ["search"] })
```
- `maxTools` จำกัดจำนวนที่เลือก (ไม่นับ `alwaysInclude`)
- `alwaysInclude` ใส่ tool ที่ต้องมีเสมอ
- **ราคาที่ต้องจ่าย:** เรียกโมเดลเพิ่มอีกหนึ่งครั้งต่อรอบ ควรใช้โมเดลเล็ก/ถูก และคุ้มเมื่อ tool เยอะจริง

**2. `todoListMiddleware` — งานยาวหลายขั้น**
เพิ่ม tool `write_todos` และฟิลด์ `todos` ใน state ให้โมเดลวางแผนและติ๊กความคืบหน้า (`pending` / `in_progress` / `completed`) ช่วยให้โมเดลไม่หลงทางในงานยาว และให้ UI แสดงแผนได้จาก `state.todos`

**3. `toolEmulatorMiddleware` — ทดสอบโดยไม่แตะของจริง**
แทนที่การรัน tool ที่ระบุด้วย **โมเดลที่แกล้งตอบ** (tool จริงไม่ถูกเรียกเลย) เหมาะกับทดสอบ agent ที่เรียก tool มีผลข้างเคียง (ส่งอีเมล ตัดเงิน) หรือยังไม่มีระบบจริง ไม่ควรเปิดใน production

ยังมี middleware ที่เป็น "เครื่องมือ" ให้ agent (เช่น tool สำหรับ shell และค้นไฟล์) ซึ่ง **มีความเสี่ยงสูง** (รันคำสั่งในเครื่อง) บทนี้ไม่ได้รัน ถ้าจะใช้ต้องมี sandbox และ human-in-the-loop (บท 2-18)

ส่วนที่ 1 ของสคริปต์ใช้ `createAgent` จริงกับโมเดลปลอม จึงเห็นพฤติกรรมจริงของ middleware (ชุด tool ที่โมเดลหลักเห็น, ค่า `todos`, tool จริงถูกเรียกกี่ครั้ง)

## 1. ลองเติมช่องเดียว

เปิด [`agents.ts`](./agents.ts) แล้วเติมข้อ 1: เติมส่วนหลักของบท (middleware สำเร็จรูปเพิ่มเติม (tool selector, to-do list, tool emulator)) รันจากโฟลเดอร์หลักของโปรเจกต์ บทนี้เรียกโมเดลจริง ตั้ง provider และ API key ใน `.env` ตาม [บท 1-02](../../level-1-basics/02-llm-config/README.md) ก่อนรัน

```sh
pnpm lesson 5-19
```

ในไฟล์ข้อ 1 มี **แนวทาง** เป็นโค้ดที่คอมเมนต์ไว้ เอา `//` ออกแล้วแทนที่ `todo(1)` ได้เลย แต่ลองอ่านก่อนว่าแต่ละบรรทัดทำอะไร

ในไฟล์มีส่วนอื่นของบทนี้เขียนไว้ให้แล้ว ขาดแค่ข้อ 1

โค้ดตามแนวทาง:

```ts
return createAgent({
  model,
  tools,
  middleware: [llmToolSelectorMiddleware({ model: selectorLlm as never, maxTools: 2, alwaysInclude: ["search"] })],
});
```

## 2. ผลที่ได้

ตัวอย่างผลที่รันจากเฉลย ข้อความจากโมเดลเปลี่ยนได้ทุกรอบ

```text
1. [กำลังทำ] ขั้นที่ 1 – เตรียมของ (Mise en place): ชั่งตวงวัตถุดิบ เตรียมอุปกรณ์ ปูรองพิมพ์ และวอร์มเตาอบไฟ 175°C
2. [รอ] ขั้นที่ 2 – ผสมและอบ: ผสมของแห้งกับของเปียก คนให้เข้ากัน เทใส่พิมพ์ อบ 30–35 นาที แล้วพักให้เย็น
3. [รอ] ขั้นที่ 3 – ทำช็อกโกแลตฟรอสติ้ง + ประกอบ: ตีฟรอสติ้ง ทาเคลือบเค้ก ตกแต่ง และพักให้เซ็ตตัว
✅ tool selector: โมเดลหลักเห็นเฉพาะ tool ที่คัดเลือก + alwaysInclude และตัวคัดเลือกถูกเรียกหนึ่งครั้ง
✅ tool selector: maxTools = 2 ตัดส่วนเกิน (alwaysInclude ไม่นับ)
✅ tool selector: ตัวคัดเลือกเห็นคำถามของผู้ใช้
✅ to-do list: มี tool write_todos และ state.todos ถูกอัปเดต
✅ tool emulator: tool ที่ระบุถูกจำลอง (ของจริงไม่ถูกเรียก) ส่วน tool อื่นรันจริง
✅ renderTodos: ป้ายสถานะและลำดับเลข
✅ renderTodos: ไม่มีแผน
✅ toolsToEmulate: จำลองทุก tool ที่ไม่ได้รับรองว่าอ่านอย่างเดียว (ปลอดภัยไว้ก่อน)
✅ toolsToEmulate: เทียบชื่อตรงเป๊ะ (ชื่อที่ขึ้นต้นเหมือนกันยังถูกจำลอง)
✅ โมเดลจริง: จดแผนด้วย write_todos ได้อย่างน้อย 1 งาน
```

สิ่งที่ได้: เลือก tool ให้โมเดลอัตโนมัติ ให้โมเดลวางแผนงานยาว และทดสอบ agent โดยไม่แตะระบบจริง

## ข้อควรจำ

- ตัวคัดเลือกอาจเลือกผิด: วัดด้วย eval (บท 4-08) ว่าคุ้มจริงกับ tool ชุดของคุณ
- ชื่อ tool ใน `alwaysInclude` / ที่จะจำลอง ต้องตรงชื่อจริง (สะกดผิดจะไม่เกิดผลเงียบ ๆ)
