# บทที่ 5-25 จัดการสถานะ UI จากสตรีม (ส่วนที่ไม่ผูกกับเฟรมเวิร์ก)

## แนวคิด

เอกสารส่วน Frontend ของ LangGraph/LangChain ใช้ hook เช่น `useStream` (แพ็กเกจ `@langchain/react`, `vue`, `svelte`, `angular`) ซึ่งต้องมี DOM และเฟรมเวิร์ก คอร์สนี้ไม่สร้างหน้าเว็บ แต่ **หัวใจของ UI สตรีมมิงคือตรรกะล้วน ๆ ที่ไม่ผูกกับเฟรมเวิร์ก** บทนี้ให้ฝึกตรงนั้น เพื่อให้เอาไปใช้กับ React/Vue/Svelte หรือ terminal UI ก็ได้:

1. **reducer ของสถานะ UI:** รับ event ทีละตัวจากสตรีม (บท 5-24 ส่ง `custom:node-status`, ของมาตรฐาน `lifecycle`/`values`) แล้วคืนสถานะ UI ใหม่ **โดยไม่แก้ของเดิม** (React/Vue ตรวจการเปลี่ยนแปลงจากการเทียบอ้างอิง) event ที่ไม่เกี่ยวต้องคืน **อ็อบเจ็กต์เดิม** เพื่อไม่ให้เรนเดอร์ซ้ำโดยเปล่าประโยชน์
2. **แถบความคืบหน้าสำหรับ graph แบบไดนามิก:** node ที่ไม่ได้รัน (ถูกข้าม) จะไม่โผล่ในสตรีมเลย จึงห้ามเขียนรายชื่อ node ตายตัวใน UI และ % ต้องคิดจากจำนวนที่คาดไว้ ไม่ใช่จากจำนวนที่เห็นแล้ว
3. **markdown ที่มาไม่ครบ:** ข้อความที่สตรีมมาเป็นท่อน ๆ อาจค้างอยู่กลางโค้ดบล็อกหรือตัวหนา ถ้าส่งเข้าตัวเรนเดอร์ดิบ ๆ หน้าจอจะกะพริบหรือพัง ต้อง "ปิด" โครงสร้างที่ค้างก่อนเรนเดอร์ (เฉพาะตอนแสดงผล ไม่แก้ข้อความจริงที่เก็บไว้)

หมายเหตุจากเอกสาร: ห้ามสมมติว่าชื่อ node เท่ากับชื่อฟิลด์ใน state (บท 5-22) ค่าสุดท้ายอ่านจาก `values` ตามชื่อฟิลด์จริง

## 1. ลองเติมช่องเดียว

เปิด [`ui.ts`](./ui.ts) แล้วเติมข้อ 1: เติมส่วนหลักของบท (จัดการสถานะ UI จากสตรีม (ส่วนที่ไม่ผูกกับเฟรมเวิร์ก)) รันจากโฟลเดอร์หลักของโปรเจกต์ บทนี้ไม่เรียกโมเดลจริง รันได้โดยไม่ต้องมี API key

```sh
pnpm lesson 5-25
```

ในไฟล์ข้อ 1 มี **แนวทาง** เป็นโค้ดที่คอมเมนต์ไว้ เอา `//` ออกแล้วแทนที่ `todo(1)` ได้เลย แต่ลองอ่านก่อนว่าแต่ละบรรทัดทำอะไร

`ui.ts` มีชนิดข้อมูลและ `initialUi` ให้แล้ว ส่วนอื่นของบทนี้เขียนไว้ให้แล้ว ขาดแค่ข้อ 1

โค้ดตามแนวทาง:

```ts
const total = Math.max(1, expectedTotal);
const done = nodes.filter((n) => n.status === "complete").length;
return Math.min(100, Math.round((done / total) * 100));
```

## 2. ผลที่ได้

ผลที่รันจากเฉลย

```text
lifecycle            → กำลังทำงาน 0%  []  0%
custom:node-status   → กำลังทำงาน 0% (plan)  [plan:running]  0%
custom:node-status   → กำลังทำงาน 33%  [plan:complete]  33%
custom:node-status   → กำลังทำงาน 33% (work)  [plan:complete work:running]  33%
custom:node-status   → กำลังทำงาน 33%  [plan:complete work:error]  33%
lifecycle            → ล้มเหลว: boom  [plan:complete work:error]  33%

markdown ที่ค้าง: "ขั้นตอน **สำคัญ ใช้ `npm i" → "ขั้นตอน **สำคัญ ใช้ `npm i**`"
สตรีมจริง: เสร็จแล้ว {"text":"B"}
✅ lifecycle ของ graph หลักกำหนดสถานะรวม (รันใหม่ล้าง error เก่า)
✅ event ของ subgraph (namespace ไม่ว่าง) ไม่เปลี่ยนสถานะรวมและ values
✅ values เก็บค่าล่าสุดทั้งก้อน (คีย์ที่หายไปในก้อนใหม่หายด้วย)
✅ node-status: ต่อท้ายตามลำดับที่เห็น แทนที่ตำแหน่งเดิมเมื่อสถานะเปลี่ยน
✅ node-status: เก็บข้อความ error ข้ามข้อมูลผิดรูป และสถานะใหม่ล้าง error เก่า
✅ reducer ไม่แก้ state เดิม (immutable) และ event ที่ไม่เกี่ยวคืนอ็อบเจ็กต์เดิม
✅ progressPercent: คิดจาก node ที่เสร็จ / จำนวนที่คาดไว้ ปัดใกล้สุด ไม่เกิน 100
✅ closeMarkdown: โค้ดบล็อกที่ค้างถูกปิดโดยไม่แตะเรื่องอื่นในบล็อก
✅ closeMarkdown: ตัวหนาและโค้ดบรรทัดเดียวที่ค้างถูกปิด
✅ closeMarkdown: ข้อความที่ครบแล้วคืนเหมือนเดิมทุกตัวอักษร
✅ headline: แต่ละสถานะ
✅ ต่อกับสตรีมจริงของ LangGraph: UI จบที่ complete พร้อม values และสถานะ node ครบ
```

สิ่งที่ได้: เขียนตรรกะสถานะ UI สตรีมมิงที่ใช้ซ้ำได้ทุกเฟรมเวิร์ก

## ข้อควรจำ

- event อาจมาซ้ำหรือเกินลำดับเมื่อเชื่อมต่อใหม่ ตัวลดรูปควรทนต่อการเล่นซ้ำ (idempotent เท่าที่ทำได้)
- ถ้า event ถี่มาก ให้รวมการอัปเดตก่อนเรนเดอร์ (เช่นทุกเฟรมภาพ) ตรรกะข้างในไม่ต้องเปลี่ยน
