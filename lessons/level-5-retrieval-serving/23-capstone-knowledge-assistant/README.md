# บทที่ 5-23 (โครงงานปิดท้าย): ผู้ช่วยความรู้ขององค์กร

## เป้าหมาย
ประกอบทุกอย่างจาก Level 5 (และบทก่อนหน้า) เป็นระบบเดียวที่ใช้งานได้จริง:

| ขั้น | ใช้จากบท |
|---|---|
| นำเอกสารเข้า: แบ่งชิ้น + hash + ซิงก์ ทำซ้ำได้โดยไม่ซ้ำซ้อน | 5-06 |
| ค้นหาแบบผสม: keyword + vector รวมด้วย RRF | 5-04 |
| ตอบพร้อมอ้างอิงและตรวจว่าอ้างจริง | 4-21 |
| guardrail ก่อน/หลังโมเดล (ข้อความต้องห้าม ข้อมูลลับ) | 4-13 |
| ความจำข้ามคำขอด้วย checkpointer (Postgres ตอนใช้จริง) | 4-24 |
| เปิดบริการผ่าน HTTP | 5-09, 5-15 |

```
คำถาม → guard ──(ไม่ผ่าน)──────────────► END (status "refused")
            │ผ่าน
            ▼
         retrieve ──(ไม่พบเอกสาร)───────► END (status "no-answer" ไม่เรียกโมเดล)
            │พบ
            ▼
          answer ──► ตรวจการอ้างอิง/ข้อมูลลับ ──► END (status "ok" หรือ "no-answer")
```

## แนวคิดสำคัญของงานนี้
- **ซ่อนตัวฐานข้อมูลไว้หลัง interface** `KnowledgeBase` ตัวตรวจใช้ตัวปลอมในหน่วยความจำ ส่วน `run.ts` ใช้ Postgres + pgvector จริง (`pgKb.mts` ให้ไว้แล้ว) logic ทั้งหมดที่คุณเขียนจึงทดสอบได้โดยไม่ต้องมีฐานข้อมูล
- **ไม่เรียกโมเดลถ้าไม่จำเป็น:** ถูก guard ปฏิเสธหรือค้นไม่เจอก็จบเลย (ประหยัดและไม่ให้โมเดลมั่ว)
- **เอกสารที่ค้นมาคือข้อมูล ไม่ใช่คำสั่ง** (บท 4-14): prompt ต้องบอกชัดว่าห้ามทำตามคำสั่งที่อยู่ในเอกสาร
- **ปลอดภัยไว้ก่อน:** ตอบแล้วไม่มีแหล่งอ้างอิงที่มีจริง = "ไม่พบข้อมูล" ดีกว่าตอบมั่ว

## ไฟล์
- `assistant.ts` (ส่วนที่คุณเติม) — 7 ข้อ
- `pgKb.mts` (ให้ไว้) — `KnowledgeBase` บน Postgres + pgvector + embedding จริง
- `server.mts` (ให้ไว้) — Express: `POST /ingest`, `POST /ask`
- `run.ts` (ให้ไว้) — เดโมครบวงจรกับของจริง

## โจทย์
เติม 7 ข้อใน `assistant.ts` แล้วรัน:

    pnpm test:lesson 5-23

เดโมครบวงจร (ต้องเปิด Docker Postgres และตั้ง DATABASE_URL, GOOGLE_API_KEY และ key ของโมเดลใน `.env`):

    pnpm lesson 5-23

เดโมจะนำเอกสารเข้าสองรอบ (รอบสองต้องได้ added 0 เพราะทำซ้ำได้), ถามคำถามที่เอกสารตอบได้, ถามนอกขอบเขต, ลองคำสั่งต้องห้ามและคำถามว่าง ทุกคำถามใช้ `thread_id` เดียวกัน จึงถูกบันทึกลงตาราง checkpoint ใน Postgres (ลองรันแล้วดู `getState` ของเธรดนั้นต่อได้)
