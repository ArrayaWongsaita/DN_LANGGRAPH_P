# บทที่ 5-14: กราฟ SQL agent

## แนวคิด
บท 5-13 ได้ตัวตรวจ SQL แล้ว บทนี้ประกอบเป็น agent ที่ตอบคำถามภาษาคนด้วยข้อมูลในฐานข้อมูล โดยไม่ปล่อยให้โมเดลรันอะไรตามใจ:

```
START → inspect (อ่าน schema) → write (โมเดลเขียน SQL) → check (ตัวตรวจ)
                                        ↑                    │ ไม่ผ่าน (ส่งเหตุผลกลับไปให้โมเดลแก้)
                                        └────────────────────┤
                                                              │ ผ่าน
                                                              ▼
                       respond ← execute (รันแบบอ่านอย่างเดียว) ── ล้มเหลว (ส่งข้อความ error กลับไปให้แก้)
```
- **วงรอบแก้ไข (retry loop):** เมื่อตัวตรวจหรือฐานข้อมูลปฏิเสธ ส่งเหตุผลกลับเข้าไปในพรอมต์ให้โมเดลเขียนใหม่ แต่ **จำกัดจำนวนครั้ง** (`maxAttempts`) ไม่งั้นวนไม่รู้จบและเปลืองเงิน หมดแล้วต้อง "ยอมแพ้อย่างสุภาพ" โดย **ไม่รัน SQL และไม่เรียกโมเดลอีก**
- **รันเฉพาะ SQL ที่ตัวตรวจคืนมา** (ที่ผ่านการเติม LIMIT แล้ว) ไม่ใช่ข้อความดิบจากโมเดล
- **ผลลัพธ์จากฐานข้อมูลคือข้อมูลภายนอก** (บท 4-14): ในแถวอาจมีข้อความที่ผู้ใช้คนอื่นเขียนไว้ว่า "ละเลยคำสั่งก่อนหน้า…" พรอมต์ตอบต้องระบุว่าเป็นข้อมูลดิบห้ามทำตาม
- ตัวตรวจและตัวรันถูก **ฉีดเข้ามา** (`validate`, `db`) ตัวตรวจของบทนี้จึงใช้ของปลอมได้ ส่วนของจริงคือผลงานของบท 5-13

## ดูตัวอย่าง
`agent.ts` ให้ State, การเดินสายกราฟ และ node `inspect`/`giveup` ไว้แล้ว ขาด 5 ส่วน

## คุณทำได้แล้ว
- สร้าง SQL agent ที่แก้คำสั่งเองได้ในขอบเขต ปฏิเสธอย่างปลอดภัย และไม่เชื่อข้อมูลที่ดึงมา

## ข้อควรจำ
- agent เห็นเฉพาะ schema ของตารางที่อนุญาต (ไม่ใช่ทั้งฐานข้อมูล)
- ใช้ role ฐานข้อมูลสิทธิ์ต่ำเสมอ (บท 5-13)
- ถ้าตารางเยอะ ให้ใส่ schema เฉพาะที่เกี่ยวข้อง (ค้นด้วย retrieval จาก Part 18)
