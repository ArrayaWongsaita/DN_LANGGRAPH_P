# บทที่ 5-09 ส่งความคืบหน้าผ่าน HTTP ด้วย Express (SSE)

## แนวคิด

หน้าเว็บรับความคืบหน้าจากเซิร์ฟเวอร์ได้ด้วย **Server-Sent Events (SSE)**: การตอบ HTTP ที่ไม่ปิด เซิร์ฟเวอร์ทยอยเขียนข้อความตามรูปแบบมาตรฐาน ฝั่งเบราว์เซอร์ใช้ `EventSource` อ่านได้เลย รูปแบบของแต่ละข้อความ:

    id: 7                 (ไม่บังคับ)
    event: token          (ชื่อเหตุการณ์ ไม่บังคับ)
    data: {"text":"ส"}    (ข้อมูล: ถ้ามีหลายบรรทัดต้องขึ้น data: ทุกบรรทัด)
    (บรรทัดว่าง = จบหนึ่งข้อความ)

และต้องส่งหัว `Content-Type: text/event-stream`

สิ่งที่ผิดบ่อยในของจริง และบทนี้จัดการให้ในโค้ด:
1. **เมื่อผู้ใช้ปิดแท็บ** ต้องหยุดอ่านท่อต้นทาง (และยกเลิกการรันกราฟ) ไม่งั้นโมเดลยังทำงานและเสียเงินต่อ (ส่ง `signal` ตัวเดียวกันให้ `streamEvents(input, { version: "v3", signal })` ทดลองแล้ว: ยกเลิกกลางทาง node ถัดไปไม่ถูกรัน และการวนอ่าน throw `This operation was aborted`)
2. **ต้องปิดการตอบเสมอ** (`end()`) แม้เกิดข้อผิดพลาด และแจ้งข้อผิดพลาดเป็นเหตุการณ์ `error` ไม่ใช่ปล่อยให้เชื่อมต่อค้าง
3. หัว `Cache-Control: no-cache, no-transform` กันตัวกลาง (proxy) เก็บหรือบีบอัดจนข้อความมาเป็นก้อน

ส่วนที่ผูกกับ Express ในไฟล์เดียวกันให้ไว้แล้ว: route `GET /ask?q=...` สร้าง `AbortController`, ผูก `res.on("close")` ให้ยกเลิก แล้วเรียกฟังก์ชันของคุณ ส่วนตรวจใช้ sink ปลอมไม่เปิดพอร์ต ส่วนที่รันจริงเปิดเซิร์ฟเวอร์ชั่วคราวและเรียกตัวเอง

## 1. ลองเติมช่องเดียว

เปิด [`sse.ts`](./sse.ts) แล้วเติมข้อ 1: เติมส่วนหลักของบท (ส่งความคืบหน้าผ่าน HTTP ด้วย Express (SSE)) รันจากโฟลเดอร์หลักของโปรเจกต์ บทนี้เรียกโมเดลจริง ตั้ง provider และ API key ใน `.env` ตาม [บท 1-02](../../level-1-basics/02-llm-config/README.md) ก่อนรัน

```sh
pnpm lesson 5-09
```

ในไฟล์ข้อ 1 มี **แนวทาง** เป็นโค้ดที่คอมเมนต์ไว้ เอา `//` ออกแล้วแทนที่ `todo(1)` ได้เลย แต่ลองอ่านก่อนว่าแต่ละบรรทัดทำอะไร

ในไฟล์มีส่วนอื่นของบทนี้เขียนไว้ให้แล้ว ขาดแค่ข้อ 1

โค้ดตามแนวทาง:

```ts
let out = "";
if (message.id !== undefined) out += `id: ${message.id}\n`;
if (message.event) out += `event: ${message.event}\n`;
const lines = typeof message.data === "string" ? message.data.split("\n") : [JSON.stringify(message.data)];
for (const line of lines) out += `data: ${line}\n`;
return `${out}\n`;
```

## 2. ผลที่ได้

ตัวอย่างผลที่รันจากเฉลย ข้อความจากโมเดลเปลี่ยนได้ทุกรอบ

```text
event: token
data: {"type":"token","text":"สวัสดี"}

event: done
data: {"type":"done"}


✅ formatSse: event + data เป็น JSON จบด้วยบรรทัดว่าง
✅ formatSse: id มาก่อน event และไม่มี event ก็ได้
✅ formatSse: ข้อความหลายบรรทัดต้องขึ้น data: ทุกบรรทัด
✅ formatSse: ออบเจ็กต์ที่มีขึ้นบรรทัดใหม่ในค่า JSON escape ให้ ข้อความไม่แตก
✅ sseHeaders: ชนิดสื่อและกัน cache/บีบอัดของตัวกลาง
✅ streamToSink: เขียนทุกรายการเป็นเหตุการณ์ตามชนิด แล้วปิดครั้งเดียว
✅ ผู้ใช้ปิดแท็บ: หยุดเขียนและหยุดท่อต้นทาง แล้วปิด sink
✅ ต้นทางล้ม: ส่งเหตุการณ์ error ปิด sink ไม่ throw ออกมา
✅ ยกเลิกแล้วต้นทางล้ม: ไม่เขียน error เพิ่ม แต่ยังปิด sink
✅ ยกเลิกก่อนเริ่ม: ไม่เขียนอะไรเลย
✅ เซิร์ฟเวอร์จริง: ได้ text/event-stream และข้อความ SSE ครบ
✅ เซิร์ฟเวอร์จริง: ไม่มี q ได้ 400
✅ เซิร์ฟเวอร์จริง: ลูกค้าตัดการเชื่อมต่อแล้วต้นทางหยุดเอง
✅ เอเจนต์จริงผ่าน SSE: มีเหตุการณ์ token และ done และเรียก tool add
```

สิ่งที่ได้: ส่งความคืบหน้าแบบสตรีมผ่าน HTTP ที่หยุดงานได้เมื่อผู้ใช้ปิดหน้า

## ข้อควรจำ

- ของจริงต้องมีการยืนยันตัวตนและจำกัดอัตราก่อนเปิดสาธารณะ (บท 4-13 ให้แนวคิดเรื่อง guardrail)
- ถ้า `write` คืน false ฝั่งรับช้า ควรรอ event `drain` (ที่นี่ตัดทิ้งเพื่อความง่าย)
- เบราว์เซอร์ `EventSource` ใช้ได้เฉพาะ GET ถ้าต้อง POST ให้ใช้ `fetch` อ่านสตรีมแทน
