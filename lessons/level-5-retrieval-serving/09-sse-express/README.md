# บทที่ 5-09: ส่งความคืบหน้าผ่าน HTTP ด้วย Express (SSE)

## แนวคิด
หน้าเว็บรับความคืบหน้าจากเซิร์ฟเวอร์ได้ด้วย **Server-Sent Events (SSE)**: การตอบ HTTP ที่ไม่ปิด เซิร์ฟเวอร์ทยอยเขียนข้อความตามรูปแบบมาตรฐาน ฝั่งเบราว์เซอร์ใช้ `EventSource` อ่านได้เลย รูปแบบของแต่ละข้อความ:

    id: 7                 (ไม่บังคับ)
    event: token          (ชื่อเหตุการณ์ ไม่บังคับ)
    data: {"text":"ส"}    (ข้อมูล: ถ้ามีหลายบรรทัดต้องขึ้น data: ทุกบรรทัด)
    (บรรทัดว่าง = จบหนึ่งข้อความ)

และต้องส่งหัว `Content-Type: text/event-stream`

สิ่งที่ผิดบ่อยในของจริง และบทนี้ให้คุณจัดการ:
1. **เมื่อผู้ใช้ปิดแท็บ** ต้องหยุดอ่านท่อต้นทาง (และยกเลิกการรันกราฟ) ไม่งั้นโมเดลยังทำงานและเสียเงินต่อ (ส่ง `signal` ตัวเดียวกันให้ `streamEvents(input, { version: "v3", signal })` ทดลองแล้ว: ยกเลิกกลางทาง node ถัดไปไม่ถูกรัน และการวนอ่าน throw `This operation was aborted`)
2. **ต้องปิดการตอบเสมอ** (`end()`) แม้เกิดข้อผิดพลาด และแจ้งข้อผิดพลาดเป็นเหตุการณ์ `error` ไม่ใช่ปล่อยให้เชื่อมต่อค้าง
3. หัว `Cache-Control: no-cache, no-transform` กันตัวกลาง (proxy) เก็บหรือบีบอัดจนข้อความมาเป็นก้อน

ส่วนที่ผูกกับ Express (`server.mts`) ให้ไว้แล้ว: route `GET /ask?q=...` สร้าง `AbortController`, ผูก `res.on("close")` ให้ยกเลิก แล้วเรียกฟังก์ชันของคุณ ตัวตรวจไม่เปิดพอร์ต ใช้ sink ปลอม ส่วน `pnpm lesson 5-09` เปิดเซิร์ฟเวอร์จริงชั่วคราวและเรียกตัวเอง

## ดูตัวอย่าง
`sse.ts` ขาด 3 ส่วน: การจัดรูปแบบข้อความ, หัว HTTP และการเขียนท่อลง sink

## คุณทำได้แล้ว
- ส่งความคืบหน้าแบบสตรีมผ่าน HTTP ที่หยุดงานได้เมื่อผู้ใช้ปิดหน้า

## ข้อควรจำ
- ของจริงต้องมีการยืนยันตัวตนและจำกัดอัตราก่อนเปิดสาธารณะ (บท 4-13 ให้แนวคิดเรื่อง guardrail)
- ถ้า `write` คืน false ฝั่งรับช้า ควรรอ event `drain` (ที่นี่ตัดทิ้งเพื่อความง่าย)
- เบราว์เซอร์ `EventSource` ใช้ได้เฉพาะ GET ถ้าต้อง POST ให้ใช้ `fetch` อ่านสตรีมแทน
