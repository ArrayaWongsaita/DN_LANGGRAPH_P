# บทที่ 5-03: ความจำระยะยาวที่ค้นด้วยความหมาย

## แนวคิด
ในบท 3-10..3-12 คุณเก็บความจำใน store แล้วดึงด้วยคีย์หรือ namespace ตอนนี้เพิ่ม **ดัชนีเวกเตอร์** เข้าไปที่ store ทำให้ค้นด้วย "ความหมาย" ได้: ผู้ใช้เคยบอกว่า "ฉันแพ้ถั่ว" แล้วภายหลังถามว่า "แนะนำของหวานหน่อย" ระบบดึงความจำเรื่องแพ้ถั่วมาประกอบการตอบได้ แม้ไม่มีคำซ้ำกัน

```ts
const store = new InMemoryStore({ index: { dims: 768, embeddings, fields: ["text"] } });
// ของจริงบน Postgres:
// PostgresStore.fromConnString(url, { index: { dims: 768, embed: embeddings, fields: ["text"] } })
await store.put(["user-1", "memories"], key, { text: "แพ้ถั่ว" });
const hits = await store.search(["user-1", "memories"], { query: "ของหวาน", limit: 3 });
// hits[i].value.text, hits[i].score  (ยิ่งมากยิ่งคล้าย)
```
- `fields` บอกว่าฟิลด์ไหนของเอกสารถูก embed
- **namespace แยกผู้ใช้** เป็นเรื่องความเป็นส่วนตัว: ความจำของคนหนึ่งต้องไม่โผล่ให้อีกคน
- ตั้ง **คะแนนขั้นต่ำ** ไม่งั้นระบบจะดึงความจำที่ไม่เกี่ยวมาเสมอ (ค้นหาเวกเตอร์คืน "ที่ใกล้ที่สุด" ไม่ใช่ "ที่เกี่ยวข้อง")
- **เกณฑ์ต้องตั้งจากข้อมูลจริง** embedding จริงให้คะแนนอยู่ในช่วงแคบ: ตอนทดลอง `run.ts` ที่เขียนบทนี้ คำถามที่เกี่ยวข้องได้ประมาณ 0.62-0.64 ส่วนที่ไม่เกี่ยวได้ประมาณ 0.5-0.58 เกณฑ์ 0.3 ในตัวตรวจใช้ได้กับ embedding ปลอมเท่านั้น (บนของจริงมันไม่กรองอะไรเลย) รัน `pnpm lesson 5-03` ดูคะแนนจริงแล้วเลือกเกณฑ์ให้เหมาะกับโมเดลและข้อมูลของคุณ

## ดูตัวอย่าง
`memory.ts` มีบอทที่เรียกใช้ความจำให้แล้ว ขาด 3 ส่วน: namespace ของผู้ใช้, การจำ และการระลึก

## คุณทำได้แล้ว
- ทำความจำระยะยาวที่ระลึกตามความหมาย แยกตามผู้ใช้ และไม่ดึงของที่ไม่เกี่ยว

## ข้อควรจำ
- ความจำคือข้อมูลส่วนบุคคล ต้องมีวิธีลบตามคำขอของผู้ใช้
- ข้อความที่ระลึกมาเป็น "ข้อมูลภายนอก" อาจมีคำสั่งแอบแฝง (บท 4-14)
