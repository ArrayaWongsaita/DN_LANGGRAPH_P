# บทที่ 5-03 ความจำระยะยาวที่ค้นด้วยความหมาย

## แนวคิด

ในบท 3-10..3-12 คุณเก็บความจำใน store แล้วดึงด้วยคีย์หรือ namespace ตอนนี้เพิ่ม **ดัชนีเวกเตอร์** เข้าไปที่ store ทำให้ค้นด้วย "ความหมาย" ได้: ผู้ใช้เคยบอกว่า "ฉันแพ้ถั่ว" แล้วภายหลังถามว่า "แนะนำของหวานหน่อย" ระบบดึงความจำเรื่องแพ้ถั่วมาประกอบการตอบได้ แม้ไม่มีคำซ้ำกัน

```ts
const store = new InMemoryStore({ index: { dims: 768, embeddings, fields: ["text"] } });
// ของจริงบน Postgres:
// PostgresStore.fromConnString(url, { index: { dims: 768, embed: embeddings, fields: ["text"] } })
await store.put(["user-1", "memories"], key, { text: "แพ้ถั่ว" });
const hits = await store.search(["user-1", "memories"], { query: "ของหวาน", limit: 3 });
// hits[i].value.text, hits[i].score  (ยิ่งมากยิ่งคล้าย)
```
- `fields` บอกว่าฟิลด์ไหนของเอกสารถูก embed
- **namespace แยกผู้ใช้** เป็นเรื่องความเป็นส่วนตัว: ความจำของคนหนึ่งต้องไม่โผล่ให้อีกคน
- ตั้ง **คะแนนขั้นต่ำ** ไม่งั้นระบบจะดึงความจำที่ไม่เกี่ยวมาเสมอ (ค้นหาเวกเตอร์คืน "ที่ใกล้ที่สุด" ไม่ใช่ "ที่เกี่ยวข้อง")
- **เกณฑ์ต้องตั้งจากข้อมูลจริง** embedding จริงให้คะแนนอยู่ในช่วงแคบ: ตอนทดลองเขียนบทนี้ คำถามที่เกี่ยวข้องได้ประมาณ 0.62-0.64 ส่วนที่ไม่เกี่ยวได้ประมาณ 0.5-0.58 เกณฑ์ 0.3 ในส่วนตรวจที่ใช้ embedding ปลอมใช้ได้กับ embedding ปลอมเท่านั้น (บนของจริงมันไม่กรองอะไรเลย) รัน `pnpm lesson 5-03` ดูคะแนนจริงแล้วเลือกเกณฑ์ให้เหมาะกับโมเดลและข้อมูลของคุณ

## 1. ลองเติมช่องเดียว

เปิด [`memory.ts`](./memory.ts) แล้วเติมข้อ 1: เติมส่วนหลักของบท (ความจำระยะยาวที่ค้นด้วยความหมาย) รันจากโฟลเดอร์หลักของโปรเจกต์ บทนี้ใช้ Postgres: เปิดฐานข้อมูลด้วย `docker compose up -d --wait` และตั้ง `DATABASE_URL` ใน `.env` ก่อนรัน

```sh
pnpm lesson 5-03
```

ในไฟล์ข้อ 1 มี **แนวทาง** เป็นโค้ดที่คอมเมนต์ไว้ เอา `//` ออกแล้วแทนที่ `todo(1)` ได้เลย แต่ลองอ่านก่อนว่าแต่ละบรรทัดทำอะไร

`memory.ts` มีบอทที่เรียกใช้ความจำให้แล้ว ส่วนอื่นของบทนี้เขียนไว้ให้แล้ว ขาดแค่ข้อ 1

โค้ดตามแนวทาง:

```ts
const hits = await store.search(memoryNamespace(userId), { query, limit: k });
return hits.filter((h) => (h.score ?? 0) >= minScore).map((h) => String(h.value.text));
```

## 2. ผลที่ได้

ตัวอย่างผลที่รันจากเฉลย ข้อความจากโมเดลเปลี่ยนได้ทุกรอบ

```text
ถาม: แนะนำของหวานหน่อย
  0.622 ผู้ใช้แพ้ถั่วและอาหารทะเล
  0.578 ผู้ใช้ชอบเดินทางด้วยรถไฟ
  0.577 ผู้ใช้ทำงานเป็นพยาบาล

ถาม: จะไปเชียงใหม่ยังไงดี
  0.639 ผู้ใช้ชอบเดินทางด้วยรถไฟ
  0.551 ผู้ใช้ทำงานเป็นพยาบาล
  0.545 ผู้ใช้แพ้ถั่วและอาหารทะเล

ถาม: วันนี้หุ้นขึ้นหรือลง
  0.555 ผู้ใช้ทำงานเป็นพยาบาล
  0.526 ผู้ใช้ชอบเดินทางด้วยรถไฟ
  0.508 ผู้ใช้แพ้ถั่วและอาหารทะเล
✅ memoryNamespace: แยกตามผู้ใช้
✅ remember: เก็บ { text } ใต้ namespace ของผู้ใช้ และคืน key ที่ใช้ดึงกลับได้
✅ recall: ได้ข้อความที่เกี่ยวที่สุดก่อน
✅ recall: ตัดอันที่คะแนนต่ำกว่าเกณฑ์ ไม่ดึงของที่ไม่เกี่ยวมา
✅ recall: จำกัดจำนวนด้วย k
✅ ความเป็นส่วนตัว: ความจำของผู้ใช้หนึ่งไม่โผล่ให้อีกคน
✅ บอท: ความจำที่เกี่ยวถูกใส่ในพรอมต์ ส่วนของคนอื่นไม่ถูกใส่
✅ Postgres จริง: ถามหาของหวานเจอความจำเรื่องแพ้อาหาร ถามเที่ยวเจอเรื่องรถไฟ
```

สิ่งที่ได้: ทำความจำระยะยาวที่ระลึกตามความหมาย แยกตามผู้ใช้ และไม่ดึงของที่ไม่เกี่ยว

## ข้อควรจำ

- ความจำคือข้อมูลส่วนบุคคล ต้องมีวิธีลบตามคำขอของผู้ใช้
- ข้อความที่ระลึกมาเป็น "ข้อมูลภายนอก" อาจมีคำสั่งแอบแฝง (บท 4-14)
