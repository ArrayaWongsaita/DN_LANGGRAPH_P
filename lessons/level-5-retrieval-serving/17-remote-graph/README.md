# บทที่ 5-17: เรียกกราฟบนเซิร์ฟเวอร์เป็น node ด้วย RemoteGraph

## แนวคิด
`RemoteGraph` ทำให้กราฟที่รันบนเซิร์ฟเวอร์อื่น (เช่น `langgraph dev` หรือ deployment) ใช้งานเหมือนกราฟในเครื่อง: `invoke`/`stream` ได้ และ **ใส่เป็น node ใน StateGraph อื่นได้** เหมาะกับการแยกทีมหรือแยกบริการ (กราฟ "ค้นความรู้" อยู่บริการหนึ่ง กราฟ "ผู้ช่วย" เรียกมัน)

```ts
import { RemoteGraph } from "@langchain/langgraph/remote";
const remote = new RemoteGraph({ graphId: "demo", url: "http://localhost:2024" /* หรือ client: new Client(...) */ });
await remote.invoke({ question: "สวัสดี" }, { configurable: { thread_id: "remote-abc" } });
```
สิ่งที่สังเกตจากการรันจริง และเป็นจุดอันตรายของการใส่ `RemoteGraph` เป็น node ตรง ๆ:
- **มันส่ง state ทั้งก้อนของกราฟแม่ไปให้ปลายทาง** (ทุกฟิลด์ รวมที่ไม่เกี่ยวหรือเป็นความลับ) และรับ state ปลายทางกลับมา merge เข้ากราฟแม่
- ปลายทางล้ม (503, เครือข่ายหลุด) → ข้อผิดพลาดพากราฟแม่ล้มด้วย
- `thread_id` ใน config คือ thread **ฝั่งปลายทาง** (ถ้าใช้ของกราฟแม่ตรง ๆ จะชนกัน/รั่วข้ามผู้ใช้) และ **ต้องเป็น UUID** เซิร์ฟเวอร์ตอบ `HTTP 400 Invalid uuid` ถ้าส่ง `remote-abc` (เจอตอนรันจริง ที่ซ่อนอยู่หลัง fallback จนเกือบไม่เห็น: จึงต้องบันทึก `error` ไว้ใน state และดูมัน)

จึงควรห่อด้วย **node ตัวแปลง (adapter)**: ส่งเฉพาะฟิลด์ที่จำเป็น, ตั้ง thread ฝั่งปลายทางเอง (อิงจาก thread ของแม่), ตรวจรูปแบบคำตอบ และถ้าล้มให้ถอยกลับ (fallback) อย่างสุภาพ

สคริปต์ทดลองสองแบบ: เปิดเซิร์ฟเวอร์ `langgraph dev` จริงให้ `RemoteGraph` เรียก (ส่วนที่ 1) และป้อน `RemoteGraph` ด้วย client ปลอมที่หน้าตาเหมือน SDK (ส่วนที่ 2 ไม่ต้องใช้เครือข่าย)

## คุณทำได้แล้ว
- เรียกกราฟระยะไกลจากกราฟในเครื่องโดยไม่รั่ว state ไม่ชน thread และไม่ล้มตามปลายทาง

## ข้อควรจำ
- สัญญา (schema) ระหว่างสองกราฟคือ API: เปลี่ยนฝั่งหนึ่งต้องคุยกัน
- ใส่ timeout/retry ที่ชั้นเรียก และบันทึกข้อผิดพลาดปลายทางไว้ใน state (`error`) เพื่อตรวจสอบ
- ส่งผู้ใช้/สิทธิ์ไปปลายทางผ่าน `headers` หรือ config ไม่ใช่ปนใน state

## ลองเล่นต่อ
อยากทดลองเองโดยไม่มีส่วนตรวจคำตอบ: `pnpm play 5-17` จะรันไฟล์ `playground.ts` ในโฟลเดอร์บทนี้ (สร้างให้แล้ว มีแต่ import ที่ใช้ เขียนโค้ดต่อเองได้เลย) ในหัวไฟล์มีไอเดียให้ลองทำ ใช้ `--watch` ให้รันซ้ำทุกครั้งที่บันทึก และ `--reset` เพื่อเริ่มใหม่
