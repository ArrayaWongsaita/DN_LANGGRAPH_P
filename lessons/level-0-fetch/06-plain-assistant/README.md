# บทที่ 0-06: ผู้ช่วยด้วย if / while ล้วน ๆ (ก่อนจะมี LangGraph)

## แนวคิด
บทสุดท้ายของ Level 0: เราจะประกอบหลายขั้นตอนเป็น "ผู้ช่วย" ตัวเดียว **โดยใช้แค่ `if` และ `while` ธรรมดา** ไม่ใช้ framework อะไรเลย เพื่อให้เห็นว่าโค้ดแบบนี้ดีแค่ไหนและเริ่มเจ็บตรงไหน

ผู้ช่วยทำงานตามแผนผังนี้:

```
ข้อความผู้ใช้ ──► classify (LLM จัดประเภท)
                    │
        greeting ◄──┴──► question
           │                 │
   ตอบสำเร็จรูป      ให้ LLM ตอบร่างแรก
   (ไม่เรียก LLM)            │
                      วนปรับปรุง ◄─┐ (ไม่เกิน maxRounds รอบ
                             └─────┘  หรือจนตอบ "OK")
```
สังเกตว่าทุกอย่างทำได้ด้วยฟังก์ชัน, `if`, `while` และตัวแปร ซึ่ง **ดีมากสำหรับแอปเล็ก ๆ** อย่ารีบใช้ framework ถ้ายังไม่จำเป็น

## ดูตัวอย่าง
`assistant.ts` มีฟังก์ชัน `ask` (ถามแล้วได้ข้อความตอบ) ให้มาแล้ว และวนถามสองข้อความ (ทักทายหนึ่ง คำถามหนึ่ง) ส่วนที่คุณเขียนคือจัดประเภท ทางตอบของ greeting และลูปปรับปรุงคำตอบ

## โจทย์
เติม 3 ช่อง (ค้นหา `// 👉 ข้อ N` ในไฟล์) แล้วรัน:

    pnpm lesson 0-06

สคริปต์จะพิมพ์ประเภทและคำตอบของแต่ละข้อความ แล้วท้ายไฟล์มีส่วนตรวจที่แสดง ✅/❌ (ไม่ต้องแก้และไม่ต้องอ่านก็ได้)

> **ข้อสังเกตจากของจริง:** ตอนทดลองกับ LLM จริง ถ้าคำสั่งเขียนแค่ "ถ้าดีแล้วตอบ OK" โมเดลบางครั้งตอบคำตอบที่ปรับปรุงแล้วต่อท้ายด้วย `OK` ทำให้เงื่อนไข "ตอบ OK คำเดียว" ไม่เป็นจริง และ `OK` ติดไปในคำตอบ จึงต้องเขียนคำสั่งให้ชัดว่าตอบรูปแบบไหนได้บ้าง และอย่าลืมว่าผลของ LLM ไม่แน่นอนเสมอ

## ลองคิดต่อ (ไม่ต้องเขียนโค้ด) ว่าถ้าลูกค้าขอเพิ่มข้อ ๆ นี้ โค้ดจะเป็นอย่างไร
1. **บันทึกทุกก้าว**: อยากรู้ว่าแต่ละคำถามผ่านขั้นตอนไหนบ้าง ใช้เวลาเท่าไร (ต้องแทรกโค้ดบันทึกทุกที่)
2. **แสดงความคืบหน้า**: ให้หน้าจอบอกว่า "กำลังจัดประเภท... กำลังปรับปรุงรอบที่ 2..." ระหว่างรอ
3. **เพิ่มประเภทใหม่**: เช่น `complaint` ที่ต้องส่งต่อให้คน และ **หยุดรอคนอนุมัติ** ก่อนตอบ แล้วค่อยทำต่อทีหลัง (แม้โปรแกรมจะถูกปิดไปแล้ว)
4. **จำบทสนทนา**: ทำต่อจากรอบก่อนเมื่อผู้ใช้กลับมาคุยใหม่
5. **ขั้นตอนขนานกัน**: ให้ LLM สองตัวทำงานพร้อมกันแล้วรวมผล

แต่ละข้อทำได้ แต่ฟังก์ชัน `runAssistant` จะยาวขึ้น ตัวแปรสถานะกระจาย และการเพิ่มเงื่อนไขหนึ่งอาจกระทบอีกที่ นี่คือปัญหาที่ **LangGraph** แก้: แยกแต่ละขั้นเป็น node, เก็บสถานะไว้ที่เดียว (State), เส้นทางเป็นข้อมูลที่ตรวจสอบได้ (edge), และมีระบบบันทึก/หยุดรอ/ทำต่อให้ในตัว

ใน Level 1 บทที่ 20 คุณจะสร้างผู้ช่วยแบบเดียวกันนี้อีกครั้งด้วย LangGraph เพื่อเทียบกับบทนี้

## คุณทำได้แล้ว
- ประกอบผู้ช่วยหลายขั้นตอนที่จัดประเภท เลือกทาง และวนปรับปรุงด้วยโค้ดธรรมดา
- รู้ว่าโค้ดแบบนี้ดีตรงไหน และมองออกว่าถ้าความต้องการเพิ่มขึ้น มันจะพันตรงไหน
- จบ Level 0 และพร้อมเห็นว่าเครื่องมือที่ใช้ต่อไป (LangChain, LangGraph) แก้ปัญหาอะไรที่คุณเจอมาเอง

## ข้อควรจำ
- แอปเล็ก ๆ ใช้ `if`/`while` ได้ ไม่ต้องรีบใช้ framework
- เมื่อต้องการบันทึก, สตรีมความคืบหน้า, หยุดรอคน, จำสถานะ ฟังก์ชันเดียวจะรับไม่ไหว
- การแยกขั้นตอน (node) และเก็บสถานะที่เดียว (State) คือหัวใจของ LangGraph
