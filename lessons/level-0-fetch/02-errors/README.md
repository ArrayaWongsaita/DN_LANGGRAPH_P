# บทที่ 0-02: เมื่อ request พัง (อ่านและจัดการ error)

## แนวคิด
บทที่แล้วเราสมมติว่าทุกอย่างราบรื่น แต่ของจริงพังได้เสมอ: key ผิด ชื่อโมเดลผิด เรียกถี่เกินโควตา หรืออินเทอร์เน็ตหลุด ถ้าไม่จัดการ ผู้ใช้จะเจอ error ที่อ่านไม่รู้เรื่อง (เช่น `Cannot read properties of undefined (reading '0')` เพราะคำตอบไม่มี `choices`)

ข้อมูลที่เรามีให้ใช้ตัดสินใจ:

| สิ่งที่เห็น | ความหมาย | ควรบอกผู้ใช้ว่า |
|---|---|---|
| `fetch` throw เอง (ไม่มี response) | เครือข่ายล่ม / URL ผิด | เชื่อมต่อไม่ได้ ตรวจอินเทอร์เน็ตและ URL |
| `res.ok === false`, status **401** | key ผิดหรือไม่มี | ตรวจ key ใน `.env` |
| status **404** | ไม่มีโมเดลนี้ / บัญชีไม่มีสิทธิ์ | ตรวจชื่อโมเดล (`LLM_MODEL`) |
| status **429** | เรียกถี่เกินโควตา | รอแล้วลองใหม่ (header `retry-after` บอกจำนวนวินาที) |
| status อื่น ๆ (เช่น 500) | ปัญหาฝั่งเซิร์ฟเวอร์ | แสดงสถานะและข้อความที่ได้ |

เมื่อเป็น error เซิร์ฟเวอร์ส่ง body เป็น JSON รูปแบบเดียวกันเสมอ:

```json
{ "error": { "message": "Invalid API Key", "type": "invalid_request_error", "code": "invalid_api_key" } }
```
ข้อควรระวัง: บางครั้ง body ของ error ไม่ใช่ JSON (เช่นหน้า HTML จาก proxy) ถ้าสั่ง `res.json()` ตรง ๆ จะพังซ้อน จึงต้องใช้ `.catch(() => undefined)` กันไว้

> ผู้ให้บริการส่ง header `x-ratelimit-remaining-requests` และ `x-ratelimit-remaining-tokens` กลับมากับทุกคำตอบ บอกโควตาที่เหลือ ใช้เฝ้าดูได้ถ้าต้องการ

## ดูตัวอย่าง
`callLLM.ts` มีส่วนส่ง request ที่คุ้นเคยจากบทที่แล้ว และมี 3 ช่องที่ต้องเติม: ฟังก์ชันแปลสถานะเป็นข้อความ การจับกรณีเครือข่ายล่ม และการจัดการ `!res.ok`

## โจทย์
เติม 3 ช่อง แล้วรัน:

    pnpm test:lesson 0-02

เขียวแล้วลอง `pnpm lesson 0-02` ปกติ และลองแกล้งทำผิด (ใส่ key มั่วใน `.env`, ตั้ง `LLM_MODEL` เป็นชื่อที่ไม่มี) แล้วดูข้อความที่ได้ (อย่าลืมแก้คืน)

## คุณทำได้แล้ว
- แยกได้ว่า error เกิดจากเครือข่าย หรือจากเซิร์ฟเวอร์ และอ่านเลขสถานะเป็น
- แปลง error ให้เป็นข้อความที่ผู้ใช้เอาไปแก้ต่อได้
- กัน error ซ้อน (body ที่ไม่ใช่ JSON)

## ข้อควรจำ
- ตรวจ `res.ok` ก่อนอ่านคำตอบเสมอ
- 401 = key, 404 = โมเดล, 429 = รอ, อื่น ๆ = แสดงข้อความที่ได้
- งานแบบนี้ (retry เมื่อ 429, เปลี่ยนไปใช้โมเดลสำรอง) framework จัดการให้เราได้ จะเจอใน Level 2
