# บทที่ 0-02 อ่านสถานะเมื่อคำขอมีปัญหา

แอปส่งคำขอแบบ [บท 0-01](../01-first-fetch/README.md) แล้วอาจได้รับ `Response` สถานะ 401 หรืออาจเชื่อมต่อไม่ได้เลย สองกรณีนี้มาถึงคนละจุดในโค้ดและควรแสดงวิธีแก้ต่างกัน

## 1. แยกคำตอบปกติด้วย `response.ok`

เปิด [`callLLM.ts`](./callLLM.ts) แล้วเติมข้อ 1 ให้ `succeeded` เป็นจริงเมื่อสถานะ HTTP อยู่ในช่วง 200–299 รันจากโฟลเดอร์หลักของโปรเจกต์ บทนี้ใช้ `Response` ตัวอย่างและจำลอง Promise ที่ถูกปฏิเสธ จึงรันได้โดยไม่ต้องมี API key หรือเชื่อมต่อเครือข่าย

```sh
pnpm lesson 0-02
```

ตัวอย่างย่อด้านล่างสร้าง `Response` สองแบบด้วย API เดียวกับออบเจ็กต์ที่ `fetch` คืนให้

```ts
const success = new Response("สวัสดี", { status: 202 });
const error = new Response(null, { status: 401 });

console.log(success.ok, error.ok); // true false
```

ในไฟล์เริ่มต้นใช้ `response.ok` ก่อนอ่าน body ถ้าเซิร์ฟเวอร์ตอบกลับด้วย 401 ค่า `response.ok` เป็น `false` และยังอ่าน `response.status` ได้ ถ้า `fetch` เชื่อมต่อไม่ได้ Promise จะถูกปฏิเสธและจะไม่มี `Response` ให้อ่าน

## 2. ดูข้อความของแต่ละกรณี

```text
[202] สวัสดี
[401] ตรวจ API key ใน .env
[404] ไม่พบโมเดลหรือปลายทาง (Model unavailable)
[429] เรียกถี่เกินไป รอ 7 วินาทีแล้วลองใหม่
[503] HTTP 503 Service Unavailable
[เครือข่าย] เชื่อมต่อไม่ได้ ตรวจอินเทอร์เน็ตและ URL
✅ อ่านคำตอบเมื่อได้สถานะในช่วง 2xx
✅ แยกปัญหา API key กับโมเดลที่หาไม่เจอ
✅ อ่านเวลารอจาก Retry-After
✅ ใช้สถานะได้แม้ body เป็นข้อความธรรมดา
✅ อธิบายกรณีที่ไม่ได้รับ Response
```

กรณี 503 ส่ง body เป็นข้อความธรรมดา การอ่านด้วย `response.json()` จึงล้มเหลว สคริปต์จับกรณีนี้และยังใช้เลขสถานะกับ `statusText` ได้

## 3. อ่านอะไรได้จาก `Response`

| ค่า | ชนิดและค่าที่พบ | ตัวอย่างการใช้ |
|---|---|---|
| `response.ok` | `boolean` เป็น `true` สำหรับ 200–299 | เลือกว่าจะอ่านคำตอบหรือหาเหตุของปัญหา |
| `response.status` | ตัวเลข เช่น `401`, `404`, `429` | แนะนำให้ตรวจ key, ตรวจชื่อโมเดลหรือ URL, หรือรอก่อนเรียกใหม่ |
| `response.statusText` | สตริง อาจว่างได้ | ใช้ประกอบข้อความเมื่อ body ไม่มีรายละเอียด JSON |
| `body.error.message` | สตริงเมื่อบริการส่ง JSON รูปนี้มา | เพิ่มรายละเอียดของ 404 |
| `response.headers.get("Retry-After")` | สตริง หรือ `null` เมื่อไม่มี header | ค่าอย่าง `"7"` คือเวลารอเป็นวินาที บทนี้ใช้ข้อความให้รอแบบทั่วไปเมื่อเจอวันเวลา HTTP หรือไม่มี header |

## 4. เปลี่ยนแค่ `Retry-After`

เก็บสถานะ 429 ไว้เหมือนเดิม แล้วเปลี่ยนเฉพาะ header

| `Retry-After` | ข้อความที่ได้ |
|---|---|
| `"7"` | เรียกถี่เกินไป รอ 7 วินาทีแล้วลองใหม่ |
| `"30"` | เรียกถี่เกินไป รอ 30 วินาทีแล้วลองใหม่ |
| ละ header | เรียกถี่เกินไป รอแล้วลองใหม่ |

คัดลอกกรณี 429 ไปลองใน [`playground.ts`](./playground.ts) แล้วรัน `pnpm play 0-02` เพื่อเปลี่ยนเวลาได้โดยไม่กระทบตัวตรวจของบท
