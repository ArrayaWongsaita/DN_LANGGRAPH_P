# บทที่ 0-03: messages และประวัติการคุย

## แนวคิด
ถ้าคุณถาม LLM ว่า "ฉันชื่ออะไร" ทั้งที่เพิ่งบอกชื่อไปเมื่อกี้ มันจะตอบไม่ได้ เพราะ **LLM ไม่มีความจำ** ทุกครั้งที่ส่ง request คือเริ่มใหม่หมด สิ่งที่ดูเหมือน "ความจำ" ในแชตบอทจริง ๆ คือโปรแกรมของเรา **ส่งบทสนทนาทั้งหมดไปให้ใหม่ทุกครั้ง**

ที่ field `messages` ใน body คือ array ของข้อความ แต่ละข้อความมี `role` บอกว่าใครพูด:

| role | ใครพูด |
|---|---|
| `system` | คำสั่งตั้งต้น กำหนดบทบาท/สไตล์ (ต้องอยู่ต้นรายการ) |
| `user` | ผู้ใช้ (เรา) |
| `assistant` | LLM |

```
messages: [
  { role: "system",    content: "ตอบสั้น ๆ" },          ← คำสั่งตั้งต้น
  { role: "user",      content: "ฉันชื่อมาลี" },         ┐ ประวัติ
  { role: "assistant", content: "ยินดีที่ได้รู้จัก" },     ┘
  { role: "user",      content: "ฉันชื่ออะไร" },         ← คำถามใหม่
]
```
- **ลำดับสำคัญ** LLM อ่านจากบนลงล่าง
- หลังได้คำตอบ เราต้อง **เก็บ** คำถามและคำตอบนั้นต่อท้ายประวัติเอง (เพื่อส่งในรอบหน้า) ไม่งั้นรอบหน้ามันก็จำไม่ได้
- ประวัติยาวขึ้น = ส่งข้อมูลมากขึ้น = ช้าลงและแพงขึ้นเรื่อย ๆ (Level 2 จะสอนวิธีจัดการ)

## ดูตัวอย่าง
`chat.ts` มีฟังก์ชัน `send` (ส่ง `messages` แล้วคืนข้อความตอบ) ให้มาแล้ว เหมือนบท 0-01 สิ่งที่ต้องเขียนคือการเก็บประวัติและประกอบ `messages` ท้ายไฟล์ถามคำถามเดิมสองแบบ คือมีประวัติกับไม่มีประวัติ แล้วเทียบกัน

## โจทย์
เติม 2 ช่อง (ค้นหา `// 👉 ข้อ N` ในไฟล์) แล้วรัน:

    pnpm lesson 0-03

สคริปต์จะพิมพ์คำตอบ "มีประวัติ" กับ "ไม่มีประวัติ" ให้เทียบกัน แล้วท้ายไฟล์มีส่วนตรวจที่แสดง ✅/❌ (ไม่ต้องแก้และไม่ต้องอ่านก็ได้)

## คุณทำได้แล้ว
- ส่งบทสนทนาหลายข้อความด้วย `role` ทั้งสามแบบ
- เข้าใจว่าทำไมแชตบอท "จำ" ได้ และเก็บประวัติเองโดยไม่แก้ array เดิม

## ข้อควรจำ
- LLM ไม่มีความจำ ต้องส่งประวัติทั้งหมดไปทุกครั้ง
- ลำดับ: system → ประวัติ → คำถามใหม่
- เก็บประวัติเป็น array ใหม่ ไม่แก้ของเดิม (กันบั๊กที่หายาก)

## ลองเล่นต่อ
อยากทดลองเองโดยไม่มีส่วนตรวจคำตอบ: `pnpm play 0-03` จะรันไฟล์ `playground.ts` ในโฟลเดอร์บทนี้ (สร้างให้แล้ว มีแต่ import ที่ใช้ เขียนโค้ดต่อเองได้เลย) ในหัวไฟล์มีไอเดียให้ลองทำ ใช้ `--watch` ให้รันซ้ำทุกครั้งที่บันทึก และ `--reset` เพื่อเริ่มใหม่
