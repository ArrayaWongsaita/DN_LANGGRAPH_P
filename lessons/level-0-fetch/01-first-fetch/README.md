# บทที่ 0-01: เรียก LLM ด้วย fetch (HTTP ล้วน ๆ)

## ทำไมเริ่มที่นี่
ก่อนจะใช้ LangChain และ LangGraph เรามาดูก่อนว่า **การเรียก LLM จริง ๆ แล้วคืออะไร** คำตอบสั้นมาก: มันคือ HTTP request ธรรมดา เหมือนที่เว็บเบราว์เซอร์ขอหน้าเว็บ ใน Level 0 คุณจะเรียก LLM ด้วย `fetch` (ที่มากับ Node อยู่แล้ว ไม่ต้องติดตั้งอะไร) แล้วค่อย ๆ เจอปัญหาจริง ๆ ที่ framework ถูกสร้างมาแก้

> นี่คือส่วนที่ "ทำเองก่อน เพื่อเห็นว่า framework ช่วยอะไร" ถ้าคุณคุ้นกับ HTTP อยู่แล้ว ข้ามไป **Level 1** ได้เลย

## ตั้งค่าก่อนเริ่ม (ทำครั้งเดียว)
1. คัดลอกไฟล์ตัวอย่าง: `cp .env.example .env`
2. สมัครบัญชีผู้ให้บริการ LLM ที่ใช้ (ค่าเริ่มต้นของคอร์สคือ Groq) แล้วสร้าง **API key** ของคุณเอง (เหมือนรหัสผ่านของแอป)
3. เปิด `.env` ใส่ key หลัง `GROQ_API_KEY=` (ไม่ต้องมีเครื่องหมายคำพูด ไม่ต้องมีช่องว่าง)
4. **ห้ามเขียน key ลงในโค้ด และห้ามอัปโหลด `.env` ขึ้น git** (เราตั้ง `.gitignore` ไว้ให้แล้ว)

## วิธีทำงานของบทเรียนในคอร์สนี้ (สั้น ๆ)
คุณเขียนโค้ดในไฟล์ `callLLM.ts` ตรงช่องที่มี `// 👉 ข้อ N` ส่วน `callLLM.test.ts` เป็น "กรรมการ" ที่ตรวจให้ (ห้ามแก้) ตอนเริ่มกรรมการจะให้ **สีแดง** ซึ่งปกติ เป้าหมายคือเติมจนเป็น **สีเขียว**

รัน: `pnpm test:lesson 0-01` ผลที่แดงจะประมาณนี้:

```
 × คืนข้อความจาก choices[0].message.content
Error: ยังไม่ได้ทำข้อ 1                       <- ช่องไหนยังว่าง
 ❯ callLLM lessons/level-0-fetch/.../callLLM.ts:25:13   <- ไฟล์และบรรทัดที่ต้องไปดู
```
(รายละเอียดเต็มของการอ่านผลที่แดง อยู่ในบท 01 ของ Level 1)

## แนวคิด: request และ response
การคุยกับ LLM มีแค่สองก้อน:

```
        ┌─────────── request (POST) ───────────┐
เรา ───►│ URL     : ที่อยู่ของ API              │───► LLM
        │ headers : Authorization: Bearer <key>│
        │           Content-Type: application/json
        │ body    : { "model": "...",           │
        │             "messages": [             │
        │               {"role":"user",         │
        │                "content":"คำถาม"} ] } │
        └───────────────────────────────────────┘

        ┌─────────── response (JSON) ──────────┐
เรา ◄───│ { "choices": [ {                      │◄─── LLM
        │     "message": {                      │
        │        "role": "assistant",           │
        │        "content": "คำตอบ" } } ],      │
        │   "usage": { ... } }                  │
        └───────────────────────────────────────┘
```
- **URL**: ที่อยู่ของ API (ในโปรเจกต์นี้ `src/llm.ts` เป็นคนบอก ขึ้นกับ provider ที่ตั้งใน `.env`)
- **header `Authorization`**: บอกว่าเราเป็นใคร ด้วย key ของเรา
- **body**: ข้อความ JSON ที่บอกว่าใช้โมเดลไหน และ `messages` คือบทสนทนา (ตอนนี้มีข้อความเดียวจากผู้ใช้ `role: "user"`)
- **คำตอบ** อยู่ลึกลงไปที่ `choices[0].message.content` (บางโมเดลมี field `reasoning` แยกไว้ด้วย เป็นความคิดของโมเดล เราไม่ใช้)

> **กล่องเล็ก: async / await**
> `fetch` ต้องรอเครือข่าย จึงได้ Promise กลับมา ใส่ `await` เพื่อรอผลก่อนไปบรรทัดถัดไป และฟังก์ชันที่ใช้ `await` ต้องประกาศเป็น `async` (ผลที่คืนเป็น `Promise<...>`) ลืม `await` = ได้ Promise แทนข้อมูล

> **ทำไมฟังก์ชันรับ `fetchFn` เข้ามา**
> ตอนใช้จริงเราส่ง `fetch` ตัวจริงเข้าไป แต่ตอนตรวจงานกรรมการส่ง "fetch ปลอม" ที่ตอบตามที่เขียนไว้ จึงไม่ต้องมี key และไม่เสียเงิน

## ดูตัวอย่าง
เปิด `callLLM.ts`: ฟังก์ชัน `callLLM` รับ `fetchFn`, `url`, `apiKey`, `model` และ `question` แล้วต้องคืนข้อความคำตอบ

## โจทย์
เติม 2 ช่อง `// 👉 ข้อ N` ใน `callLLM.ts` แล้วรัน:

    pnpm test:lesson 0-01

เขียวแล้วลองเรียก LLM จริง (ต้องตั้ง key แล้ว):

    pnpm lesson 0-01

> ถ้าขึ้นว่ายังไม่ได้ตั้ง key ให้กลับไปทำ "ตั้งค่าก่อนเริ่ม" ถ้าได้ error อื่น (เช่น คำตอบไม่มี `choices`) ไม่ต้องตกใจ บทที่ 0-02 จะสอนอ่านและจัดการ error

## คุณทำได้แล้ว
- เรียก LLM ด้วย HTTP request ธรรมดา และรู้ว่า request/response หน้าตาเป็นอย่างไร
- ตั้งค่า API key ใน `.env` อย่างปลอดภัย
- อ่านผลสีแดงของกรรมการและเติมช่องจนเขียว

## ข้อควรจำ
- การเรียก LLM = POST + header `Authorization` + body JSON ที่มี `model` กับ `messages`
- คำตอบอยู่ที่ `choices[0].message.content`
- key อยู่ใน `.env` เท่านั้น ไม่ลงโค้ด ไม่ขึ้น git

## บทถัดไป
บทที่ 0-02 จะดูว่าเกิดอะไรขึ้นเมื่อ request พัง (key ผิด โมเดลไม่มี เรียกถี่เกินไป) และทำให้ข้อความ error อ่านรู้เรื่อง
