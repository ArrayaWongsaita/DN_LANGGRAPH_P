# บทที่ 0-04: ขอให้ LLM ตอบเป็น JSON (และปัญหาที่จะเจอ)

## แนวคิด
LLM ตอบเป็นข้อความอิสระ ซึ่งโปรแกรมเอาไปใช้ต่อยาก (ตัดคำเองก็พังง่าย) ถ้าอยากได้ข้อมูลเป็นโครงสร้าง วิธีพื้นฐานที่สุดคือ **ขอให้ตอบเป็น JSON** ในคำสั่ง แล้วเอาข้อความที่ได้ไปแปลงเป็น object:

```
คำสั่ง "ตอบเป็น JSON {name, age}" ──► LLM ──► ข้อความ ──► JSON.parse ──► ตรวจด้วย zod ──► object
```
ฟังดูง่าย แต่ของจริงมีกับดัก (ซึ่งบทนี้จะให้เจอ):

1. **รั้วโค้ด**: LLM หลายตัวชอบห่อคำตอบด้วย ```` ```json ... ``` ```` ทำให้ `JSON.parse` พัง (ต้องลอกรั้วออกก่อน)
2. **ไม่ใช่ JSON เลย**: บางครั้งตอบ "ขอโทษครับ ตอบไม่ได้" ต้อง error ที่อ่านรู้เรื่อง ไม่ใช่ `Unexpected token`
3. **ชนิดข้อมูลผิด**: ได้ JSON ที่ถูกรูปแบบแต่ `age` เป็น `"สี่สิบสอง"` แทนตัวเลข หรือขาด field จึงต้องตรวจด้วย **zod** (ที่คุณใช้ในบท 01 ของ Level 1) ก่อนใช้ข้อมูล

> **หมายเหตุ:** ตอนทดลองกับโมเดลเริ่มต้นของคอร์ส 3 ครั้ง ไม่เจอรั้วโค้ดเลย แต่เจอกับโมเดลอื่นได้จริง บทนี้ตัวตรวจจึงใช้คำตอบ **จำลอง** ที่ห่อรั้วโค้ดเพื่อให้เห็นปัญหาแน่นอนทุกครั้ง (ไม่ได้บอกว่าโมเดลของคุณจะทำแบบนี้เสมอ)

## ดูตัวอย่าง
`parsePerson.ts` มี `personSchema` (รูปร่างที่ต้องการ), ฟังก์ชันที่ต้องเขียนคือ `stripFence` และ `parsePerson` ส่วน `extractPerson` (ที่ส่ง request) ให้มาแล้ว

## โจทย์
เติม 3 ช่อง แล้วรัน:

    pnpm test:lesson 0-04

ลอง `pnpm lesson 0-04` กับ LLM จริง

## คุณทำได้แล้ว
- ขอให้ LLM ตอบเป็น JSON แล้วแปลงเป็น object ที่ตรวจรูปร่างแล้วด้วย zod
- รับมือกับคำตอบที่ห่อรั้วโค้ด ไม่ใช่ JSON หรือชนิดข้อมูลผิด

## ข้อควรจำ
- ข้อมูลจาก LLM เชื่อ 100% ไม่ได้ ต้องตรวจด้วย schema เสมอ
- ต้องเตรียมรับกรณีล้มเหลวและบอกสาเหตุให้ชัด
- งานทั้งหมดนี้ (ขอ JSON, ลอกรั้ว, ตรวจ schema) ใน Level 1 บท 09 เหลือบรรทัดเดียวด้วย `.withStructuredOutput(schema)`
