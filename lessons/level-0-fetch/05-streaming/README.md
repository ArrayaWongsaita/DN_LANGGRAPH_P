# บทที่ 0-05: streaming ด้วย SSE (บทเสริม ข้ามได้)

> บทนี้ยากที่สุดของ Level 0 และเป็นทางเลือก ถ้าอยากไปต่อเร็ว ข้ามไปบท 0-06 ได้โดยไม่ขาดอะไร

## แนวคิด
ถ้ารอให้ LLM เขียนจบทั้งคำตอบแล้วค่อยแสดง ผู้ใช้จะเห็นหน้าจอว่างเป็นสิบวินาที แอปแชตจริงจึงใช้ **streaming**: เซิร์ฟเวอร์ส่งคำตอบมาทีละชิ้นเล็ก ๆ เราแสดงทันทีที่ได้ เปิดโหมดนี้ด้วยการเพิ่ม `"stream": true` ใน body

รูปแบบที่ตอบกลับมาเรียกว่า **SSE (Server-Sent Events)** ซึ่งเป็นข้อความธรรมดาที่มีหน้าตาแบบนี้:

```
data: {"choices":[{"delta":{"content":"สวั"}}]}

data: {"choices":[{"delta":{"content":"สดี"}}]}

data: [DONE]
```
- แต่ละ event คือบรรทัดที่ขึ้นต้นด้วย `data: ` ตามด้วย JSON และคั่นด้วยบรรทัดว่าง
- ข้อความของชิ้นนั้นอยู่ที่ `choices[0].delta.content`
- ชิ้นสุดท้ายคือ `data: [DONE]`
- บางชิ้นไม่มีข้อความ (เช่น ชิ้นความคิดของโมเดลที่มี `delta.reasoning` แทน) ต้องข้าม

### กับดักใหญ่: ข้อมูลถูกตัดกลางบรรทัด
ตอนทดลองกับของจริง เราอ่านสตรีมหนึ่งครั้งได้ 16 ก้อน และ **9 ก้อนไม่ได้จบที่ขึ้นบรรทัดใหม่** คือ event หนึ่งอาจมาถึงครึ่ง ๆ แล้วอีกครึ่งมาในก้อนถัดไป ถ้าเราเอาแต่ละก้อนไป `JSON.parse` ทันที จะพังเป็นครั้งคราว (แบบที่ทดสอบยากมาก) วิธีที่ถูกคือ **เก็บเศษของบรรทัดสุดท้ายไว้ใน buffer** แล้วต่อกับก้อนถัดไปก่อนค่อยประมวลผล

> **async generator** (`async function*` + `yield`) คือฟังก์ชันที่ "ส่งค่าออกมาทีละชิ้น" ผู้เรียกใช้ `for await (const piece of streamText(...))` อ่านเป็นชิ้น ๆ ได้ คล้ายกับที่คุณใช้ใน Level 1 บท 07

## ดูตัวอย่าง
`streamText.ts`: ส่ง request พร้อม `stream: true` แล้วอ่านก้อนข้อมูลจาก `res.body` ในลูป สิ่งที่ต้องเขียนคือการแยกบรรทัดพร้อม buffer และการจัดการแต่ละบรรทัด

## โจทย์
เติม 2 ช่อง แล้วรัน:

    pnpm test:lesson 0-05

ตัวตรวจมีเคสที่ตัดข้อมูลกลางบรรทัดให้ด้วย ลอง `pnpm lesson 0-05` กับ LLM จริง

## คุณทำได้แล้ว
- อ่านสตรีม SSE เองได้ และเข้าใจว่าทำไมต้องมี buffer
- ใช้ async generator ส่งข้อมูลออกมาทีละชิ้น

## ข้อควรจำ
- สตรีมแบ่งก้อนไม่ตรงกับบรรทัด ต้องเก็บเศษไว้ใน buffer เสมอ
- ข้ามบรรทัดที่ไม่ใช่ `data: ` และหยุดที่ `[DONE]`
- ใน Level 1 บท 07 สิ่งนี้เหลือ `for await (const chunk of await llm.stream(...))` สามบรรทัด
