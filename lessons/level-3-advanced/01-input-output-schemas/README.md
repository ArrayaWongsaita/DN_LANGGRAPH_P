# บทที่ 3-01 schema ของ input/output และ state ส่วนตัว

## แนวคิด

ปกติ graph รับและคืน State ทั้งก้อน แต่ในงานจริงเรามักอยาก:
- จำกัดว่า **ผู้เรียกส่งอะไรเข้ามาได้** (input)
- จำกัดว่า **ผู้เรียกได้อะไรกลับไป** (output) ไม่รั่วข้อมูลภายใน
- มี field **ส่วนตัว** ที่ใช้ระหว่าง node เท่านั้น (เช่น ร่างความคิด) ไม่โผล่ออกไป

ทำได้โดยแยก 3 schema แล้วส่งให้ `StateGraph`:

```ts
new StateGraph({ state: Full, input: In, output: Out })
```
- `Full`: field ทั้งหมดที่ node อ่าน/เขียนได้
- `In`: field ที่รับตอน `invoke`
- `Out`: field ที่คืนตอนจบ (field ที่ไม่อยู่ใน `Out` เช่น `scratch` จะไม่ถูกคืน)

## 1. ลองเติมช่องเดียว

เปิด [`schemas.ts`](./schemas.ts) แล้วเติมข้อ 1: ประกอบ `StateGraph` ด้วย schema ของ state เต็ม, input และ output รันจากโฟลเดอร์หลักของโปรเจกต์ บทนี้ไม่เรียกโมเดลจริง รันได้โดยไม่ต้องมี API key

```sh
pnpm lesson 3-01
```

ในไฟล์ข้อ 1 มี **แนวทาง** เป็นโค้ดที่คอมเมนต์ไว้ เอา `//` ออกแล้วแทนที่ `todo(1)` ได้เลย แต่ลองอ่านก่อนว่าแต่ละบรรทัดทำอะไร

ในไฟล์มี schema สามชุด (`Full`, `In`, `Out`) และ node ที่ใช้ field ส่วนตัวให้แล้ว สคริปต์เรียก graph แล้วดูว่าผลลัพธ์มีแค่ field ของ `Out` หรือไม่

โค้ดตามแนวทาง:

```ts
const builder = new StateGraph({ state: Full, input: In, output: Out });
```

## 2. ผลที่ได้

ผลที่รันจากเฉลย

```text
{ answer: 'คำตอบของ: ทำไมท้องฟ้าสีฟ้า' }
✅ ผลลัพธ์มีแค่ field ของ Out (answer)
✅ answer มาจาก node think
✅ ช่องส่วนตัว scratch ไม่รั่วออกมา
```

สิ่งที่ได้: กำหนดหน้าตา input/output ของ graph และซ่อน state ภายใน

## 3. ส่วนประกอบที่ใช้ในบทนี้

| ค่าใน `StateGraph` | ใช้กำหนดอะไร | ตัวอย่างในบทนี้ |
|---|---|---|
| `state` | field ทั้งหมดที่ node อ่านและเขียนได้ | `Full` |
| `input` | field ที่ผู้เรียกส่งตอน `invoke` | `In` |
| `output` | field ที่ผู้เรียกได้กลับมาตอนจบ | `Out` (field ส่วนตัวอย่าง `scratch` ไม่ถูกคืน) |

## ข้อควรจำ

- node ยังอ่าน/เขียน field ใดก็ได้ใน `Full`
- `Out` คือสัญญากับผู้เรียก เปลี่ยนแล้วกระทบผู้ใช้
