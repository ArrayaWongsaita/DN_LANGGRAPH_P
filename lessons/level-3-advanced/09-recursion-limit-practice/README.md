# บทที่ 3-09 วนซ้ำอย่างปลอดภัย (recursion limit ในงานจริง)

## แนวคิด

บท 2-12 กัน agent วน บทนี้ใช้กับ **ลูปที่เราออกแบบเอง** เช่น "ปรับปรุงข้อความจนผ่านเกณฑ์" ลูปมีเงื่อนไขหยุดสองชั้น:

1. **เงื่อนไขของงาน**: หยุดเมื่อได้ผลตามต้องการ (เช่น ปรับครบ `target` รอบ)
2. **เพดานความปลอดภัย**: `recursionLimit` กันกรณีเงื่อนไขแรกไม่เคยเป็นจริง (บั๊ก/ข้อมูลแปลก)

```ts
await graph.invoke(input, { recursionLimit: 20 }); // เกิน = GraphRecursionError
```
งานของคุณคือคำนวณเพดานให้พอดีกับจำนวนรอบที่ตั้งใจ (แต่ละรอบ = 1 step) และจัดการกรณีชนเพดานให้ผู้ใช้ได้ข้อความที่เข้าใจ

## 1. ลองเติมช่องเดียว

เปิด [`loop.ts`](./loop.ts) แล้วเติมข้อ 1: คำนวณเพดาน step ของลูปจาก `target` (เช่น `target + 2`) รันจากโฟลเดอร์หลักของโปรเจกต์ บทนี้ไม่เรียกโมเดลจริง รันได้โดยไม่ต้องมี API key

```sh
pnpm lesson 3-09
```

ในไฟล์ข้อ 1 มี **แนวทาง** เป็นโค้ดที่คอมเมนต์ไว้ เอา `//` ออกแล้วแทนที่ `todo(1)` ได้เลย แต่ลองอ่านก่อนว่าแต่ละบรรทัดทำอะไร

ในไฟล์มี graph ที่นับ `n` ทีละหนึ่ง เงื่อนไขหยุด และการจับ `GraphRecursionError` ให้แล้ว ขาดแค่สูตรเพดาน `recursionLimit` ที่พอดีกับจำนวนรอบ

โค้ดตามแนวทาง:

```ts
const limitForRounds = (target: number): number => target + 2;
```

## 2. ผลที่ได้

ผลที่รันจากเฉลย

```text
[ 'ok:3', 'limit' ]
✅ limitForRounds(3) = 5
✅ เพดานพอดี วนครบ 3 รอบ
✅ เพดานต่ำเกินไป ถูกหยุดและจับ error ได้
```

สิ่งที่ได้: ออกแบบลูปที่หยุดได้แน่นอนทั้งโดยเงื่อนไขงานและเพดานระบบ

## 3. ส่วนประกอบที่ใช้ในบทนี้

| ชั้นป้องกัน | คืออะไร | ในบทนี้ |
|---|---|---|
| เงื่อนไขของงาน | หยุดเมื่อได้ผลตามต้องการ | `n >= target` แล้วไป `END` |
| เพดานความปลอดภัย | `recursionLimit` กันกรณีเงื่อนไขแรกไม่เคยเป็นจริง | `target + 2` |
| การจับ error | `GraphRecursionError` | บันทึก `limit` ไม่ใช่ error อื่น |

## ข้อควรจำ

- เพดานต้อง "เผื่อ" แต่ไม่ใหญ่เกินจนไม่ช่วยอะไร
- เงื่อนไขหยุดผิด = ชนเพดานเสมอ ให้ถือเป็นสัญญาณบั๊ก
