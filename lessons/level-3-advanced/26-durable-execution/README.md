# บทที่ 3-26: durable execution (ทนต่อการล่มกลางทาง)

## แนวคิด
เพราะ checkpointer บันทึกทุก step LangGraph จึง **ทำต่อจากจุดที่ล่ม** ได้: ถ้า graph มี 3 ขั้นแล้วขั้นที่ 3 ล่ม (เครือข่าย, โปรแกรมถูกปิด) ขั้นที่ 1-2 ที่สำเร็จแล้ว **ไม่ต้องทำใหม่** (ไม่เสียค่า LLM ซ้ำ) แค่เรียกต่อด้วย input เป็น `null` และ `thread_id` เดิม:

```ts
try { await graph.invoke(input, cfg); } catch { /* ล่ม */ }
await graph.invoke(null, cfg);   // ทำต่อจากขั้นที่ล่ม
```
ตัวเลือก `durability` ตอน invoke ควบคุมจังหวะบันทึก:
- `"exit"`: บันทึกตอนจบ (เร็วสุด แต่ถ้าโปรเซสตายกลางทาง ความคืบหน้าระหว่างทางอาจไม่ถูกบันทึก)
- `"async"`: บันทึกแบบไม่รอ (ค่าเริ่มต้น สมดุล)
- `"sync"`: บันทึกครบทุก step ก่อนไปต่อ (ทนที่สุด ช้าสุด)

เรื่องที่ต้องระวัง: ขั้นที่ล่มจะรัน **ใหม่ทั้งขั้น** ผลข้างเคียงในขั้นนั้นต้องปลอดภัยเมื่อซ้ำ (idempotent)

## ดูตัวอย่าง
`durable.ts` มี graph 3 ขั้นที่ขั้นกลางล่มครั้งแรก ขาดการรันแบบ `sync` และการทำต่อหลังล่ม บทนี้ไม่ใช้ LLM

## คุณทำได้แล้ว
- ทำต่อจากจุดล่มโดยไม่ทำขั้นที่สำเร็จแล้วซ้ำ

## ข้อควรจำ
- ในบทนี้ทั้งสามโหมดให้ผลเหมือนกัน เพราะ error เกิดจาก node ภายในโปรเซสที่ยังมีชีวิตอยู่ ความต่างจะเห็นเมื่อโปรเซสตายจริง (ซึ่งบทนี้จำลองไม่ได้)
- งานยาว/แพงควรใช้ checkpointer ที่เก็บถาวร (ไฟล์/ฐานข้อมูล) เพื่อรอดแม้โปรเซสตาย
- ใช้ `thread_id` เดิมเสมอเมื่อต้องการทำต่อ
