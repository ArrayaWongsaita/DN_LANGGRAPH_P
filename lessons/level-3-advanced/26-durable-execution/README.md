# บทที่ 3-26 durable execution (ทนต่อการล่มกลางทาง)

## แนวคิด

เพราะ checkpointer บันทึกทุก step LangGraph จึง **ทำต่อจากจุดที่ล่ม** ได้: ถ้า graph มี 3 ขั้นแล้วขั้นที่ 3 ล่ม (เครือข่าย, โปรแกรมถูกปิด) ขั้นที่ 1-2 ที่สำเร็จแล้ว **ไม่ต้องทำใหม่** (ไม่เสียค่า LLM ซ้ำ) แค่เรียกต่อด้วย input เป็น `null` และ `thread_id` เดิม:

```ts
try { await graph.invoke(input, cfg); } catch { /* ล่ม */ }
await graph.invoke(null, cfg);   // ทำต่อจากขั้นที่ล่ม
```
ตัวเลือก `durability` ตอน invoke ควบคุมจังหวะบันทึก:
- `"exit"`: บันทึกตอนจบ (เร็วสุด แต่ถ้าโปรเซสตายกลางทาง ความคืบหน้าระหว่างทางอาจไม่ถูกบันทึก)
- `"async"`: บันทึกแบบไม่รอ (ค่าเริ่มต้น สมดุล)
- `"sync"`: บันทึกครบทุก step ก่อนไปต่อ (ทนที่สุด ช้าสุด)

เรื่องที่ต้องระวัง: ขั้นที่ล่มจะรัน **ใหม่ทั้งขั้น** ผลข้างเคียงในขั้นนั้นต้องปลอดภัยเมื่อซ้ำ (idempotent)

## 1. ลองเติมช่องเดียว

เปิด [`durable.ts`](./durable.ts) แล้วเติมข้อ 1: ทำงานต่อหลังล่มด้วย `invoke(null, config)` ที่ `thread_id` เดิม รันจากโฟลเดอร์หลักของโปรเจกต์ บทนี้ไม่เรียกโมเดลจริง รันได้โดยไม่ต้องมี API key

```sh
pnpm lesson 3-26
```

ในไฟล์ข้อ 1 มี **แนวทาง** เป็นโค้ดที่คอมเมนต์ไว้ เอา `//` ออกแล้วแทนที่ `todo(1)` ได้เลย แต่ลองอ่านก่อนว่าแต่ละบรรทัดทำอะไร

ในไฟล์มี graph 3 ขั้นที่ขั้นกลางล่มครั้งแรก และการรันครั้งแรกด้วย `durability: "sync"` ให้แล้ว ขาดแค่การเรียกต่อ

โค้ดตามแนวทาง:

```ts
const finished = await job.invoke(null, config);
```

## 2. ผลที่ได้

ผลที่รันจากเฉลย

```text
{ crashed: true, runs: { one: 1, two: 2, three: 1 }, log: '123' }
✅ งานล่มที่ขั้นสอง
✅ ทำต่อได้ครบ ได้ log 123
✅ ขั้นหนึ่งที่เสร็จไปแล้วไม่ถูกรันซ้ำ (รันแค่ครั้งเดียว)
✅ ขั้นสองถูกลองใหม่ (รัน 2 ครั้ง) ขั้นสามรันครั้งเดียว
```

สิ่งที่ได้: ทำต่อจากจุดล่มโดยไม่ทำขั้นที่สำเร็จแล้วซ้ำ

## 3. ส่วนประกอบที่ใช้ในบทนี้

| อาร์กิวเมนต์ | ค่า | ผล |
|---|---|---|
| input | `null` | ใช้ State ที่ checkpoint บันทึกไว้ ไม่เริ่มใหม่ |
| config | `thread_id` เดิม | ชี้ thread ที่ล่มกลางทาง |
| ขั้นที่สำเร็จแล้ว | — | ไม่รันซ้ำ จึงไม่เสียค่าโมเดลซ้ำ |

## ข้อควรจำ

- ในบทนี้ทั้งสามโหมดให้ผลเหมือนกัน เพราะ error เกิดจาก node ภายในโปรเซสที่ยังมีชีวิตอยู่ ความต่างจะเห็นเมื่อโปรเซสตายจริง (ซึ่งบทนี้จำลองไม่ได้)
- งานยาว/แพงควรใช้ checkpointer ที่เก็บถาวร (ไฟล์/ฐานข้อมูล) เพื่อรอดแม้โปรเซสตาย
- ใช้ `thread_id` เดิมเสมอเมื่อต้องการทำต่อ
