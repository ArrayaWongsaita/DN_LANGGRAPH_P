# บทที่ 3-03 Send แตกงานออกเป็นหลายสาย (fan-out)

## แนวคิด

บางครั้งจำนวนงานย่อย **ไม่รู้ล่วงหน้า**: มีเอกสาร 3 ชิ้นก็ต้องทำ 3 งาน มี 100 ชิ้นก็ 100 งาน edge ปกติผูกกับ node ที่ตายตัว จึงใช้ **`Send`** ที่สั่ง "รัน node นี้ด้วย input ก้อนนี้" ได้หลายครั้งในคราวเดียว:

```ts
.addConditionalEdges(START, (state) => state.items.map((item) => new Send("work", { item })), ["work"])
```
- router คืน **รายการ `Send`** แต่ละอันคือหนึ่งงาน (ชื่อ node, input ของงานนั้น)
- node `work` ทำงานขนานกัน แต่ละงานได้ input ของตัวเอง (`{ item }` ไม่ใช่ State ทั้งก้อน)
- ผลจากทุกงานรวมเข้า State ผ่าน **reducer** (บท 17 ของ Level 1) เพราะหลายงานเขียน field เดียวกันพร้อมกัน

## 1. ลองเติมช่องเดียว

เปิด [`fanout.ts`](./fanout.ts) แล้วเติมข้อ 1: คืนรายการ `Send` หนึ่งอันต่อหนึ่ง item รันจากโฟลเดอร์หลักของโปรเจกต์ บทนี้ไม่เรียกโมเดลจริง รันได้โดยไม่ต้องมี API key

```sh
pnpm lesson 3-03
```

ในไฟล์ข้อ 1 มี **แนวทาง** เป็นโค้ดที่คอมเมนต์ไว้ เอา `//` ออกแล้วแทนที่ `todo(1)` ได้เลย แต่ลองอ่านก่อนว่าแต่ละบรรทัดทำอะไร

ในไฟล์มี State ที่ field `out` มี reducer รวมผล, node `work` ที่แปลง item เป็นตัวพิมพ์ใหญ่ และ edge ที่ต่อ router เข้ากับ node นั้นแล้ว ขาดแค่ router ที่แตกงาน

โค้ดตามแนวทาง:

```ts
return state.items.map((item) => new Send("work", { item }));
```

## 2. ผลที่ได้

ผลที่รันจากเฉลย

```text
{ three: [ 'A', 'B', 'C' ], five: [ 'X', 'Y', 'Z', 'W', 'V' ] }
✅ งานสามชิ้น ได้ผลครบ (ลำดับอาจต่างกัน)
✅ จำนวนชุดขึ้นกับข้อมูลตอนรัน (5 ชิ้น = 5 ผล)
```

สิ่งที่ได้: แตกงานแบบ dynamic ด้วย `Send` และรวมผลด้วย reducer

## 3. ส่วนประกอบที่ใช้ในบทนี้

| ค่า | ชนิด | หน้าที่ |
|---|---|---|
| `new Send("work", { item })` | ชื่อ node กับ input ของงานนั้น | สั่งให้ node `work` รันหนึ่งครั้งด้วย input ก้อนนี้ |
| ผลของ router | อาร์เรย์ของ `Send` | หนึ่งสมาชิกต่อหนึ่งงาน ว่างคือไม่มีงาน |
| reducer ของ `out` | ฟังก์ชันรวมค่า | รวมผลของทุกงานที่เขียน field เดียวกันพร้อมกัน |

## ข้อควรจำ

- ลำดับผลลัพธ์ของงานขนานไม่รับประกัน ถ้าต้องเรียงให้เรียงทีหลัง
- ไม่มี item = ไม่มีงาน graph จบเลย (ผลว่าง)
