# บทที่ 3-08 defer (รอทุกสายเสร็จก่อนค่อยรัน)

## แนวคิด

เมื่อ graph แตกเป็นสายที่ **ยาวไม่เท่ากัน** แล้วไปรวมที่ node เดียว node รวมนั้นจะรันทันทีที่ "สายใดสายหนึ่ง" ส่งถึง ซึ่งอาจเร็วกว่าที่อยากได้:

```
START → a → b2 → b3 ─┐
START → b1 ──────────┴→ end     (สายสั้น b1 ถึง end ก่อนสายยาว b3)
```
ถ้า `end` ต้อง **รอทุกสายเสร็จจริง ๆ** (เช่น รวมผล) ให้ทำเครื่องหมาย `defer: true` ที่ node นั้น: LangGraph จะเลื่อนมันไปรันเมื่อไม่มีงานอื่นค้างแล้ว

```ts
.addNode("end", fn, { defer: true })
```

## 1. ลองเติมช่องเดียว

เปิด [`defer.ts`](./defer.ts) แล้วเติมข้อ 1: ทำให้ node `final` รอทุกสายเสร็จด้วย `{ defer: true }` รันจากโฟลเดอร์หลักของโปรเจกต์ บทนี้ไม่เรียกโมเดลจริง รันได้โดยไม่ต้องมี API key

```sh
pnpm lesson 3-08
```

ในไฟล์ข้อ 1 มี **แนวทาง** เป็นโค้ดที่คอมเมนต์ไว้ เอา `//` ออกแล้วแทนที่ `todo(1)` ได้เลย แต่ลองอ่านก่อนว่าแต่ละบรรทัดทำอะไร

ในไฟล์มี graph สองสายที่ยาวไม่เท่ากันและไปรวมที่ `final` ให้แล้ว ขาดแค่ option `defer` ที่ `final`

โค้ดตามแนวทาง:

```ts
{ defer: true },
```

## 2. ผลที่ได้

ผลที่รันจากเฉลย

```text
[ 'a', 'b1', 'b2', 'b3', 'final' ]
✅ ทุก node ทำงานครบ
✅ final ทำงานเป็นขั้นสุดท้าย หลังสายยาวเสร็จ (b3 มาก่อน final)
```

สิ่งที่ได้: ทำให้ node รวมผลรอทุกสายด้วย `defer`

## 3. ส่วนประกอบที่ใช้ในบทนี้

| ตัวเลือกของ node | ค่า | ผล |
|---|---|---|
| ไม่ใส่ `defer` | — | `final` รันทันทีที่สายใดสายหนึ่งส่งถึง |
| `{ defer: true }` | `true` | `final` รอจนทุกสายที่ยังรันอยู่เสร็จก่อน |

## ข้อควรจำ

- ถ้าทุกสายยาวเท่ากัน ไม่ต้องใช้ `defer`
- `defer` ใช้กับ node ที่ต้องเห็นผลครบทุกสายเท่านั้น
