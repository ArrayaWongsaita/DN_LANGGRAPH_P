# บทที่ 3-17 parallelization (ตรวจหลายด้านพร้อมกัน)

## แนวคิด

เมื่อมีงานย่อย **ที่ไม่ขึ้นต่อกัน** หลายอย่างบนข้อมูลชุดเดียว (ตรวจความปลอดภัย + ตรวจน้ำเสียง + สรุปความยาว) ไม่ต้องรอทีละอัน ให้แตกเป็นหลาย node ที่เริ่มพร้อมกันแล้วค่อยรวมผล เรียกว่า parallelization (แบบ sectioning):

```
        ┌→ checkSafety ─┐
START ──┼→ checkTone ───┼→ report → END
        └→ checkLength ─┘
```
ใน LangGraph ทำได้ด้วย **หลาย edge ที่ออกจาก node เดียวกัน** (หรือจาก `START`) node ที่ edge เข้ามาจากหลายทาง จะรันใน step ถัดจากที่มีทางใดทางหนึ่งส่งมาถึง ในบทนี้ทุกสายยาวเท่ากันจึงมาพร้อมกัน (ถ้าสายยาวไม่เท่ากัน ต้องรอด้วย `defer` ตามบท 3-08 หรือ `addEdge([...], node)`) แต่ละ node เขียน field ของตัวเอง จึงไม่ชนกัน

## 1. ลองเติมช่องเดียว

เปิด [`parallel.ts`](./parallel.ts) แล้วเติมข้อ 1: เพิ่ม edge จาก `START` ไปทั้งสาม node ตรวจ และจากทั้งสามไป `makeReport` รันจากโฟลเดอร์หลักของโปรเจกต์ บทนี้เรียกโมเดลจริง ตั้ง provider และ API key ใน `.env` ตาม [บท 1-02](../../level-1-basics/02-llm-config/README.md) ก่อนรัน

```sh
pnpm lesson 3-17
```

ในไฟล์ข้อ 1 มี **แนวทาง** เป็นโค้ดที่คอมเมนต์ไว้ เอา `//` ออกแล้วแทนที่ `todo(1)` ได้เลย แต่ลองอ่านก่อนว่าแต่ละบรรทัดทำอะไร

ในไฟล์มี node ตรวจสามด้าน (`checkSafety`, `checkTone`, `checkLength`) และ `makeReport` ที่รวมผลให้แล้ว ขาดแค่เส้นเชื่อมทั้งหมด

โค้ดตามแนวทาง:

```ts
for (const node of ["checkSafety", "checkTone", "checkLength"] as const) {
  builder.addEdge(START, node);
  builder.addEdge(node, "makeReport");
}
```

## 2. ผลที่ได้

ตัวอย่างผลที่รันจากเฉลย ข้อความจากโมเดลเปลี่ยนได้ทุกรอบ

```text
ใช้เวลา 60658 ms
ปลอดภัย ไม่มีเนื้อหาอันตรายหรือหลอกลวง | น้ำเสียงเชิงบวก ชื่นชม พอใจ และแนะนำอย่างสุภาพครับ | 48 ตัวอักษร (รวมช่องว่าง) / 46 ตัวอักษร (ไม่รวมช่องว่าง)
✅ ทั้งสามตัวตรวจทำงาน (ได้ผลทั้ง safety tone length)
✅ makeReport รอรวมผลครบทั้งสาม (มีตัวคั่น | สองตัว)
```

สิ่งที่ได้: รันงานย่อยที่ไม่ขึ้นต่อกันพร้อมกันแล้วรวมผล

## 3. ส่วนประกอบที่ใช้ในบทนี้

| เส้นที่ต้องเพิ่ม | จาก | ไป |
|---|---|---|
| แตกสาย | `START` | `checkSafety`, `checkTone`, `checkLength` (ทั้งสามเริ่มพร้อมกัน) |
| รวมสาย | แต่ละ node ตรวจ | `makeReport` (รอให้ทั้งสามสายถึงก่อนรัน) |

## ข้อควรจำ

- ขนานช่วยเรื่องเวลา ไม่ได้ช่วยเรื่องจำนวนครั้งที่เรียก LLM (ยังจ่ายเท่ากัน)
- งานที่ขึ้นต่อกันห้ามขนาน
