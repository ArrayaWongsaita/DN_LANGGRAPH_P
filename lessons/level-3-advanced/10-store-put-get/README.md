# บทที่ 3-10 ความจำระยะยาว (Store) เก็บและอ่านค่า

## แนวคิด

ความจำใน Level 2 (checkpointer) ผูกกับ **thread เดียว** เปิดบทสนทนาใหม่ = เริ่มจากศูนย์ แต่บางอย่างควรจำ **ข้ามบทสนทนา**: ชื่อของผู้ใช้ ภาษาที่ชอบ ข้อเท็จจริงที่เคยบอกไว้ ที่เก็บแบบนี้เรียกว่า **Store** (ความจำระยะยาว) ลักษณะเหมือนฐานข้อมูลคีย์-ค่า:

```ts
const store = new InMemoryStore();
await store.put(["users", "u1"], "prefs", { lang: "th" }); // (namespace, key, value)
const item = await store.get(["users", "u1"], "prefs");     // item?.value = { lang: "th" }
```
- **namespace** = รายการสตริง เหมือนเส้นทางโฟลเดอร์ (บท 3-11)
- **key** = ชื่อของรายการภายใน namespace
- **value** = อ็อบเจ็กต์ JSON
- `get` ที่ไม่เจอได้ `null`

`InMemoryStore` เก็บใน RAM เหมาะกับเรียนรู้ ของจริงใช้ store ที่เก็บลงฐานข้อมูล (หน้าตาเหมือนกัน)

## 1. ลองเติมช่องเดียว

เปิด [`store.ts`](./store.ts) แล้วเติมข้อ 1: บันทึกโปรไฟล์ด้วย `store.put` ลงใน namespace `["profiles"]` รันจากโฟลเดอร์หลักของโปรเจกต์ บทนี้ไม่เรียกโมเดลจริง รันได้โดยไม่ต้องมี API key

```sh
pnpm lesson 3-10
```

ในไฟล์ข้อ 1 มี **แนวทาง** เป็นโค้ดที่คอมเมนต์ไว้ เอา `//` ออกแล้วแทนที่ `todo(1)` ได้เลย แต่ลองอ่านก่อนว่าแต่ละบรรทัดทำอะไร

ในไฟล์มี `InMemoryStore`, ข้อมูลโปรไฟล์ของมาลี และโค้ดที่อ่านกลับด้วย `store.get` ให้แล้ว ขาดแค่ขั้นบันทึก

โค้ดตามแนวทาง:

```ts
await store.put(["profiles"], "mali", profile);
```

## 2. ผลที่ได้

ผลที่รันจากเฉลย

```text
{ found: { name: 'มาลี', lang: 'th' }, missing: null }
✅ อ่านโปรไฟล์ที่เก็บไว้ได้ตรงกัน
✅ key ที่ไม่มีได้ค่าว่าง (null)
```

สิ่งที่ได้: เก็บและอ่านความจำระยะยาวด้วย `put` / `get`

## 3. ส่วนประกอบที่ใช้ในบทนี้

| เมธอด | รับ | ได้ |
|---|---|---|
| `store.put(namespace, key, value)` | namespace เป็นอาร์เรย์สตริง, key เป็นสตริง, value เป็นออบเจ็กต์ | บันทึกหรือเขียนทับค่าของ key นั้น |
| `store.get(namespace, key)` | namespace และ key เดียวกัน | item (ใช้ `item?.value`) หรือ `null` ถ้าไม่มี |

## ข้อควรจำ

- Store ไม่ผูกกับ thread: ใช้ร่วมได้ทุกบทสนทนา
- `put` กับ key เดิมคือเขียนทับ
