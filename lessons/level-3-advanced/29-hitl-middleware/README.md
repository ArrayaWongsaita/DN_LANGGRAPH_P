# บทที่ 3-29 human-in-the-loop middleware

## แนวคิด

ในบท 2-21 คุณใส่ `interrupt` ไว้ใน tool แต่ละตัว ถ้ามีหลาย tool ที่ต้องขออนุมัติ จะซ้ำซ้อน **`humanInTheLoopMiddleware`** ดักการเรียก tool ที่ระบุไว้ให้ agent หยุดรออนุมัติเอง โดยไม่ต้องแก้ตัว tool:

```ts
humanInTheLoopMiddleware({ interruptOn: { sendEmail: true } }) // เฉพาะ tool ที่ระบุ
```
agent หยุดพร้อมรายการ `actionRequests` (tool + args ที่ขอเรียก) ผู้ตัดสินตอบด้วย `Command({ resume: { decisions: [...] } })` โดยหนึ่งการตัดสินต่อหนึ่งคำขอตามลำดับ:

```ts
{ type: "approve" }                                  // อนุมัติ รัน tool ตามที่ขอ
{ type: "reject", message: "ไม่ได้ครับ" }           // ปฏิเสธ แจ้งเหตุผลให้โมเดล
// มีแบบ "edit" (แก้ args) และ "respond" ด้วย
```
ต้องมี checkpointer เหมือน interrupt ทุกแบบ

## 1. ลองเติมช่องเดียว

เปิด [`hitl.ts`](./hitl.ts) แล้วเติมข้อ 1: ใส่ `humanInTheLoopMiddleware` ให้หยุดรออนุมัติก่อนเรียก `sendEmail` รันจากโฟลเดอร์หลักของโปรเจกต์ บทนี้เรียกโมเดลจริง ตั้ง provider และ API key ใน `.env` ตาม [บท 1-02](../../level-1-basics/02-llm-config/README.md) ก่อนรัน

```sh
pnpm lesson 3-29
```

ในไฟล์ข้อ 1 มี **แนวทาง** เป็นโค้ดที่คอมเมนต์ไว้ เอา `//` ออกแล้วแทนที่ `todo(1)` ได้เลย แต่ลองอ่านก่อนว่าแต่ละบรรทัดทำอะไร

ในไฟล์มี tool `sendEmail` (ไม่มี `interrupt` ในตัว), `MemorySaver` และโค้ดที่ส่งคำตัดสินกลับด้วย `Command({ resume })` ให้แล้ว ขาดแค่การติด middleware

โค้ดตามแนวทาง:

```ts
middleware: [humanInTheLoopMiddleware({ interruptOn: { sendEmail: true } })],
```

## 2. ผลที่ได้

ตัวอย่างผลที่รันจากเฉลย ข้อความจากโมเดลเปลี่ยนได้ทุกรอบ

```text
  paused: [ true, true ],
  sent: [ 'mali@example.com' ],
  finals: [
    'เรียบร้อยครับ ส่งอีเมลถึง mali@example.com เรียบร้อยแล้วนะครับ 📧
' +
      '
' +
      'หากต้องการให้ส่งเนื้อหาหรือหัวข้ออะไรเพิ่มเติม หรือมีผู้รับคนอื่นอีก บอกได้เลยครับ',
    'ผมได้เรียกใช้ tool `sendEmail` ไปยัง somchai@example.com แล้วครับ แต่ผลลัพธ์ที่ได้คือ **"ไม่อนุมัติ"** — หมายความว่าการส่งอีเมลครั้งนี้ไม่ได้รับอนุญาต จึงยังไม่ได้ส่งออกไปครับ
' +
      '
' +
      'หากต้องการให้ผมลองอีกครั้ง หรือมีข้อมูลเพิ่มเติม (เช่น ต้องขออนุมัติจากใคร หรือเปลี่ยนผู้รับ) แจ้งได้เลยครับ'
  ]
✅ agent หยุดรออนุมัติก่อนส่ง (ทั้งสอง thread)
✅ อนุมัติแล้วส่งจริงเฉพาะรายที่อนุมัติ
✅ agent ตอบสรุปหลังจบทั้งสองรอบ
```

สิ่งที่ได้: กั้น tool อันตรายด้วย middleware โดยไม่แก้ตัว tool

## 3. ส่วนประกอบที่ใช้ในบทนี้

| ส่วน | ตัวอย่าง | หน้าที่ |
|---|---|---|
| `interruptOn` | `{ sendEmail: true }` | ระบุ tool ที่ต้องหยุดรอก่อนรัน tool อื่นรันได้เลย |
| resume | `new Command({ resume: { decisions: [...] } })` | ส่งคำตัดสินหนึ่งรายการต่อหนึ่งคำขอที่หยุดรอ |

## ข้อควรจำ

- tool ที่ไม่อยู่ใน `interruptOn` รันได้เลยไม่ต้องรอ
- จำนวนคำตัดสินต้องเท่าจำนวนคำขอที่หยุดรอ
