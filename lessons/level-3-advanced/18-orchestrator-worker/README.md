# บทที่ 3-18 orchestrator-worker (ผู้วางแผน + คนงาน)

## แนวคิด

เมื่อ **ไม่รู้ล่วงหน้าว่างานย่อยมีอะไรบ้าง** (ต่างจาก 3-17 ที่รู้ว่ามี 3 ด้าน) ให้ LLM ตัวหนึ่งเป็น **orchestrator** วางแผนแตกงานย่อย แล้วส่งให้ **worker** แต่ละตัวทำ แล้วรวมผล: เป็นการประกอบของ `withStructuredOutput` (บท 08) + `Send` (บท 3-03) + ขั้นสังเคราะห์

```
plan (LLM แตกเป็นรายการ tasks) ─Send ต่อ task→ worker (×N) → synthesize (LLM รวมเป็นรายงาน)
```
ต่างจาก map-reduce (3-04) ตรงที่จำนวนและเนื้อหาของงานย่อย **LLM เป็นคนกำหนด**

## 1. ลองเติมช่องเดียว

เปิด [`orchestrator.ts`](./orchestrator.ts) แล้วเติมข้อ 1: คืนรายการ `Send` หนึ่งอันต่อหนึ่งงานย่อยที่ orchestrator วางแผนไว้ รันจากโฟลเดอร์หลักของโปรเจกต์ บทนี้เรียกโมเดลจริง ตั้ง provider และ API key ใน `.env` ตาม [บท 1-02](../../level-1-basics/02-llm-config/README.md) ก่อนรัน

```sh
pnpm lesson 3-18
```

ในไฟล์ข้อ 1 มี **แนวทาง** เป็นโค้ดที่คอมเมนต์ไว้ เอา `//` ออกแล้วแทนที่ `todo(1)` ได้เลย แต่ลองอ่านก่อนว่าแต่ละบรรทัดทำอะไร

ในไฟล์มี orchestrator ที่ให้โมเดลแตกงานเป็นรายการ `tasks`, `worker` ที่ทำงานแต่ละชิ้น และขั้นสังเคราะห์ผลให้แล้ว ขาดแค่ตัวแตกงานด้วย `Send`

โค้ดตามแนวทาง:

```ts
return state.tasks.map((task) => new Send("worker", { task }));
```

## 2. ผลที่ได้

ตัวอย่างผลที่รันจากเฉลย ข้อความจากโมเดลเปลี่ยนได้ทุกรอบ

```text
งานย่อย: [ 'แตกเป้าหมาย: จัดงานเลี้ยงวันเกิดเล็ก ๆ ที่บ้าน เป็นงานย่อยสั้น ๆ' ]
รายงาน: **รายงานสรุปการเตรียมงาน**

การเตรียมงานแบ่งออกเป็น 3 ระยะ ดังนี้  
1. **วางแผนงาน** กำหนดวัน เวลา และจำนวนแขก ตั้งงบประมาณ วางเมนูอาหาร ของว่าง และเครื่องดื่ม พร้อมสั่งเค้กและจัดซื้อของที่จำเป็น  
2. **เตรียมความพร้อมก่อนงาน** เตรียมของตกแต่งและภาชนะ ทำความสะอาดบ้าน ส่งคำเชิญและยืนยันแขก เตรียมกิจกรรม/เพลง และเตรียมกล้องถ่ายรูป  
3. **หลังเสร็จงาน** ดำเนินการเก็บกวาดและทำความสะอาดสถานที่จัดงาน  

**สรุป:** การเตรียมงานครอบคลุมตั้งแต่การวางแผน งบประมาณ อาหาร การเชิญแขก การเตรียมสถานที่ อุปกรณ์ กิจกรรม จนถึงการเก็บกวาดหลังงาน เพื่อให้งานดำเนินไปอย่างเรียบร้อยและครบถ้วน
✅ แผนมีงานย่อย 1-3 ข้อ
✅ worker ทำงานครบทุกงานย่อย
✅ ได้รายงานรวมที่ไม่ว่าง
```

สิ่งที่ได้: สร้างระบบที่ให้ LLM วางแผนแล้วแตกงานให้คนงานขนานกัน

## 3. ส่วนประกอบที่ใช้ในบทนี้

| บทบาท | ทำอะไร | ใช้โมเดลหรือไม่ |
|---|---|---|
| orchestrator | วางแผนว่ามีงานย่อยอะไรบ้าง | ใช้ (ผลมีโครงสร้าง `tasks`) |
| แตกงาน | สร้าง `Send("worker", { task })` ต่อหนึ่งงาน | ไม่ใช้ เป็นช่องที่คุณเติม |
| worker | ทำงานย่อยหนึ่งชิ้น | ใช้ |
| synthesizer | รวมผลเป็นรายงาน | ใช้ |

## ข้อควรจำ

- จำกัดจำนวนงานย่อยสูงสุด ไม่งั้น LLM แตกงานมหาศาลแล้วค่าใช้จ่ายพุ่ง
- คนงานต้องได้ข้อมูลครบใน input ของ `Send` เพราะไม่เห็น State ทั้งก้อน
