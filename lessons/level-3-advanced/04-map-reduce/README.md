# บทที่ 3-04 map-reduce (แตก ทำขนาน แล้วรวม)

## แนวคิด

รูปแบบยอดนิยมจาก 3-03: **map** แตกงานให้แต่ละชิ้นทำเอง แล้ว **reduce** รวมผลทุกชิ้นเป็นผลเดียว ใช้กับงานอย่าง "สรุปเอกสารทีละฉบับแล้วรวมเป็นรายงานเดียว" (ที่นี่ใช้การนับคำเพื่อให้ผลแน่นอนและทดสอบได้ ของจริงเปลี่ยนเป็นเรียก LLM)

```
START ─Send→ countWords (×N ขนานกัน) → total (รวมผล) → END
```
node `total` ต่อท้าย `countWords` ด้วย edge ปกติ LangGraph จะรอให้ **ทุกงานที่แตกออกไปเสร็จก่อน** แล้วค่อยรัน `total` หนึ่งครั้ง

## 1. ลองเติมช่องเดียว

เปิด [`mapreduce.ts`](./mapreduce.ts) แล้วเติมข้อ 1: แตกงานหนึ่งอันต่อหนึ่งเอกสารด้วย `Send` รันจากโฟลเดอร์หลักของโปรเจกต์ บทนี้ไม่เรียกโมเดลจริง รันได้โดยไม่ต้องมี API key

```sh
pnpm lesson 3-04
```

ในไฟล์ข้อ 1 มี **แนวทาง** เป็นโค้ดที่คอมเมนต์ไว้ เอา `//` ออกแล้วแทนที่ `todo(1)` ได้เลย แต่ลองอ่านก่อนว่าแต่ละบรรทัดทำอะไร

ในไฟล์มีขั้น map (`countWords` นับคำของเอกสารหนึ่งฉบับ) และขั้น reduce (`sum` รวมผล) ให้แล้ว ขาดแค่ router ที่แตกงานจาก `START`

โค้ดตามแนวทาง:

```ts
return state.docs.map((doc) => new Send("countWords", { doc }));
```

## 2. ผลที่ได้

ผลที่รันจากเฉลย

```text
  docs: [ 'one two three', 'four five', 'six' ],
  counts: [ 3, 2, 1 ],
  total: 6
✅ map: นับคำของแต่ละเอกสารได้ครบ
✅ reduce: total = 6
```

สิ่งที่ได้: สร้างงาน map-reduce แบบ dynamic

## 3. ส่วนประกอบที่ใช้ในบทนี้

| ขั้น | ทำอะไร | ในบทนี้ |
|---|---|---|
| แตกงาน | สร้าง `Send` หนึ่งอันต่อเอกสาร | ช่องที่คุณเติม |
| map | แต่ละงานทำกับเอกสารของตัวเอง | `countWords` คืน `{ counts: จำนวนคำ }` |
| reduce | รวมผลของทุกงาน | `sum` คืน `{ total: ผลรวมของ counts }` |

## ข้อควรจำ

- ขั้น reduce เห็นผลของ map ทุกชิ้นใน State เพราะ reducer รวมไว้ให้
- map ต้องไม่ขึ้นต่อกัน ถึงขนานได้
