# บทที่ 3-19 evaluator-optimizer (เขียน ตรวจ แก้ วนจนผ่าน)

## แนวคิด

ให้ LLM ตัวหนึ่ง **เขียน** อีกตัว (หรือตัวเดียวกันคนละหน้าที่) **ตรวจ** แล้วส่งข้อติกลับไปให้เขียนใหม่ วนจนผ่านหรือครบจำนวนรอบ เป็นลูปที่คุณรู้จักจากบท 16 ของ Level 1 แต่ผู้ตัดสินเป็น LLM ที่ตอบเป็นข้อมูลมีโครงสร้าง:

```
generate → evaluate ─ผ่าน/ครบรอบ→ END
              └ไม่ผ่าน→ generate (พร้อมข้อติ)
```
- `evaluate` คืน `{ approved: boolean, feedback: string }` ด้วย `withStructuredOutput`
- รอบถัดไปของ `generate` ต้อง **ใส่ข้อติลงใน prompt**
- ต้องมี **เพดานรอบ** เสมอ (ผู้ตรวจไม่พอใจตลอดกาลก็ต้องหยุด)

## 1. ลองเติมช่องเดียว

เปิด [`optimizer.ts`](./optimizer.ts) แล้วเติมข้อ 1: เขียนตัวเลือกทางของลูป: จบเมื่ออนุมัติหรือครบรอบ ไม่เช่นนั้นกลับไปเขียนใหม่ รันจากโฟลเดอร์หลักของโปรเจกต์ บทนี้เรียกโมเดลจริง ตั้ง provider และ API key ใน `.env` ตาม [บท 1-02](../../level-1-basics/02-llm-config/README.md) ก่อนรัน

```sh
pnpm lesson 3-19
```

ในไฟล์ข้อ 1 มี **แนวทาง** เป็นโค้ดที่คอมเมนต์ไว้ เอา `//` ออกแล้วแทนที่ `todo(1)` ได้เลย แต่ลองอ่านก่อนว่าแต่ละบรรทัดทำอะไร

ในไฟล์มี node `generate` (เขียนตามข้อติ), node `evaluate` (ตัดสินเป็น `approved` กับ `feedback`) และเพดาน `MAX_ROUNDS` = 3 ให้แล้ว ขาดแค่ฟังก์ชันตัดสินว่าจะวนต่อหรือจบ

โค้ดตามแนวทาง:

```ts
return state.approved || state.round >= MAX_ROUNDS ? END : "generate";
```

## 2. ผลที่ได้

ตัวอย่างผลที่รันจากเฉลย ข้อความจากโมเดลเปลี่ยนได้ทุกรอบ

```text
วนไป 2 รอบ อนุมัติ=true
ร่างสุดท้าย: ฉบับแก้ไข:

- ผู้ใหญ่ทั่วไปดื่มน้ำประมาณ 8 แก้ว/วัน (ราว 2 ลิตร) และเพิ่มหากออกกำลังกายหรืออากาศร้อน
- แบ่งดื่มง่าย ๆ เช่น ตื่นนอน 1 แก้ว ก่อนมื้ออาหาร 1 แก้ว ตั้งขวดน้ำ 1 ลิตรดื่มให้หมดช่วงเช้า และก่อนนอน 1 แก้ว
- ตัวอย่างจริง: พนักงานออฟฟิศที่นั่งทำงานนานตั้งเตือนดื่มน้ำทุก 1 ชั่วโมง พบว่าอาการปวดหัวช่วงบ่ายลดลง
- สังเกตว่าดื่มพอหรือไม่จากปัสสาวะสีเหลืองอ่อนและไม่รู้สึกกระหายจัดตลอดวัน
- ผู้มีโรคไต/หัวใจควรปรึกษาแพทย์ก่อนปรับปริมาณน้ำดื่ม
ข้อติล่าสุด: ผ่านตามเงื่อนไข "ต้องมีตัวอย่างประกอบ" — เนื้อหามีตัวอย่างจริงเป็นรูปธรรมชัดเจน 1 กรณี คือพนักงานออฟฟิศที่ตั้งเตือนดื่มน้ำทุก 1 ชั่วโมง แล้วอาการปวดหัวช่วงบ่ายลดลง ซึ่งทำหน้าที่เป็นตัวอย่

ข้อสังเกต/ข้อเสนอแนะเล็กน้อย (ไม่ถึงขั้นไม่ผ่าน):
1) ตัวอย่างพนักงานออฟฟิศเป็นข้อมูลเชิงประสบการณ์ (anecdotal) ควรระบุให้ชัดว่าเป็น "ตัวอย่างเชิงillustration" ไม่ใช่หลักฐานทางวิชาการ เพื่อไม่ให้ผู้อ่านเหมารวมว่าการตั้งเตือนดื่มน้ำรักษาอาการปวดหัวได้
2) "ก่อนนอน 1 แก้ว" อาจทำให้บางคนต้องตื่นปัสสาวะกลางคืน ควรเพิ่มหมายเหตุว่าปรับเวลา/ปริมาณได้ตามความเหมาะสม
3) ปริมาณ 2 ลิตรควรย้ำว่าเป็นน้ำดื่มทั้งหมดโดยประมาณ และของเหลวจากอาหาร/เครื่องดื่มอื่นก็มีส่วน ตัวเลข 8 แก้วเป็นแนวทางกว้าง ๆ ไม่ใช่เกณฑ์ตายตัว
4) เกณฑ์ "ปัสสาวะสีเหลืองอ่อน + ไม่กระหายจัดตลอดวัน" เป็นเกณฑ์สังเกตตนเองที่เหมาะสมแล้ว และการเตือนให้ผู้มีโรคไต/หัวใจปรึกษาแพทย์ก่อนก็เป็นข้อควรระวังที่ครบถ้วน

สรุป: เนื้อหาครบองค์ประกอบ (หลักปฏิบัติ + วิธีแบ่งดื่ม + ตัวอย่างจริง + วิธีประเมินตนเอง + ข้อควรระวัง) และมีตัวอย่างประกอบจริง จึงอนุมัติให้ผ่าน
✅ วนอย่างน้อย 1 รอบและไม่เกิน 3 รอบ
✅ ได้ร่างที่ไม่ว่าง
✅ จบเพราะอนุมัติ หรือครบรอบ (ไม่หยุดกลางคัน)
```

สิ่งที่ได้: สร้างลูปเขียน-ตรวจ-แก้ที่มีเพดานรอบ

## 3. ส่วนประกอบที่ใช้ในบทนี้

| เงื่อนไข | ทางที่เลือก | เหตุผล |
|---|---|---|
| `state.approved` เป็นจริง | `END` | ผู้ตรวจยอมรับแล้ว |
| `state.round >= MAX_ROUNDS` | `END` | ครบเพดานรอบ กันลูปไม่รู้จบและค่าใช้จ่ายพุ่ง |
| นอกเหนือจากสองข้อบน | `"generate"` | ส่งข้อติกลับไปเขียนใหม่ |

## ข้อควรจำ

- ผู้ตรวจที่เข้มเกินไป = เสียเงินครบทุกรอบเสมอ ตั้งเกณฑ์ให้ชัดเจนและวัดได้
- คืนข้อความสุดท้ายแม้ไม่ผ่าน เพื่อให้คนตัดสินต่อ
