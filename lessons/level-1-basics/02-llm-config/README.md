# บทที่ 1-02 สร้าง chat model จากค่าที่ตั้งไว้

[บท 1-01](../01-env-schema/README.md) ส่งออก `env` ที่ตรวจแล้ว บทนี้ใช้ชื่อโมเดลและ API key เพื่อสร้าง `llm` ตัวเดียวให้ไฟล์บทอื่น import ไปเรียกได้

## 1. สร้างตัวเรียกโดยยังไม่ส่งคำขอ

เติม [บท 1-01](../01-env-schema/README.md) ให้เสร็จ ตั้ง `LLM_PROVIDER` กับ API key ที่ตรงกันใน `.env` ตาม [`.env.example`](../../../.env.example) แล้วเปิด [`llm.ts`](./llm.ts) เติมข้อ 1 ใช้ `getLLM` โดยส่ง `model` จาก `env.LLM_MODEL` หรือ `undefined` ถ้าค่านี้ว่าง รันจากโฟลเดอร์หลักของโปรเจกต์ การสร้างตัวเรียกในบทนี้ยังไม่ใช้เครือข่าย

```sh
pnpm lesson 1-02
```

`env` มาจากบท 1-01 ส่วน `getLLM` ของคอร์สเลือกตัวสร้าง chat model และ key ให้ตาม `LLM_PROVIDER`

```ts
export const llm: BaseChatModel = getLLM({ model: env.LLM_MODEL || undefined });
```

เมื่อใส่ `LLM_MODEL=demo-model` จะได้ผลต่อไปนี้ บรรทัดแรกแสดงค่าที่ตั้งไว้ ตัวอย่างนี้ตรวจการสร้างตัวเรียก ส่วนชื่อที่บริการรองรับและสิทธิ์ของ key จะตรวจตอนเรียกในบทถัดไป

```text
โมเดล demo-model
✅ สร้าง chat model ตามชื่อที่ตั้งไว้
```

## 2. เลือกค่าตรงไหน

| ค่า | ค่าที่ใส่ได้และค่าเริ่มต้น |
|---|---|
| `LLM_PROVIDER` | ใช้ค่าที่ระบุใน [`.env.example`](../../../.env.example) ค่าว่างใช้บริการเริ่มต้นของคอร์ส |
| API key | ใช้ตัวแปรที่ตรงกับ `LLM_PROVIDER` คอร์สตรวจว่าข้อความมีความยาวอย่างน้อย 10 ตัวอักษร |
| `LLM_MODEL` | ใส่ชื่อโมเดลที่บริการนั้นรองรับ ค่าว่างกลายเป็น `undefined` ที่จุดเรียก `getLLM` จึงเลือกโมเดลเริ่มต้นของบริการ |

## 3. เปลี่ยนชื่อโมเดลแล้วเทียบ

ใช้ `LLM_PROVIDER` และ API key ชุดเดิม ตั้ง `LLM_MODEL=demo-model` เพื่อดูชื่อที่ระบุ จากนั้นปล่อย `LLM_MODEL` ว่างแล้วรันซ้ำ รอบหลังพิมพ์ชื่อเริ่มต้นของบริการที่เลือก เมื่อจะเปลี่ยนบริการให้แก้ทั้ง `LLM_PROVIDER` และ key ที่ตรงกันใน `.env` แล้วตรวจว่า `LLM_MODEL` ใช้กับบริการใหม่ได้

ดู [เฉลย `llm.ts`](./solution/llm.ts) แล้วไป [บท 1-03 ส่งคำถามด้วย `invoke`](../03-first-llm-call/README.md)
