# บทที่ 1-04 เปรียบเทียบคำตอบเมื่อเปลี่ยน `temperature`

[บท 1-03](../03-first-llm-call/README.md) ถามโมเดลครั้งเดียว ลองขอให้โมเดลตั้งชื่อแมวสีส้มซ้ำหลายรอบ เพื่อดูว่าชื่อที่ได้เปลี่ยนแค่ไหนเมื่อปรับ `temperature`

## 1. ถามคำถามเดียวกันที่ค่า `0` และ `1`

เปิด [`temperature.ts`](./temperature.ts) แล้วเติมข้อ 1 ให้ `getLLM` สร้างโมเดลโดยใช้ `temperature` ของรอบนั้น รันจากโฟลเดอร์หลักของโปรเจกต์ ใช้ API key และโมเดลที่ตั้งใน `.env` ตาม [บท 1-02](../02-llm-config/README.md) เลือกโมเดลที่รองรับการกำหนด `temperature` และเชื่อมต่ออินเทอร์เน็ต บทนี้ถามโมเดลหกครั้ง

```sh
pnpm lesson 1-04
```

ในไฟล์ข้อ 1 มี **แนวทาง** เป็นโค้ดที่คอมเมนต์ไว้ เอา `//` ออกแล้วแทนที่ `todo(1)` ได้เลย แต่ลองอ่านก่อนว่าแต่ละบรรทัดทำอะไร

`question` และตัวนับรอบมีในไฟล์แล้ว ในแต่ละรอบของ `temperatures` โปรแกรมสร้างตัวเรียกหนึ่งตัวและถามตัวเดิมสามครั้ง

```ts
for (const temperature of temperatures) {
  const model = getLLM({ temperature });
  const answers: string[] = [];
  for (let i = 0; i < attempts; i++) {
    const reply = await model.invoke(question);
    answers.push(reply.text.trim());
  }
  console.log(`temperature ${temperature}`, answers, `มี ${new Set(answers).size} ชื่อที่ต่างกัน`);
}
```

ตัวอย่างผลที่อาจได้ ชื่อและจำนวนชื่อที่ต่างกันเปลี่ยนได้ในแต่ละรอบ

```text
temperature 0 [ 'ส้มจี๊ด', 'ส้มจี๊ด', 'ส้มจี๊ด' ] มี 1 ชื่อที่ต่างกัน
temperature 1 [ 'ส้มจี๊ด', 'ฟักทอง', 'ชาไทย' ] มี 3 ชื่อที่ต่างกัน
✅ ส่ง temperature ทั้งสองค่าให้โมเดล
✅ ได้คำตอบทั้งสามรอบของแต่ละค่า
```

โมเดลบางตัวตอบซ้ำแม้ตั้ง `temperature` เป็น `1` เช่นตอนทดสอบกับ `deepseek-v4.1-flash` ผ่าน OpenCode Go ได้ `'ส้มจี๊ด'` ทั้งหกครั้ง ถ้าเจอแบบนี้ ไม่ได้แปลว่าโค้ดผิด ให้ลองเพิ่ม `attempts` หรือเปลี่ยนเป็นคำถามปลายเปิดกว่านี้ใน `playground.ts` เช่น "ตั้งชื่อร้านกาแฟมา 1 ชื่อ"

## 2. ค่า `temperature` ใช้อย่างไร

`temperature` เป็นตัวเลขที่ส่งเข้า `getLLM({ temperature })` ค่าต่ำมักให้น้ำหนักกับคำที่โมเดลเห็นว่ามีโอกาสสูง ค่าที่สูงขึ้นเปิดโอกาสให้ได้คำทางเลือกมากขึ้น ช่วงที่รับได้และค่าเริ่มต้นเมื่อเว้น `temperature` ขึ้นกับบริการและโมเดล บางโมเดลรับเฉพาะค่าเริ่มต้น ถ้าบริการปฏิเสธ `0` หรือ `1` ให้เลือกโมเดลที่รองรับทั้งสองค่าใน `.env`

## 3. คงคำถามไว้แล้วเปลี่ยนค่าเดียว

ก่อนทดลอง ให้นำโค้ดจากเฉลยตั้งแต่หลัง import ถึงก่อนส่วนตรวจคำตอบไปใส่ใน `playground.ts`

ใน [playground](./playground.ts) ใช้คำถามเดิมเทียบ `0` กับ `0.5` แล้วนับชื่อที่ต่างกัน ดูว่าผลต่างจากรอบ `0` กับ `1` หรือไม่ แม้ `0` ก็อาจได้หลายชื่อ และค่าที่สูงขึ้นอาจได้ชื่อซ้ำ การตรวจท้ายไฟล์จึงดูว่าตั้งค่าครบและได้คำตอบครบทุกครั้ง
