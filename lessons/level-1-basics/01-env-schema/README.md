# บทที่ 1-01 ตรวจค่า `.env` ด้วย Zod

## 1. ทำไมต้องตรวจก่อนใช้

ใน [บท 0-01](../../level-0-fetch/01-first-fetch/README.md) โปรแกรมอ่าน key จาก environment ตรงๆ ถ้าลืมตั้ง key หรือพิมพ์ชื่อโมเดลมีช่องว่างติดมา จะรู้ก็ต่อเมื่อเรียก API แล้ว error ที่ได้มักอ่านยาก บทนี้ใช้ Zod ตรวจและจัดรูปค่าตั้งต้น **ก่อน** ส่งต่อให้บทที่สร้าง chat model ถ้าผิดจะหยุดทันทีพร้อมข้อความที่บอกว่าผิดที่ไหน

```text
.env  ──►  process.env  ──►  envSchema.safeParse  ──►  export env  ──►  บท 1-02
                              (ตัดช่องว่าง ใส่ค่าเริ่มต้น ตรวจ)
```

## 2. ลองอ่านชื่อโมเดลจาก `.env`

เปิด [`env.ts`](./env.ts) มี 1 ข้อให้เติม (ค้นหา `// 👉 ข้อ 1`) ให้ `envSchema.safeParse` ตรวจ `process.env`

เตรียมก่อนรัน: ติดตั้งแพ็กเกจด้วย `pnpm install` แล้วคัดลอก `.env.example` เป็น `.env` ด้วย `cp .env.example .env` ใส่ API key ของเจ้า LLM ที่คุณมีในตัวแปรที่ตรงกัน (ดูชื่อตัวแปรใน [`.env.example`](../../../.env.example)) จากนั้นรันจากโฟลเดอร์หลักของโปรเจกต์ บทนี้อ่านค่าในเครื่องและยังไม่ส่งคำขอไปที่ API

```sh
pnpm lesson 1-01
```

ในไฟล์ข้อ 1 มี **แนวทาง** เป็นโค้ดที่คอมเมนต์ไว้ เอา `//` ออกแล้วแทนที่ `todo(1)` ได้เลย แต่ลองอ่านก่อนว่าแต่ละบรรทัดทำอะไร

```ts
const result = envSchema.safeParse(process.env);
```

`envSchema` ในไฟล์ประกาศช่องไว้แล้ว (ชื่อโมเดลและ API key ของแต่ละเจ้า) ทุกช่องมีรูปแบบ `z.string().trim().default("")` เมื่อทำถูกจะเห็น

```text
LLM_MODEL (ใช้โมเดลเริ่มต้น)
✅ พบ API key อย่างน้อยหนึ่งตัว
✅ ตัดช่องว่างหัวท้ายของ LLM_MODEL แล้ว
```

บรรทัดแรกขึ้นกับว่าคุณตั้ง `LLM_MODEL` ไว้หรือไม่ ปล่อยว่างจะเป็น "(ใช้โมเดลเริ่มต้น)"

## 3. ส่วนของ schema ทำอะไร

| ส่วนของโค้ด | ค่าที่รับและสิ่งที่เกิดขึ้น |
|---|---|
| `z.string()` | รับข้อความ (`process.env` ให้ทุกค่าเป็นข้อความอยู่แล้ว) |
| `.trim()` | ตัดช่องว่างหัวท้าย เช่น `"  demo-model  "` เป็น `"demo-model"` |
| `.default("")` | ให้ `""` เมื่อไม่มีตัวแปรนั้นใน environment |
| `z.object(...)` | ดึงเฉพาะช่องที่ประกาศ ข้ามตัวแปรอื่นของเครื่อง |
| `envSchema.safeParse(...)` | คืน `{ success: true, data }` เมื่อผ่าน หรือ `{ success: false, error }` เมื่อผิดรูปแบบ (ไม่ throw ให้เรา จึงตรวจ `result.success` เอง) |

ไฟล์โหลด `.env` เข้า `process.env` ให้แล้ว ถ้าตัวแปรเดียวกันถูกตั้งใน environment ของเครื่องอยู่ก่อน ค่าในเครื่องจะชนะค่าในไฟล์ `.env` ส่วน `.env` เก็บไว้ในเครื่องเท่านั้น ถ้าจะแชร์ชื่อตัวแปรให้ใช้ `.env.example`

## 4. เปลี่ยนค่าเดียวแล้วเทียบผล

เก็บ API key ไว้เหมือนเดิม แล้วรันซ้ำโดยเปลี่ยนเฉพาะ `LLM_MODEL`

| `LLM_MODEL` | บรรทัดแรกที่พิมพ์ | เหตุผล |
|---|---|---|
| `"  demo-model  "` | `LLM_MODEL demo-model` | `trim()` ตัดช่องว่างให้ |
| ว่าง | `LLM_MODEL (ใช้โมเดลเริ่มต้น)` | `default("")` ให้ค่าว่าง |
| ไม่มี key ของเจ้าไหนเลย | หยุดด้วย `ยังไม่ได้ตั้ง API key ใน .env` | ไม่มี key ที่มีข้อความ |

ตัวอย่างลองจาก terminal โดยไม่ต้องแก้ `.env`

    LLM_MODEL="  demo-model  " pnpm lesson 1-01

ที่ตรวจในบทนี้คือ "มี key อยู่ในรูปข้อความ" ส่วนการตรวจว่า key เรียก API ได้จริงจะเกิดในบท 1-03

## คุณทำได้แล้ว
- ตรวจ `process.env` ด้วย `safeParse` และอ่านผลจาก `result.success`
- ใช้ `.trim()` และ `.default()` จัดรูปค่าตั้งต้น

## ข้อควรจำ
- อย่าเขียน key ลงในโค้ด ให้อ่านจาก `env`
- `.env` ห้าม commit ใช้ `.env.example` แทนเมื่อต้องแชร์
