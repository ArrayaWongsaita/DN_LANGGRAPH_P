# บทที่ 01: ตรวจค่าใน .env ด้วย zod

> ถ้าคุณผ่าน Level 0 มาแล้ว เรื่องวิธีเรียนจะคุ้นเคยอยู่แล้ว ข้ามไปอ่านหัวข้อ "แนวคิด" ได้เลย

## วิธีเรียนของคอร์สนี้
แต่ละบทมีไฟล์หลักแค่ไฟล์เดียว คุณเปิดไฟล์นั้น เติมช่องที่ขึ้นว่า `// 👉 ข้อ N` (ตอนนี้ช่องพวกนี้เป็น `todo(N)`) แล้วรันด้วย `pnpm lesson NN` เพื่อดูผลจริง

```
01-env-schema/
  README.md         <- ไฟล์นี้ อธิบายแนวคิด
  env.ts            <- ไฟล์ที่คุณเติม และรันดูผลได้เลย
  solution/env.ts   <- เฉลย ดูเมื่อติดจริง ๆ เท่านั้น
```

- ยังเติมไม่ครบ: รันแล้วจะเห็น `ยังไม่ได้ทำข้อ N` บอกว่าช่องไหนค้างอยู่ (เรื่องปกติ ไม่ใช่ว่าคุณทำผิด)
- เติมครบ: รันแล้วเห็นผลและบรรทัด `✅ ผ่าน`

## แนวคิด
เวลาเรียก LLM เราต้องมี **API key** (เหมือนรหัสผ่านของแอปคุณ) และต้อง **ห้ามเขียน key ลงในโค้ด** เพราะถ้าเผลอเอาโค้ดขึ้น GitHub คนอื่นจะเอา key ไปใช้ได้ วิธีมาตรฐานคือเก็บไว้ในไฟล์ `.env` (ที่ git ไม่อัปโหลด) แล้วให้โปรแกรมอ่านจาก environment variable:

```
.env  (ไฟล์ลับในเครื่องคุณ)         โปรแกรม
GROQ_API_KEY=gsk_xxxxx   ──────►   process.env.GROQ_API_KEY
```

### ทำไมต้อง "ตรวจ" ค่าจาก .env
ค่าใน `.env` คนพิมพ์เอง จึงพลาดได้ง่าย (ลืมใส่ key, มีช่องว่างเกิน) ถ้าไม่ตรวจ โปรแกรมจะไปพังกลางทางด้วย error ที่อ่านยาก หลักที่ดีคือ **ตรวจตั้งแต่เริ่มโปรแกรม (fail fast)** แล้วบอกชัดว่า "ตัวแปรไหนผิด เพราะอะไร" เครื่องมือที่วงการ TypeScript ใช้คือ **zod** และเราจะใช้ตลอดคอร์สนี้ (ทั้ง structured output และ State ของ graph)

> **กล่องแนะนำ zod**
> zod ให้เราเขียน "schema" คือคำอธิบายว่าข้อมูลที่ถูกต้องหน้าตาเป็นอย่างไร แล้วใช้ตรวจข้อมูลจริง
> ```ts
> z.string()                       // ข้อความ
> z.string().trim()                // ข้อความ ตัดช่องว่างหัวท้าย
> z.string().default("")           // ถ้าไม่มีค่า ให้ใช้ ""
> z.object({ a: z.string() })      // object ที่มีช่อง a (ช่องอื่นที่ไม่ได้ประกาศจะถูกข้าม)
> ```
> ตรวจด้วย `schema.safeParse(ข้อมูล)` ซึ่ง **ไม่ throw** แต่คืน `{ success: true, data }` หรือ `{ success: false, error }` (ใช้ `schema.parse` ถ้าอยากให้ throw เมื่อผิด)
> รายการปัญหาอยู่ที่ `error.issues` แต่ละอันมี `path` (ช่องไหน) และ `message` (เพราะอะไร)

## ตั้งค่าก่อนเริ่ม (ทำครั้งเดียว)
> ถ้าคุณตั้งค่า `.env` ไปแล้วในบท 0-01 ข้ามขั้นนี้ได้

1. คัดลอกไฟล์ตัวอย่าง: `cp .env.example .env`
2. สมัครบัญชีผู้ให้บริการ LLM เจ้าที่คุณจะใช้ แล้วสร้าง API key ของคุณเอง
3. เปิด `.env` ใส่ key หลังชื่อตัวแปรของเจ้านั้น (ไม่ต้องมีเครื่องหมายคำพูด ไม่ต้องมีช่องว่าง) เช่น `GROQ_API_KEY=...`

## ดูตัวอย่าง
เปิด `env.ts` อ่านจากบนลงล่าง:
1. โหลด `.env` เข้า `process.env` (ให้มาแล้ว)
2. ประกาศ `envSchema`: ช่อง key ให้มาแล้วเป็นตัวอย่าง เหลือช่อง `LLM_MODEL` ให้คุณเขียนเอง (ข้อ 1)
3. ตรวจ `process.env` ด้วย `safeParse` (ข้อ 2)
4. ถ้าผิดก็หยุดพร้อมบอกว่าตัวแปรไหนผิด และต้องมี key อย่างน้อยหนึ่งเจ้า (ให้มาแล้ว)
5. `export const env` ส่งค่าที่ตรวจแล้วให้ไฟล์อื่นใช้ (บท 02 จะ `import { env }` จากไฟล์นี้)

## โจทย์
เติม 2 ช่อง (`todo(1)`, `todo(2)`) ใน `env.ts` แล้วรัน:

    pnpm lesson 1-01

ถ้าเติมถูกจะเห็นค่าที่ตั้งไว้ (key ถูกซ่อนไว้ แสดงแค่ 4 ตัวแรก เพราะการพิมพ์ key เต็มลงจอเสี่ยงหลุดตอนแชร์หน้าจอ) และ `✅ ผ่าน` ลองคอมเมนต์ key ทุกตัวออกจาก `.env` ดูว่าได้ข้อความอะไร (อย่าลืมใส่คืน)

## คุณทำได้แล้ว
- เก็บ API key ไว้ใน `.env` และรู้ว่าทำไมห้ามใส่ในโค้ด
- เขียน schema ด้วย zod และตรวจข้อมูลด้วย `safeParse`
- `export` ค่าที่ตรวจแล้วให้ไฟล์อื่น import ไปใช้

## ข้อควรจำ
- `.env` ห้ามอัปโหลดขึ้น git และห้ามส่งให้ใคร key แต่ละคนใช้ของตัวเอง
- ข้อมูลจากภายนอก (ไฟล์, ผู้ใช้, เครือข่าย) ควรตรวจด้วย schema ก่อนใช้เสมอ
- `safeParse` คืนผลให้เราจัดการเอง ส่วน `parse` throw เมื่อผิด
