# บทที่ 03: เรียก LLM ครั้งแรก

## แนวคิด
ถึงเวลาคุยกับ LLM จริง ๆ แล้ว! ใน LangChain ทุกเจ้า (Groq, Google, DeepSeek, OpenAI ฯลฯ) หน้าตาเหมือนกันหมด เรียกว่า **chat model** และมีท่าหลักท่าเดียวคือ `.invoke(...)`:

```
คำถาม ──► llm.invoke(คำถาม) ──► (รอสักครู่) ──► คำตอบ
```

chat model (`llm`) ที่เราใช้ คุณสร้างและ export ไว้แล้วในบท 02 บทนี้แค่ `import { llm }` มาใช้

> **กล่องเล็ก: async / await**
> การเรียก LLM ต้องรอเครือข่าย จึงเป็นงาน "รอผล" (ได้ Promise กลับมา)
> - ใส่ `await` หน้าคำสั่งเพื่อรอผลให้เสร็จก่อนไปบรรทัดถัดไป
> - ฟังก์ชันที่ใช้ `await` ข้างในต้องประกาศเป็น `async` และผลที่คืนจะเป็น `Promise` (เช่น `Promise<string>`)
> - ลืม `await` = ได้ Promise แทนคำตอบ (บั๊กยอดฮิตของมือใหม่)

## ดูตัวอย่าง
เปิด `firstCall.ts` เป็นสคริปต์ที่อ่านจากบนลงล่าง ไม่มีฟังก์ชันครอบ:
1. `import { llm }` จากบท 02
2. ตั้ง `question`
3. **ส่วนที่คุณเติม**: ส่งคำถามด้วย `llm.invoke(...)` แล้วเอาคำตอบออกมา จุดสำคัญคือ `invoke` ไม่ได้คืน string ตรง ๆ แต่คืน **object ข้อความ** (เรียกว่า message) ที่มีหลายส่วน ข้อความล้วน ๆ อยู่ที่ `.text` (บทหน้าจะเจาะลึกเรื่องนี้)
4. พิมพ์คำถาม คำตอบ และบอกว่าผ่านหรือไม่ (ไม่ต้องแก้)

## โจทย์
เติม 2 ช่อง (`todo(1)`, `todo(2)`) ใน `firstCall.ts` แล้วรัน (ต้องทำบท 01 และ 02 เสร็จก่อน):

    pnpm lesson 1-03

ถ้าเติมถูกจะเห็นคำตอบของ LLM และบรรทัด `✅ ผ่าน` ถ้ายังไม่เติมจะเห็น `ยังไม่ได้ทำข้อ N` บอกว่าข้อไหนค้างอยู่ ติดก็แอบดู `solution/firstCall.ts` ได้

> ถ้าเจอ error ตอนรัน: **401** = key ผิดหรือไม่ได้ตั้ง, **404** = ชื่อโมเดลผิดหรือบัญชีไม่มีสิทธิ์ (ดู `LLM_MODEL`), **429** = เรียกถี่เกินโควตา รอสักครู่แล้วลองใหม่, `fetch failed` = เครือข่ายมีปัญหา

## เทียบกับตอนใช้ fetch (Level 0 บท 0-01 และ 0-02)
ถ้าคุณผ่าน Level 0 มาแล้ว จะเห็นว่าบทนี้เหลือโค้ดไม่กี่บรรทัด:

| งาน | ตอน `fetch` | ตอนนี้ |
|---|---|---|
| URL, header `Authorization`, body JSON | เขียนเองทุกครั้ง | `llm` จัดการให้ จากค่าใน `.env` (ตั้งไว้ในบท 02) |
| อ่านคำตอบ | `data.choices[0].message.content` | `reply.text` |
| error 401/404/429 | แปลงสถานะเอง | LangChain โยน error ที่มีรายละเอียด (ยังตั้ง retry ได้ใน Level 2) |
| เปลี่ยน provider | แก้ URL และรูปแบบ response | เปลี่ยนบล็อกที่เลือกในบท 02 (บทนี้ไม่ต้องแก้) |

## คุณทำได้แล้ว
- เรียก LLM จริงและได้คำตอบกลับมา
- ใช้ `await` รอผลของงานที่ใช้เวลา
- อ่านข้อความคำตอบจาก `.text`

## ข้อควรจำ
- `llm.invoke(...)` ต้อง `await` เสมอ
- คำตอบเป็น object ข้อความ ใช้ `.text` เอาข้อความล้วน
- chat model ทุกเจ้าใน LangChain ใช้ `.invoke` เหมือนกัน เปลี่ยนเจ้าแค่แก้ที่ไฟล์ `llm.ts` ของบท 02
