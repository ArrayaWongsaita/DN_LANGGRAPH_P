# บทที่ 09: State (กระดานกลางของ graph)

## แนวคิด
ตั้งแต่บทนี้เราเริ่มเข้าสู่ **LangGraph** แล้ว LangGraph ให้เราต่อขั้นตอนหลายขั้นเป็น **graph** และสิ่งแรกที่ต้องมีคือ **State**: ข้อมูลที่ไหลผ่านทุกขั้นตอน เปรียบเหมือนกระดานกลางที่ทุกขั้นตอนมาอ่านและเขียน

```
        ┌──────── State ────────┐
        │ name: "มาลี"          │
        │ age:  0   (default)   │
        │ city: ""  (default)   │
        └───────────────────────┘
   input ──► ขั้นตอนที่ 1 ──► ขั้นตอนที่ 2 ──► ผลลัพธ์ (State สุดท้าย)
```

เราประกาศ State ด้วย `StateSchema` โดยบอกชื่อ field และชนิดข้อมูลด้วย **zod** (ไลบรารีที่ใช้อธิบายรูปร่างข้อมูล เราใช้ตรวจ `.env` ในบทที่ 02 และใช้ใน structured output บทที่ 08 แล้ว):

```ts
const State = new StateSchema({
  name: z.string(),                 // ต้องส่งมาเสมอ
  age: z.number().default(0),       // ไม่ส่งมา = 0
});
```
- ถ้าส่งข้อมูลผิดชนิดเข้า graph (เช่น `age: "สามสิบ"`) LangGraph จะ error ทันที ช่วยจับบั๊กตั้งแต่ต้นทาง
- ถ้าไม่ส่ง field ที่มี `.default(...)` ก็จะได้ค่าเริ่มต้น

## ดูตัวอย่าง
เปิด `profile.ts`: ประกาศ `ProfileState` แล้วมี graph ที่มี node เดียว (เรื่อง node/edge จะเรียนในบทถัดไป ตอนนี้ดูแค่ว่า State ทำงานอย่างไร) ท้ายไฟล์ลองส่งข้อมูลแบบต่าง ๆ เข้าไปแล้วพิมพ์ state ที่ได้กลับมา

## โจทย์
เติมช่อง `// 👉 ข้อ N` (ตอนนี้เป็น `todo(N)`) ให้ครบ แล้วรัน:

    pnpm lesson 09

ถ้ายังเติมไม่ครบจะเห็น `ยังไม่ได้ทำข้อ N` บอกว่าช่องไหนค้างอยู่ เติมครบแล้วจะเห็นผลที่พิมพ์ออกมา และบรรทัด `✅` ทุกข้อ ถ้ามี `❌` ให้ดูคำใบ้ในวงเล็บท้ายบรรทัด

ข้อ 1 และ 2 ให้แทน `todo(1)` และ `todo(2)` ด้วยนิยาม field (ไม่ใช้ LLM จึงไม่ต้องมี key)

## คุณทำได้แล้ว
- ประกาศ State ของ graph ด้วย `StateSchema` และ zod
- กำหนดค่าเริ่มต้นด้วย `.default(...)`
- เข้าใจว่า State คือข้อมูลกลางที่ทุกขั้นตอนใช้ร่วมกัน

## ข้อควรจำ
- State ต้องประกาศก่อนสร้าง graph เสมอ
- field ที่ไม่มี `.default` ต้องส่งมาตอนเรียก
- **ชื่อ node ห้ามซ้ำกับชื่อ field ใน State** (จะเจอตั้งแต่บทหน้า)
