# บทที่ 19: โปรเจกต์ปิด Level 1 — ผู้ช่วยในเทอร์มินัล

## แนวคิด
ถึงเวลารวมทุกอย่างที่เรียนมาเป็นแอปเดียว บทนี้ต่างจากบทก่อน ๆ ตรงที่ **มีช่องให้เติมเยอะขึ้น (5 ช่อง)** และคุณต้องเลือกใช้เครื่องมือเองจากสิ่งที่เรียนมา โดยมีแผนผังกำกับไว้ใน `assistant.ts`:

```
START ──► classify ──?──► smallTalk ──► END     ทักทาย: ตอบสำเร็จรูป (ไม่เปลือง LLM)
                     └──► respond   ──► END     คำถามทั่วไป: ให้ LLM ตอบ
```
ผู้ช่วยนี้ **จัดประเภทข้อความก่อน** ด้วย LLM (ใช้ structured output ให้ได้คำตอบที่โปรแกรมเอาไปเลือกทางต่อได้) แล้วค่อยเลือกทางตอบ นี่คือรูปแบบ **routing** ที่ใช้จริงในแอป LLM: ทางง่ายไม่ต้องเสียเงินเรียก LLM ซ้ำ

ของที่ใช้ในบทนี้ และบทที่สอนไว้:
| ขั้นตอน | บทที่ |
|---|---|
| node จัดประเภทด้วย structured output | 08, 12 |
| router เลือกทาง | 14 |
| node ที่เรียก LLM | 12 |
| ต่อ edge ไป END | 11 |

ถ้าติด กลับไปเปิด README ของบทนั้นได้เลย

## ดูตัวอย่าง
`assistant.ts` มีโครง State, schema ของ category และ node `smallTalk` ให้แล้ว ที่เหลือคือ 5 ช่อง ทำตามลำดับข้อ 1 → 5 ได้เลย

## โจทย์
เติมให้ครบ 5 ช่อง แล้วรัน:

    pnpm test:lesson 19

ข้อ 4 และ 5 ถ้าตกหล่น `compile()` จะ error ว่า node ไม่ถูกต่อ ให้อ่านข้อความแล้วตามไปแก้

เขียวแล้วลองคุยกับผู้ช่วยตัวจริง:

    pnpm lesson 19

ลองพิมพ์ "สวัสดี" และคำถามทั่วไป สังเกตวงเล็บหน้าคำตอบที่บอกว่าถูกจัดเป็นประเภทอะไร

## คุณทำได้แล้ว 🎉
- สร้าง graph ที่ใช้ LLM จัดประเภท แล้วเลือกเส้นทางตอบได้เอง
- ใช้ State, node, edge, conditional edge และ structured output ร่วมกันในแอปเดียว
- ทดสอบ graph ที่ใช้ LLM ได้โดยไม่ต้องเรียกเครือข่ายจริง

คุณจบ **Level 1** แล้ว ตอนนี้คุณสร้างแอป LLM ที่มีหลายขั้นตอนและมีการตัดสินใจได้แล้ว

## ข้อควรจำ
- แบ่งงานเป็น node เล็ก ๆ ที่ทำหน้าที่เดียว แล้วต่อด้วย edge
- งานง่ายอย่าเรียก LLM ถ้าไม่จำเป็น (routing ช่วยประหยัดเวลาและเงิน)
- structured output ทำให้ผลจาก LLM "ต่อกับโค้ด" ได้อย่างเชื่อถือได้

## บทถัดไป (Level 2)
ผู้ช่วยตัวนี้ยังจำบทสนทนาไม่ได้ (ทุกข้อความเริ่มใหม่) และยังลงมือทำอะไรไม่ได้ Level 2 จะเพิ่ม **ความจำ** (memory) และ **เครื่องมือ** (tools/agents)
