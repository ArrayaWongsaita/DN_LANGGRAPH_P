# บทที่ 16: reducer (รวมค่าเมื่อมีหลายคนเขียน field เดียวกัน)

## แนวคิด
โดยปกติ field ใน State ทำงานแบบ **"ค่าใหม่ทับค่าเก่า"** ซึ่งพอสำหรับงานเรียงลำดับ แต่มีสองสถานการณ์ที่ไม่พอ:

1. **อยากสะสมค่า** เช่น เก็บประวัติข้อความทุกขั้น ถ้าทับกันตลอดจะเหลือแค่ค่าสุดท้าย
2. **หลาย node ทำงานขนานกัน** แล้วเขียน field เดียวกันพร้อมกัน ถ้าไม่บอกวิธีรวม LangGraph จะ error `LastValue can only receive one value per step` เพราะไม่รู้ว่าจะเอาค่าไหน

ทางออกคือ **reducer**: ฟังก์ชันที่บอกว่า "เมื่อมีค่าใหม่เข้ามา ให้รวมกับค่าปัจจุบันอย่างไร"

```
reducer(ค่าปัจจุบัน, ค่าใหม่) => ค่าที่จะเก็บ

log:   (["a"], "b")   => ["a", "b"]      (ต่อท้าย)
score: (1, 2)         => 3               (บวก)
```
ประกาศด้วย `ReducedValue` (ใส่ชนิดข้อมูลของ field, ชนิดของค่าใหม่ `inputSchema`, และ `reducer`):

```ts
log: new ReducedValue(z.array(z.string()).default(() => []), {
  inputSchema: z.string(),
  reducer: (current, next) => [...current, next],
}),
```
reducer ใช้กับค่าที่ส่งเข้ามาตอน `invoke` ด้วย (เช่น `score: 10` จะถูกรวมกับค่าเริ่มต้น 0)

## ดูตัวอย่าง
`reducers.ts` มี graph สองแบบ: เรียงกัน (`a` แล้ว `b`) และขนานกัน (`x` กับ `y` พร้อมกัน) ทั้งคู่เขียน `log` และ `score` สิ่งที่ขาดคือกติกาการรวมของแต่ละ field

## โจทย์
เติม reducer 2 ตัว แล้วรัน:

    pnpm test:lesson 16

ลอง `pnpm lesson 16` ดูผล แล้วลองลบ reducer ของ field หนึ่งออก (เปลี่ยนเป็น `z.number().default(0)` ธรรมดา) เพื่อดู error ของกรณีขนาน (อย่าลืมคืนค่า)

## คุณทำได้แล้ว
- กำหนด reducer ให้ field ที่ต้องสะสมหรือรวมค่า
- เข้าใจว่าทำไมงานขนานต้องมี reducer

## ข้อควรจำ
- ไม่มี reducer = ทับ; มี reducer = รวมตามกติกา
- reducer ต้องคืนค่าใหม่ ไม่แก้ค่าเดิมตรง ๆ
- reducer สำเร็จรูปสำหรับแชตมีอยู่แล้ว (`MessagesValue`) เราจะใช้ใน Level 2
