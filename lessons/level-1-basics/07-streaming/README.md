# บทที่ 07: streaming (คำตอบที่ทยอยออกมา)

## แนวคิด
`invoke` ต้องรอจน LLM เขียนเสร็จทั้งคำตอบ ถ้าตอบยาวผู้ใช้จะจ้องหน้าจอว่างเป็นสิบวินาที แอปแชตจริงจึงใช้ **streaming**: LLM ส่งชิ้นเล็ก ๆ ทยอยมาเรื่อย ๆ เราแสดงทันทีที่ได้

```
invoke:  [............รอ............] "คำตอบทั้งก้อน"
stream:  "สวั" "สดี" "ครับ" ...  ← ทยอยมาทีละชิ้น
```

`llm.stream(...)` คืน **async iterable** ใช้วนอ่านด้วย `for await ... of`:

```ts
const stream = await llm.stream("...");
for await (const chunk of stream) {
  console.log(chunk.text);   // chunk แต่ละชิ้นมี .text เหมือน message
}
```
ชิ้นเล็กแต่ละชิ้น (chunk) หน้าตาเหมือน message ทำให้ใช้ `.text` ได้เหมือนเดิม

## ดูตัวอย่าง
`collectChunks.ts` เก็บข้อความของทุกชิ้นลง array ตามลำดับ (ของจริงเรามักส่งแต่ละชิ้นไปแสดงบนจอทันที)

## เทียบกับตอนใช้ fetch (บท 0-05)
ถ้าคุณทำบท 0-05 มา จะจำได้ว่าต้องอ่านทีละก้อน แยกบรรทัด เก็บเศษของบรรทัดที่ถูกตัดไว้ใน buffer ข้าม `[DONE]` และ `JSON.parse` เอง ตอนนี้ทั้งหมดนั้นเหลือ:

```ts
for await (const chunk of await llm.stream(question)) { ... chunk.text ... }
```
LangChain จัดการ SSE, buffer และการข้ามชิ้นที่ไม่มีข้อความให้หมด

## คุณทำได้แล้ว
- ขอคำตอบแบบ stream และวนอ่านด้วย `for await`
- เข้าใจว่าทำไมแอปแชตถึงรู้สึกเร็วกว่า

## ข้อควรจำ
- `await llm.stream(...)` ได้ stream แล้ว `for await` วนอ่านอีกที
- แต่ละ chunk ใช้ `.text` ได้
- ต่อทุก chunk กลับ = คำตอบเต็ม
