# บทที่ 02: ตั้งค่า .env และตรวจค่าด้วย zod

## แนวคิด
เวลาเรียก LLM เราต้องบอกผู้ให้บริการว่า "ใครเป็นคนเรียก" ด้วย **API key** (เหมือนรหัสผ่านของแอปคุณ) ข้อควรระวัง: **ห้ามเขียน key ลงในโค้ด** เพราะถ้าเผลอเอาโค้ดขึ้น GitHub คนอื่นจะเอา key ไปใช้ได้ (และคุณต้องจ่ายเงินแทน)

วิธีมาตรฐานคือเก็บ key ไว้ในไฟล์ `.env` ที่ไม่ถูกอัปโหลด (เราตั้ง `.gitignore` ไว้แล้ว) แล้วให้โปรแกรมอ่านจาก **environment variable**:

```
.env  (ไฟล์ลับในเครื่องคุณ)         โปรแกรม
GROQ_API_KEY=gsk_xxxxx   ──────►   process.env.GROQ_API_KEY
```

### ทำไมต้อง "ตรวจ" ค่าจาก .env
ค่าใน `.env` คนพิมพ์เอง จึงพลาดได้ง่าย: ลืมใส่ key, พิมพ์ชื่อ provider ผิด, มีช่องว่างเกิน ถ้าไม่ตรวจ โปรแกรมจะไปพังกลางทางด้วย error ที่อ่านยาก (เช่น 401) หลักที่ดีคือ **ตรวจตั้งแต่เริ่มโปรแกรม (fail fast)** แล้วบอกชัดว่า "ตัวแปรไหนผิด เพราะอะไร"

เครื่องมือที่วงการ TypeScript ใช้ตรวจข้อมูลจากภายนอกคือ **zod** และเราจะใช้ตลอดคอร์สนี้ (ทั้ง structured output และ State ของ graph)

> **กล่องแนะนำ zod**
> zod ให้เราเขียน "schema" คือคำอธิบายว่าข้อมูลที่ถูกต้องหน้าตาเป็นอย่างไร แล้วใช้ตรวจข้อมูลจริง
> ```ts
> z.string()                       // ข้อความ
> z.string().trim().min(1)         // ข้อความ ตัดช่องว่างหัวท้าย และห้ามว่าง
> z.enum(["groq", "ollama"])       // ต้องเป็นหนึ่งในนี้เท่านั้น
> z.string().default("")           // ถ้าไม่มีค่า ให้ใช้ ""
> z.object({ a: z.string() })      // object ที่มีช่อง a (ช่องอื่นที่ไม่ได้ประกาศจะถูกข้าม)
> ```
> ตรวจด้วย `schema.safeParse(ข้อมูล)` ซึ่ง **ไม่ throw** แต่คืน `{ success: true, data }` หรือ `{ success: false, error }` (ใช้ `schema.parse` ถ้าอยากให้ throw เมื่อผิด)
> รายการปัญหาอยู่ที่ `error.issues` แต่ละอันมี `path` (ช่องไหน) และ `message` (เพราะอะไร)

ในคอร์สนี้ไฟล์ **`src/env.ts`** ทำสิ่งเดียวกับที่คุณกำลังเขียนในบทนี้ คือประกาศ schema ของ `.env` ด้วย zod แล้วตรวจ `process.env` ครั้งเดียว (`parseEnv`) ทุกไฟล์ที่ต้องการค่าตั้งต้นเพียง `import { env } from "@src/env"` ถ้าค่าผิดจะได้ข้อความไทยที่บอกทุกข้อที่ผิดพร้อมกัน ลองเปิดอ่านหลังทำบทนี้เสร็จ (โครงเหมือนกับของคุณ เพิ่มแค่กฎ "ต้องมี key ของ provider ที่เลือก") ส่วน `src/llm.ts` เอาค่านั้นไปสร้างตัวเรียก LLM คุณเปลี่ยนเจ้า LLM หรือโมเดลได้ที่ `.env` ที่เดียว (ตัวแปร `LLM_PROVIDER`, `LLM_MODEL`)

## ตั้งค่าก่อนเริ่ม (ทำครั้งเดียว)
> ถ้าคุณตั้งค่า `.env` ไปแล้วในบท 0-01 ข้ามขั้นนี้ได้ บทนี้เน้นการ **ตรวจ** ค่าด้วย zod

1. คัดลอกไฟล์ตัวอย่าง: `cp .env.example .env`
2. สมัครบัญชี provider ที่ใช้ (ค่าเริ่มต้นของคอร์สคือ Groq) แล้วสร้าง API key ของคุณเอง
3. เปิด `.env` ใส่ key หลัง `GROQ_API_KEY=` (ไม่ต้องมีเครื่องหมายคำพูด ไม่ต้องมีช่องว่าง)

## ดูตัวอย่าง
เปิด `envCheck.ts` มี 3 ฟังก์ชันที่ต้องเขียน และ `maskKey` ที่ให้มาแล้ว (ซ่อน key ก่อนพิมพ์ เพราะการพิมพ์ key เต็มลงจอเสี่ยงหลุดตอนแชร์หน้าจอ):
- `buildSettingsSchema()` คำอธิบายว่า `LLM_PROVIDER` / `LLM_MODEL` ที่ถูกต้องเป็นอย่างไร
- `checkSettings(env)` ตรวจ env ด้วย schema นั้น แล้วคืนผลแบบ "ผ่าน/ไม่ผ่านพร้อมรายการปัญหา"
- `checkKey(env, keyVar)` ตรวจว่า key ถูกตั้งไว้

## คุณทำได้แล้ว
- เก็บ API key ไว้ใน `.env` และรู้ว่าทำไมห้ามใส่ในโค้ด
- เขียน schema ด้วย zod และตรวจข้อมูลด้วย `safeParse`
- แปลงผลตรวจเป็นข้อความที่คนอ่านแล้วรู้ว่าต้องแก้อะไร

## ข้อควรจำ
- `.env` ห้ามอัปโหลดขึ้น git และห้ามส่งให้ใคร key แต่ละคนใช้ของตัวเอง
- ข้อมูลจากภายนอก (ไฟล์, ผู้ใช้, เครือข่าย) ควรตรวจด้วย schema ก่อนใช้เสมอ
- `safeParse` คืนผลให้เราจัดการเอง ส่วน `parse` throw เมื่อผิด
